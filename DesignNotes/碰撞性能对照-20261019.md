## §0 结论

1. **当前 256 件、稀疏空间的主场景，绝对碰撞开销不落后**：碰撞后 300 步平均 20.9–23.6 µs/步，热态单次碰撞链 0.42–0.52 ms；这比跑一套连续刚体引擎便宜得多。
2. **落后的是“每单位工作”的常数因子**：我们一次 256 件接触大约做 **6 次全量 part 收集**（`EnsurePartBoxes` 2 次 + 位置投影 2 轮 × 2 组）。Release 台架实测：完整收集 **76–87 µs/次**（256 件全 identity，约 341 ns/件），6 次约 **0.46–0.52 ms**；**相对几何缓存实测只省 37–54%**（不是 73%）——因为缓存构建本身≈一次完整收集，缓存平移仍要构造 `PartAabb`。
3. **落后的是最坏情况**：同格 **256 艘配对枚举实测 9–16 ms**（64 艘已 0.93–0.97 ms）；CCD 每采样 O(nA×nB)，64×64 的 64 次采样仅重叠扫描就 **0.76 ms**（256×256 达 5.6 ms）；1000+ 件会进入 ms 级。
4. **落后的是冷启动**：首次 10 km/s 碰撞 7.7 ms、首次多点 24.5 ms、首次同步 1.35 ms、首次物理步 4.3 ms。热态同路径只有 0.4–0.5 ms / 20 µs。**JIT 是当前最大的用户可感成本，且是可消除的。**
5. **落后的是测量**：`[步耗时] 碰撞=` 是行星表面碰撞，不是船-船；第一轮 7.3 ms 曾被误读成算法成本。没有碰撞子段时钟，就无法证明“完美”。
6. **不建议整体换 Bepu/Rapier**。我们的事件驱动、解析轨道 + 碰撞窗口架构是对的；要抄的是它们的**局部持久结构、SoA/SIMD、warm start、接触受限步长**，不是引擎本身。

一句话：**不是“算法慢”，是“重复做同一件事 + 用错数据布局 + 冷启动没预热 + 最坏情况没封顶”。**

## §2 逐层对照

| 层 | KSA/Bepu | Sable/Rapier | 我们 | 判断 |
|---|---|---|---|---|
| 时间步 | 接触 60 Hz，自适应，1 子步 | 40 Hz，2 子步 | 2 s / 1/30 s，无接触降速 | **差一档**：我们用 CCD 补，代价是精度/成本 |
| 船级宽相 | 动态 BVH + bubble/on-rails | Rapier BVH | 20 km 固定格 + 扫掠 + 哈希去重 | 稀疏场景我们更便宜；**同格密集 O(k²)** |
| 零件结构 | 一船一刚体 + BigCompound 局部树 | 刚体 + voxel 图元 | 每 part 世界 AABB 现算 | **架构级差距**：局部持久树 vs 每次世界重建 |
| 窄相 | Bepu convex/compound，speculative，persistent manifold | Rapier manifold | AABB/SAP + OBB SAT；8 接触上限 | 256 件够用；**大规模/复杂接触差** |
| 求解 | 8 迭代 + warm start + SIMD + 世界逆惯量 | 迭代 + warm start + SIMD | 6 迭代，标量 double，每次冲量四元数逆 | **2–5× 常数 + 静置稳定性差** |
| CCD | 自适应步长 + Bepu continuous | Rapier CCD | 采样 + 二分 + O(n²) overlap | **精度和成本都落后**；当前只保证“撞上” |
| 并行 | Bepu worker + vehicle jobs | Rapier 可并行 | 单线程 | 256 件不需要；**1000+ 的上限** |
| 休眠 | Bepu sleeper | Rapier island sleep | 无 | 空闲场景每步仍付固定成本 |
| 冷启动 | 启动期预热/长生命周期 | 原生 Rapier，JNI 预热 | 首次路径 JIT 7–25 ms | **用户可感最大差距** |
| 测量 | PhysicsStepDiagnostics + profiler | Rapier counters | PerfProbe；子段缺失；曾误标 | **无法证明完美** |

## §3 我们的实测账（Release / 游戏内）

### 3.1 热态

- 256 件对撞后 300 步：**平均 20.9–23.6 µs/步，最慢 37–51 µs，>2 ms 尖峰 0**。
- 空场 300 步：`[碰撞链成本] 总 平均=2.6–3.0 µs｜船对=0.8–1.1 µs`。
- 热态 10 km/s 碰撞：**船对 0.42–0.52 ms**（第 2/3 次点击；第 1 次 7.7 ms 是 JIT）。
- 热态多点：侧靠尾巴每步 ≤~300 µs，300 步平均 3–19 µs。
- 窄相台架：`GetPartAabbSystem` **209.9 ns/件**（完整收集见 §3.2）；`CollectPartContacts` 256×256 **37.0 µs**；最深对 **20.9 µs**；solver 8 接触 × 6 迭代 **1.7–8.9 µs**（单位惯量到随机惯量/姿态的口径）。

### 3.2 256 件碰撞的成本分解（完整收集台架 + 代码路径推算）

旧的 `209.9 ns/件` 只量了 `GetPartAabbSystem`；**完整 `CollectPartAabbs`（含 `PartAabb` 构造 + List.Add）Release 实测 76–87 µs/次（256 件全 identity，约 341 ns/件）**。

```
6 次完整收集（Ensure 2 + 投影 2 轮 × 2）   约 0.46–0.52 ms
3 次 CollectPartContacts（37 µs/次）        约 0.11 ms
solver（1.7–8.9 µs，取决于惯量/姿态）       约 0.002–0.009 ms
------------------------------------------------
合计                                       约 0.57–0.64 ms（推算）
```

- 256 件接触**尚无同口径的实机子段读数**；日志里 0.42–0.52 ms 是 10 km/s 爆炸路径，不是同一件事。必须先加子段钟。
- 6 次收集占总成本约 **80%**，所以“重复几何”这个方向是对的；但**相对几何缓存只省 37–54%**：缓存构建≈一次完整收集，缓存平移仍要构造 `PartAabb`。缓存后总成本约 **0.35–0.45 ms**，不是 50–100 µs。
- 剩下的最大单项变成 3 次 `CollectPartContacts`（111 µs）；要再往下走必须动接触收集本身（SoA/SIMD/减少投影轮次），不是继续做几何缓存。
- `ObbObbSat` 完整 **340.8 ns/对**；其中 `Axes` 两根只占 **3.7%**——**预存轴几乎不解决问题**；要治 OBB 必须是矩阵式 SAT 或减少 OBB 候选对。密集团实测 OBB 窄相是 AABB 的 **2.4–13×**（多次运行，方差大）。

### 3.3 冷启动

| 路径 | 首次 | 热态 |
|---|---|---|
| 10 km/s 碰撞 | 7.7 ms | 0.42–0.52 ms |
| 多点/侧靠 | 14.4–24.5 ms | ≤0.3 ms/步 |
| 同步 | 1.35 ms | 21–26 µs |
| 第一个物理步 | 4.3 ms | 亚 µs |
| 交会引导重规划 | 2.1 ms | —（30 s 到点才重算） |

合成组预热已证明手法有效：首次组物理 **4.3 ms → 193 µs**。

**纯函数隔离冷启动台架（Release，单独进程只跑这一条）**：

| 函数 | 首次（多次运行范围） | 第二次 |
|---|---|---|
| `CollectPartContacts` 256×256 | **1,760–2,318 µs** | 20–25 µs |
| `TryFindDeepestPartPair` 256×256 | **525–660 µs** | 17–23 µs |
| `CollisionSolver.Resolve` 1 接触 | **4,386–5,573 µs** | 1.4–1.7 µs |

三项合计 ≈ **6.7–8.5 ms**，覆盖多点/多接触首次执行的大部分。**10 km/s 的 7.7 ms 是 `ResolveTunneled` → `TriggerExplosion`/AoE/伤害路径，不经过 solver**；要消它必须单独预热爆炸/伤害分支（有副作用，需隔离），纯函数预热覆盖不到。
solver 预热 200 次内**没有观察到 tier-1 尖峰**（最大 1.3 µs@第 11 次）⇒ 加载期调用几十次足够，不必只调一次。

## §4 差距排序（按“完美口径”的用户可感 × 可避免程度，2026-10-19 台架修正）

1. **冷启动 JIT（8.5 ms 纯函数 + 爆炸/伤害另计）**：最大、最可避免。纯函数预热后多点/多接触首步应 <1 ms；10 km/s 爆炸路径仍需单独预热。
2. **同格密集船对（256 艘 9–16 ms；64 艘 0.93–0.97 ms）**：比原估高一个数量级，是规模上限的头号悬崖；且 9 ms 里大部分是哈希/迭代器开销，不是真实撞击对数。
3. **part 世界几何重复收集（0.46–0.52 ms 中约 80%）**：相对缓存逐位等价，但只省 37–54%（缓存构建≈一次完整收集）；缓存后还剩 0.35–0.45 ms。
4. **CCD 采样 + O(n²)**：64×64 每次重叠扫描 11.9 µs，64 次采样仅扫描就 0.76 ms；128×128 1.6 ms；256×256 5.6 ms。再加上每采样重收集 B，实际更高。KSA 用接触受限 60 Hz，我们还在 2 s 步上补采样。
5. **接触收集（3 × 37 µs = 111 µs）**：几何缓存之后的最大单项；要进 0.1 ms 必须动它。
6. **solver 常数因子**：预计算世界逆惯量实测 **1.4–7.5×（多次运行；中位约 4×）**（8 接触 × 6 迭代 8.9 → 1.9 µs），但只占总碰撞成本的 ~1%，优先级低。
7. **SAT 轴预计算**：`Axes` 两根只占完整 SAT 的 **3.7%**，**这条路基本不解决问题**；OBB 密集团是 AABB 的 2.4–13×（多次运行，方差大），要治得换矩阵式 SAT 或减少候选对。
8. **无休眠/单线程**：256 件不需要；1000+ 是上限。
9. **测量缺失**：没有子段时钟，前 8 项无法逐项验收。

## §6 实现路径（2026-10-19 台架修订后的顺序）

> 修订顺序：**P0 纯函数预热 + 子段钟 → P5 同格密集 → P1 相对几何缓存 → P4 CCD → P3 solver → P2 SAT（判过不接）**。
> 理由：冷启动 8.5 ms 与同格 9–16 ms 是实测最大两项；几何缓存只省 37–54%；SAT 轴只占 3.7%。

### P0：先让“完美”可测 + 消掉最大冷启动

1. `CheckShipCollisions` 子段时钟：配对枚举 / 组缓存 / 球 / 扫掠 / part 收集 / 窄相 / 求解 / 投影 / CCD / 爆炸 / 伤害。**单独开关**，不要叠在常驻步钟上（10 段 × 2 次 ~20 ns ≈0.4 µs，会把 0.8 µs 的 `船对` 读数抬高 ~50%）。
2. `PerfProbe` 增加 **first-hit 标记**：首次执行单独记一行，稳态统计剔除；避免再把 JIT 当算法。
3. 把 `[步耗时] 碰撞=` 改名为 `行星碰撞=`，与船-船链彻底分开。
4. **加载期纯函数预热**（`FinalizeInit`，纯静态、无副作用）：`CollectPartContacts`、`TryFindDeepestPartPair`、`CollisionSolver.Resolve` 各调用若干次（建议 ≥32 次以触发 tier-1）。实测隔离冷启动分别 2.3 ms / 0.66 ms / 5.57 ms。
5. **爆炸/伤害路径另案**：10 km/s 的 7.7 ms 不经过 solver，纯函数预热覆盖不到；`TriggerExplosion`/AoE/伤害有副作用（日志、伤害、销毁），需要隔离的合成场景，不能直接塞进 FinalizeInit。
6. 补 64/128/256 艘同格、500/1000 m/s CCD 两组基线。

### P1：part 相对几何缓存（逐位等价，但只省 37–54%）

- **缓存范围 = 一个 `collisionCacheEpoch`（一个物理步）**。键必须含 **实体 `Rotation` + `partSetVersion` + part 自身 `rotationShip`/尺寸**；只按 `partSetVersion` 会在船转向后陈旧（`Rotation` 变化不增 `partSetVersion`）。
- 与 `EnsurePartBoxes` **合并**：构建缓存的那一次同时产出当步的 `ca.parts`，不要“先 build 再 collect”付两次。
- 每实体算一次 `abs(R)`；identity part 缓存实体系 `relMin/relMax`；带姿态 part 缓存 `centerOffset`、投影半尺寸、`worldRot`。
- 平移时保持原运算顺序：`entityPos = groupPos + entity.Position`，再 `entityPos + relMin`；**不要**缓存世界 AABB 后 `Min+δ`（那会差 1 ulp）。
- 位置投影轮次只做平移；CCD 采样复用 B 侧相对几何。
- 对拍：单实体 20 个随机组位置 × 256 件（含 16 件带自身姿态、noCollide 过滤）已证 Min/Max/Center/Half 逐位一致；多实体组、损毁件、Rotation 变更后的重建仍需覆盖。

### P2：SAT 轴预计算 —— **判过不接**

- 实测 `Axes` 两根只占完整 SAT 的 **3.7%**（Axes 6.4 ns vs SAT 340.8 ns/对）。预存轴收益 <5%，还会把 `PartAabb` 撑大、压坏缓存。
- OBB 密集团确实慢（AABB 的 2.4–13×（多次运行，方差大）），但主因是 15 轴循环，不是轴矩阵。**只有 OBB 密集团被实测为真实主场景时**，才另开“矩阵式 SAT”擂台；必须保留轴顺序/并列深度规则并做影子 A/B。
- 当前 `PartAabb` 的 `Rotation` 字段保留，不加轴。

### P3：solver 预计算（成立，但优先级低）

- `CollisionBodyState` 增加世界逆惯量（对称 3×3，double），`Resolve` 开头算一次。
- `EffectiveMass`/`ApplyImpulse` 改矩阵-向量，去掉每次冲量的 `Inverse(rotation)`。
- 实测：随机惯量/姿态 **8.87 → 1.93 µs（4.6×）**；单位惯量 **1.71 → 1.21 µs（1.4×）**；2000 随机例最大绝对差 **1.276e-15**（不是逐位，需跑全闸门/32 条验收）。
- 只占总碰撞约 1%；先不做也不影响大局。warm start 是语义变更，另裁。

### P4：CCD / 时间步（问题真实，方案未证）

- 实测 `PartsOverlap` 最坏：64×64 **11.9 µs/次**、128×128 25.0 µs、256×256 87.2 µs；64 次采样分别 **0.76 / 1.60 / 5.58 ms**（还只是重叠扫描，未含每采样重收集 B）。
- 第一步应做**相对几何缓存 + 每采样复用**，把重收集消掉；第二步把 `PartsOverlap` 换成 SAP/局部 BVH，避免 O(nA×nB)。
- “接触受限局部子步”会改时间语义，是用户裁定项；不要先写。
- 先量 500/1000 m/s 的真实触发率；若 CCD 很少触发，ms 级可接受，不必为它重构。

### P5：同格密集（比预估严重，优先做）

- 实测 `EnumerateShipPairs`：**64 艘 0.93–0.97 ms / 128 艘 1.20 ms / 256 艘 9–16 ms**（2016 / 8128 / 32640 对）。
- 分解：纯数组双重循环 256 艘 **7.7 µs**；加 `HashSet<long>` 去重变成 **4.17 ms**；网格版再翻到 **9.1 ms**（`Dictionary`/迭代器/GetFrameId 的剩余开销）。⇒ 9 ms 不是真实撞击对数，是数据结构开销；数组注册表 + 每格 SAP 有明确的下探空间。
- **已落地（三刀）**：
  - 第一刀：全单格快速路径（`AllShipsSingleCell`）⇒ 256 艘 **695–733 µs**（21–22 ns/对）。
  - 第二刀：按格快速路径（无关多格船不再一票否决）+ 混合格回退 ⇒ 新开一局含无关多格船时 **857.6 µs**（旧 9 ms）；距离无关（50 km vs 1e9 m 差 17 µs）。
  - **第三刀（游戏内读数后的修正）**：01:34 日志显示全链仍 **4–8 ms/步**，枚举快速路径没有改变游戏内成本——瓶颈是 32,640 对的逐对几何过滤（组缓存/球/扫掠盒），不是枚举。改为每船存**精确扫掠 AABB**（上一步∪本步；传送不扫掠），格内按 AABB 精确过滤：
    - 船少（≤8）二重循环；
    - 船多走**格内 SAP**（按 minX 排序后扫描，只输出精确相交对）；
    - 混合格回退也加同一 AABB 过滤。
  - 台架：256 艘同格 500 m 间距（互不重叠）**0 候选 / 109.9 µs**（原始格内对 32,640）；全部同点（最坏）仍 32,640 对 / 1.24 ms；64/128/256 全重叠 96/336/1,237 µs。
- 剩余：混合格（多格船与 256 艘同格）仍走回退路径，但其逐对几何也被 AABB 预过滤；极端“全部真重叠”的 C(n,2) 是真相交，不可再省。
- 必须用扫掠 AABB（上一步∪本步），不能用当前 AABB（会重新引入 10 km/s 漏配对）。

### P6：并行（后置）

- 256 件不并行；同格 9–16 ms 先做 P5；只有 P4/P5 证明单线程仍 >1 ms 且可分解时才考虑。Bepu 的 worker 模型可参考，但不要为此重构 ECS。

## §7 不建议做的事

| 项 | 原因 |
|---|---|
| 整体换 Bepu/Rapier | 我们是事件驱动轨道模拟，不是连续刚体；引入引擎会改架构/确定性/交付面 |
| per-call BVH 重建 | 已实测 512²/1024² 慢于 SAP；要做就做**持久局部树**，不是每次 `ArrayPool.Rent` 重建 |
| SAT 轴预计算 | `Axes` 只占完整 SAT 的 3.7%；收益 <5%，还会撑大 `PartAabb` |
| 256 件上多线程 | 20 µs 量级，线程调度/同步会吃掉收益 |
| 用平均 µs 当验收 | 完美口径看 first-hit、p99/max、规模斜率、每单位工作常数 |
| 为追 0.1 µs 改物理语义 | 位置投影 epsilon/warm start/CCD 口径都是语义变更，必须单独裁定 |

## §8 方案判定（一行一项）

| 方案 | 判定 | 证据 |
|---|---|---|
| P0 纯函数加载期预热 | **成立，优先做** | 隔离冷启动 2.3 + 0.66 + 5.57 = 8.5 ms；第二次调用 25/23/1.7 µs |
| P0 爆炸/伤害路径预热 | **未证** | 10 km/s 7.7 ms 不走 solver；有副作用，需隔离合成场景 |
| P0 子段钟 + first-hit | **成立，需门控** | 10 段计时会把 0.8 µs 的 `船对` 抬高 ~50%；单独开关 |
| P1 相对几何缓存 | **成立；逐位等价** | 20 位置 × 256 件 Min/Max/Center/Half 全逐位同；6 次收集省 37–54% |
| P2 SAT 轴预计算 | **判过不接** | Axes 6.4 ns vs 完整 SAT 340.8 ns/对，只占 3.7% |
| P3 solver 世界逆惯量 | **成立；非逐位** | 1.4–7.5×（多次运行；中位约 4×）；最大绝对差 1.3e-15；需全闸门 |
| P4 CCD 局部 BVH/SAP | **问题真实，方案未证** | 64 次采样 0.76/1.6/5.6 ms（64/128/256 件） |
| P5 同格精确 AABB/SAP | **已落地** | 枚举 9–16 ms → 0.8–1.2 ms；游戏内真正病灶是逐对几何 4–8 ms ⇒ 500m 间距 32,640 原始对 → 0 候选 / 110 µs；全重叠最坏仍 32,640 对 / 1.24 ms |
| P6 并行 | **后置** | 先做 P5；256 件单线程不值得并行 |

## §9 一句话给下一位

**碰撞平均已经够快，但“完美口径”下的实测排序是：冷启动 8.5 ms 纯函数（+爆炸路径另计）> 同格 256 艘的逐对几何过滤 4–8 ms（枚举只占 ~0.8 ms；已用精确扫掠 AABB/SAP 把不重叠的 32,640 对降到 0）> 6 次几何收集 0.46–0.52 ms（缓存只省 37–54%）> CCD 0.76–5.6 ms > 接触收集 111 µs > solver 1.4–7.5×（多次运行；中位约 4×）（总量占比 ~1%）。SAT 轴预计算实测只占 3.7%，不要再做。** 先预热纯函数、再加子段钟；同格先做精确 AABB/SAP，再做相对几何缓存；CCD 和爆炸预热要单独立项。
