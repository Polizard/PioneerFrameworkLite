## 0. 总纲：两条通道 · 三层目标

**两条绘制通道（现状即如此，不是选择）**：

| 通道 | 实现 | 角色 | 打开频率 |
|---|---|---|---|
| ① 世界地图层 | `Base/Debug/SpaceGroupVisualManager.cs`（1530 行，Harmony 补丁类，**世界层唯一注入点**） | 日常**态势**：谁在场、我知道什么 | 常开（每帧） |
| ② PFView | `PFView/MainTabWindow_PFView.cs`（1692 行，全屏 RT+相机） | **详查**：这一组在干什么（姿态/轨道/部件/读数）+ 操作 | 按需打开 |

**三层目标**：

- **L1 判据层**（已有）：一键全测 42 条 / 闸门 11 步——回答"算得对不对"。
- **L2 态势层**（本方案）：世界层画出认知层——回答"**我现在知道什么**"（Live/Shadow/假接触/波束/干扰）。
- **L3 详查层**（本方案）：PFView 修缮 + 认知图层进 3D——回答"**这一组具体怎么样**"。

> ⚠ 纪律：视觉层**只读认知层**（`PlayerCanSee` 统一准入），不得成为"看真值"的旁路；真值只经 dev 开关 `DebugShowGroundTruth`（对照用，消费点已就位 `SpaceGroupVisualManager.cs:291/:946`）。

## 2. PFView 目标状态（信息架构提案）

**现状** = 全屏 3D + 右上 3 按钮 + 右下 280px 面板 + 左上提示；无列表、无平移。

**已定案（裁定①，2026-10-02）**：文字读数 UI 堆左侧；**下边缘中央 = KSP 式姿态球**；**右侧 = 以当前选中编队为中心的雷达界面（只显示，用认知层数据；暂不做功能）**；3D 视图居中，`uiBlockRects` 随分区自动登记，拾取/命中沿用"先画 UI 再收输入"的既有纪律。

```
┌────────────────────────────────────────────────────────────────────────┐
│ 工具条   [星系 ▾] [编队 ▾]  │  [雷达开机] [干扰] [波束 ▾]  [复位 R]    │
├────────────────┬─────────────────────────────────┬─────────────────────┤
│ 文字堆（左）    │                                 │ 雷达（右 · 只显示）  │
│  · 编队列表     │                                 │ 以选中编队为圆心：   │
│  · 接触列表     │          3D 视图 (RT)            │  ├ 距离环           │
│    （Live/      │   轨道线 + 波束锥 + 影子/假接触   │  ├ 接触 blip        │
│      Shadow）   │                                 │  │ （Live/Shadow/假）│
│  · 选中组读数   │                                 │  └ 不响应输入、      │
│    姿态/轨道/   │                                 │     不发命令        │
│    武器/EW      │                                 │                     │
├────────────────┴────────────────┬────────────────┴─────────────────────┤
│ 状态条：相机/时刻/帧             │      ◯ 姿态球（下边居中，KSP 式）     │
└─────────────────────────────────┴──────────────────────────────────────┘
```

**交互（V-1 落地）**：滚轮缩放（有）· 右键旋转（有）· 左键点选（有）· **中键（或 Shift+右键）平移（新）** · 双击列表项聚焦该组（新）· 列表↔视图选中联动（新）· R 复位（有）。

> 雷达"只显示"= 不响应输入、不发命令；数据走认知层（`AppendVisible`）；方位基准提案 = 该编队**顺行方向**为 12 点钟（实现期确认）。

## 4. 验收方法（视觉专项）

1. **视觉批的判据 = 游戏内肉眼清单**（每批一张核对表，照 §3 各批"判据"栏）；能离线的（布局数学、配色常量、静态场景布置）先离线做掉。
2. **必须最小场景**：每条"看得见 X"的判据要自铺最小场景——空场景"什么都没画"是**平凡成立**（§2.6 仪器教训第 6 条）。
3. **与 dev 真值开关成对**：认知层图层的意义 = "玩家看到的 vs 真值"的差；每次核对同时开 `DebugShowGroundTruth` 看一遍全量，确认"挡住的是该挡的"。
4. **视觉不得替代物理判据**：它是**补充通道**（回答"肉眼是否与读数一致"），一键全测仍是唯一判决。
5. **攒轮**：V-1/V-2/V-3/V-4 的开发可并行，游戏内核对**合并进尽量少的轮次**（每轮至多一次运行请求）。
