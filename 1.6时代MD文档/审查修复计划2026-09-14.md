## 1. 三条贯穿原则

本轮所有争执最终收敛到三条，后续 PR 应据此裁决：

**原则一：每个事实只允许有一个来源，需要展示的地方去引用它，绝不复制它。**
`deadband` 的 0.5/1.0 漂移就是这条的反面教材——`MissileGuidanceParams.CreateDefault()` 本质是 Def 默认值的平行副本，副本必然漂。该原则一次覆盖 A1/A3/A4/A5/E1 五项。

**原则二：引力只能有 `NBodyIntegrator` 一个实现。**
现在预览（`ManeuverPlanner`）与物理步（`ComputeGroupPhysics`）对同一件事给出两个不同答案，正是"同一事实多份副本"的又一次发作。A0 之后二者同源。

**原则三：物理先于回归。**
会改变弹道的改动必须先落地，再跑一次完整的游戏内回归。已确认：A0（月球群组弹道）与 A2（弹头弹道）改物理；A1 按"测试跟随 Def"方向修则**不动物理**；A5（扣料分摊）**组级弹道不变**（`GetPropellantMass` 全实体求和、`BuildNetworks` 只看 `massFlow` 不看存量），差异仅在解离后各枚余料分布。

## 2. 批次 A：引力与口径根治

### A0 — 引力积分去掉"环绕天体"参量（2026-09-14 已完成；其余 A 项的前置）

**目标形态**：统一在**系统系**（根行星/恒星为中心、钉住）传播，对系统内**所有天体**做全量求和；积分函数签名不含 primaryBody。

**为什么可行且更优**（已推导）：系统系里全量求和与"以子天体为中心 + 显式加潮汐项"**数学等价**。因为月球的开普勒运动是给定的（`r_m″ = −μ_e·r_m/r_m³`），代入 `ρ = r − r_m` 即自动产生那个间接项：

```
ρ″ = −μ_m·ρ/ρ³ + μ_e·[ r_m/r_m³ − (r_m+ρ)/|r_m+ρ|³ ]
```

所以月球系那 0.56% 的地球潮汐缺失**自动补上，不需要任何特殊代码**。

| 项 | 内容 |

**轨道保持的语义落地（A0-7，语义不变但实现要当心）**

白名单语义保持"**不**抵消的天体"不变（`SpaceEntityGroup.cs:114`；`MultiBodyAccelJerk` 按"包含"读、`ComputeOrbitKeepingDvRate` 按"要抵消的量"读，两者**本来就不矛盾**，保持原样即可）。但场变大之后有一处会变，且实现上有个坑：

- **会变的一处**：月心系群组的场现在含地球，而白名单通常只写 `{自己的中心天体}`（`OrbitTransferPlanner.cs:340`、`RendezvousPlanner.cs:625,670`）→ 地球会落入"非白名单"，于是**轨道保持的 dV 消耗在月心系从 0 变成非 0**。这是新模型下的正确行为（保住月球二体轨道本来就该抵消地球摄动），但会影响月球任务的燃料预算。
- **坑**：要抵消的不是"那一项本身"，而是 **(场的总和 − 计划轨道的二体加速度)**。旧模型里二者恰好等价（场 = 参考天体 + 子天体，且参考天体在根域不加速）；新模型里月心系不等价——天真地抵消地球的**全量**贡献，会在系统系里留下一个 0.031 m/s² 的均匀项，正是 §5 N5 那个 224 km 陷阱的镜像。等价说法：该抵消的是地球贡献的**潮汐部分**。
- **验收探针**：见 §8.4 第 12 项（对开着轨道保持的群组断言"与计划轨道的偏差有界"，能分辨这两种实现）。

### A2 — 弹头接入 A0 之后的积分场（2026-09-14 已完成，含修掉段 baseTick 真 bug）

**问题**：`CombatGrid.ComputeProjectileGravity`（`CombatGrid.cs:520-546`）拿行星系相对的 `posMeters` 去减绝对坐标 `GetBodyWorldPosition`。`r` 里凭空多一个行星自身的绝对位置矢量（地球 = 1.2e8 m）。该方法 `systemBodyId` 形参在函数体内**完全未使用**——结构上就没有参考系概念。

**验收**：新增"漏靶弹头"观察场景（打偏、活过寿命），确认它真实地绕着地球弯成衰减轨迹。**现状无任何场景覆盖该路径**——这是该 bug 藏这么久的根本原因。

### A5 — id 分配器换机制 + 补齐实体注销路径（2026-09-14 已完成）

**A5a｜分配器**（原审查项）
**事实裁定**（原设计意图已无从回忆，由代码裁定）：`entities` 是权威超集——`RegisterEntity` 同时写 `entities` 和 group（`SpaceGameComp.cs:258-261`），而 `AVM.RemoveMissileEntity` 只 `group.RemoveEntity`（`AutonomousVehicleManager.cs:752`）。所以：

**A5b｜实体注册表泄漏**（**审查未覆盖，本次新增**）

## 8. 探针布置思路

### 8.1 为什么必须布探针，而不是"进游戏看一眼"

本轮改动有两种性质完全不同的问题，**眼睛都看不出来**：

- **等价性类**（A0 地球域、A5 扣料）：断言的是"数字不能变"。变了 0.1% 你不可能发现——必须机器逐位比。
- **行为变更类**（A0 月球域、A2 漏靶弹道）：断言的是"应该按某个量级修正"。光看到"它动了"没有意义，必须有一个**能分辨三种实现**的量。

项目里已经有两套对症的机制，**不要新造轮子**：

| 机制 | 现成范本 | 适合 |
| --- | --- | --- |
| **影子校验**（`PerfProbe`） | 5 个实例：`GameComponentRef.cs:37`（缓存 vs 实查）、`SpaceEntity.cs:122`（旋转求逆）、`SpaceGameComp.cs:2572`（聚合器复用 vs 重建）、`CombatManager.cs:1231,1365`（网格候选 vs 旧全场扫描） | 新旧两条实现同时存在、比结果、计 mismatch |
| **自检断言**（`ConstellationSelfTest`） | 造场景 + `Check(cond, label)` + 末尾打印 N/N（现成 32/32） | 只有新行为、无可比对照 |

注意影子机制的既有惯例：**旧实现是作为参照被永久保留在探针开关之后的**（如 `ExplOldScanCandidates` 至今保留着全场扫描做对照）。这不是死代码，是本项目的验收基础设施。

### 8.2 三条布点规则

1. **能差分的用影子，不能差分的用断言。** 改动前后都有实现的 → 影子；只有新行为的 → 断言。
2. **影子必须分域，而且必须允许"该不等的地方不等"**（见 8.3 的陷阱）。
3. **探针只计数、限频打印、绝不改被测行为。** 沿用 `ShouldShadowXxx()` 节流（每 64/256 次取一次）+ `Mismatch`/`Note` + 300 tick 汇总（`SummaryIntervalTicks`）；全部挂在 `PerfProbe.Enabled` / `ShadowChecks` 之后，关闭时零开销零副作用。

### 8.3 陷阱：A0 的影子不能写成"处处相等"

A0 的断言是**分域**的，两域方向相反：

- `CelestialBodyId == 根行星`（地球域）→ 新旧**必须逐位相等**（同样的天体、同样的数学，只是少了参量）。这条 mismatch 必须恒为 0。
- `CelestialBodyId == 子天体`（月球域）→ 新旧**必须不等**，且差值落在预测量级。

**如果影子写成"处处相等"，A0 在月球域会看起来全绿而实际没生效**——这正是审查在测试里批评过的那种假阳性（C1 的包线外负测试同源）。所以月球域必须显式断言 `!equal` 并记录一个差值样本。

### 8.5 哪些不需要探针

- **A3/A4**（UI 间距、字面量）、**E 类**（文档）：可见或可读，探针没有意义。

- **D2/D3**（构建与 CI）：属工程验证，不进游戏。

### 8.6 入口与落地方式

- **影子与计数 → 加进 `PerfProbe`**：新计数器（标注 `✗` 异常 / `正常，信息量`）+ `ShouldShadowXxx()` 节流 + 汇总行，随现有"性能探针"复选框开合。
- **场景型断言 → 学 `ConstellationSelfTest` 新建一个"引力自检"类**：造月球系群组 + 漏靶弹头 + 分配不变量 + 实体一致性，末尾打印 N/N；在 `DebugTabMenu_PFL` 加一个动作，沿用 `AddAction(label, "00 验收", priority, action, labelGetter)` 的写法（官方扩展点，不需要 Harmony 补丁）。
- **两个机制各司其职，不要混**：影子是"连续运行、抓到才报警"，自检是"造场景、一次性给结论"。把断言塞进影子会让它每 tick 打印，把计数塞进自检则失去连续观测能力。
- **编译隔离跟随 D5 的结论**：不要把新探针做成"只在 Debug 才能编译"，否则每次验收都得在 Release 重跑一遍（而 Release 不定义 DEBUG，这正是 `#if DEBUG` 的有效隔离前提）。
- **进度窗口 + 测试项勾选（2026-09-14 已实现）**：`Window_PFLSelfTest`（`00 验收 → 自检进度窗口`）实时显示总进度条、电池与 7 阶段逐行状态（未开始/进行中/通过/未覆盖/值判据失败/跳过）、㉑㉒引力读数、失败与未覆盖清单，并能直接启动/中止。
  每行左侧有**勾选框**（运行中置灰），另有预设「全选」/「只跑引力相关（电池+6/7+7/7）」/「跳过慢阶段（4/7 等）」——阶段 4「无 Map 碰撞」要等船漂到接触，是最慢的一项。
  勾选改动在**下一次运行**生效；结论的覆盖度分母取"勾选阶段数"，未勾选的阶段记为"已跳过"（既不算通过也不算未覆盖）。
