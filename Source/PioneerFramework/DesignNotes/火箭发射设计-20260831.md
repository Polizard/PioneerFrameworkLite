# 先驱框架Lite（PFL）火箭发射与爬升段制导设计

> 创建日期：2026-08-31
> 定位：**天地往返的第一环**——火箭从地面发射台升空、爬升、入轨的完整链路。解决两个此前被"瞬移入轨"回避的问题：① 天地坐标系映射（发射台在地表，空间物理在惯性系）；② 行星自转（地表不是静止的，自转白送初速）。爬升段采用"持续引导 + 目标轨道收敛"控制律，重力转弯是涌现行为。

**历史 bug 链（为何反复修不对）**：

**连带修复（progradeSign，必要非可选）**：真实自转切向 = radial×up，与引擎旧 prograde（up×radial）**反向**。若不改控制律，发射后控制律会先把自转初速刹掉再反向加速（赤道白烧 ~2×524=1048 m/s）。
- `LaunchGuidanceParams` 新增 `progradeSign`（+1=旧约定 up×radial；**−1=radial×up 与真实自转同向**，`CreateDefault` 默认 −1）；`ComputeStep` tangent 乘 progradeSign
- `RocketLaunchController.RocketLaunchState` 同步字段+序列化（默认 −1）
- 单测 `EquatorialLaunchState/SurfaceLaunchState` 初速改 `Cross(pos, up·ω)`（真实自转方向）→ 21/21 绿（控制律对称，方向翻转不影响收敛）
- 引擎圆轨机制方向无关（法向从入轨速度推导）→ 东向发射自动入 normal=−up 圆轨，无需改圆轨代码

**✅ 本会话已修：physicsTick 负值 = 「自转相位/经度错」根因（2026-09-03 问题①）**：

## 1. 背景（Problem）

当前 [LaunchFromGround](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Launch/LaunchService.cs#L101-L210) 的入轨是**瞬移**：直接把火箭放到 500km 轨道半径、速度给到圆轨 92%，靠 `BeginCircularize` 补 8% 的真实 dV。地面"火箭飞走"只是一层 Skyfaller 视觉演出。

这回避了两个真实问题：

1. **天地映射**：发射台在 RimWorld 地面地图上（有经纬度），空间物理在惯性系里，两者之间没有坐标换算。现在靠"随机角度"绕过了它。
2. **行星自转**：地面不是静止的。天体 `dayLengthTicks` 目前只被光照/日历消费（`CelestialBodyLayerManager`），从未进入轨道物理。自转带来的地表速度是"免费的初速"，也是日后顺行/逆行发射选址博弈的来源。

本设计的价值：把"从地面真实爬升入轨"做出来，让发射是**过程**而非**传送**，同时为后续天地往返（降落瞄准移动地表点）铺好单一事实源。

## 2. 核心概念

| 概念 | 定义 |
|---|---|
| **地心惯性系（ECI）** | 原点 = 行星中心，坐标轴固定于惯性空间。Group 位置就维护在此系（现有代码已如此）。忽略公转 → 系不动，牛顿定律直接成立 |
| **行星自转** | 行星在此惯性系内绕 +y 自转，角速度 `ω = 2π/dayLengthTicks`（rad/s，1 tick = 1 秒）。原点不动，只转地表点 |
| **地表点惯性状态** | 纬度 φ、经度 λ₀ 的地表点在惯性系里的时变 `(p, v)`：`λ(t) = λ₀ + ωt`，`v = ω × p`。**非惯性效应（科里奥利/离心）自动消除**——因为物理在惯性系算，无需人为建模 |
| **自转初速** | 火箭停在发射台就带着 `v_surface = ω × p`（赤道 ≈ 524 m/s），而 5500km 圆轨 ≈ 6030 m/s → 白送约 8% 入轨速度 |
| **爬升段** | 出生 `(r≈R, v≈524)` 到目标圆轨 `(r=R+500km, v≈6030)` 的持续燃烧段。起点不在任何可解析轨道上，只能持续推进 + TWR>1 |
| **持续引导** | 每物理步重算期望速度差的闭环控制（跳帮 BoardingManager 同构），无节流、无死区振荡 |
| **重力转弯（涌现）** | 爬升初期径向收拢项大 → 燃烧偏上；接近目标时切向 vC 主导 → 燃烧自动倒向水平。**不显式编俯仰程序** |
| **目标轨道收敛** | 期望速度 = 目标圆轨速度 + 朝目标半径的收拢项，距离衰减自动减速，不会过冲 |

## 3. 天地映射契约（单一事实源）

### 3.1 参考系与自转约定（冻结）

1. **轴与面**：自转轴 = +y（北极），赤道面 = xz（与现有轨道面一致，XML `orbitNormal=(0,1,0)`）。
2. **方向**：`ω = 2π/dayLengthTicks`，绕 +y 正方向；东向 = `Cross(up, radial)`，即自转切向。已核实与现有 `LaunchService` 的 `tangentDir` 同向，**无需改任何坐标系约定**。
3. **time**：自转相位用 **physicsTick**（与轨道物理同源，不能用 realTick——近月参考系漂移的教训）。
4. **不缓存**：点火时刻用当前 physicsTick 现算 `p(t)/v(t)`（发射台随自转在动）。

### 3.2 单一事实源函数（待落码）

```
GetSurfaceState(bodyId, φ, λ₀, t) → (p, v)
  ω = 2π / dayLengthTicks(bodyId)
  λ(t) = λ₀ + ω·t
  p(t) = r·( cosφ·cosλ,  sinφ,  cosφ·sinλ )
  v(t) = r·cosφ·ω·( -sinλ,  0,  cosλ )

派生：
  GroundStateAtLaunch(pad, t)   // 发射台 → (φ, λ) → 惯性状态，点火现算
  SurfaceStateAbove(p, alt)     // 出生点 = p + radial·alt，速度继承 v_surface
```

- **tile → 经纬度**：`Find.WorldGrid.LongLatOf(tile)` → `(经度 x, 纬度 y)`；冻结"世界经度 0° = 空间 +x"（可含任意常数相位，自洽即可）。
- **忽略 Map 内偏移**：发射台经纬度 = 所在 tile 中心（几米偏移对 5000km 半径可忽略）。
- **按 bodyId 参数化**：月球（潮汐锁定，dayLengthTicks=160000）日后做月面基地/对月发射直接复用；月球表面在惯性系是"公转 + 自转"叠合，先留参数位。

### 3.3 出生状态

```
pos_rocket = SurfaceStateAbove(p_surface, alt)   // alt 极小，如 10km
vel_rocket = v_surface                            // 继承地表速度，尚未被推力改变
```

## 4. 爬升段制导（核心）

### 4.1 现实约束（决定可行性的前提）

- **TWR > 1**：地表 `g = GM/R² = 8 m/s²`。化学引擎 `F = ve·ṁ = 3500×20 = 70kN`，对 2t 全重 TWR≈4.4，够。**这是爬升起点的硬校验**。
- **燃料预算真相**：到 5500km 圆轨总 ΔV ≈ **7000-9000 m/s**（切向 6030-524 + 势能 ~2700 + 重力损失 ~1500+）。化学 ve=3500 → 质量比 e^2.4≈11，燃料 = 干质量 10 倍。现有 debug spec（fuel 1000kg）远不够。
  → 结论：**分级不是后加的锦上添花，是让爬升可行的前提**。但制导与分级在代码上**完全解耦**（控制器只认 `IPropulsionSource`，将来切到当前级），先写制导，分级后接。

### 4.2 控制律（纯数学核心，脱离 RimWorld 可单测）

```
// LaunchGuidanceCore.ComputeStep(pos, vel, GM, params) → (dv 指令, 到达标记)
vC        = sqrt(GM / r_target)                       // 目标圆轨速度（常数）
radialOut = pos.normalized
tangent   = Cross(up, radialOut).normalized           // 当前点顺向（与自转同向）
deltaR    = r_target - |pos|
vTan      = vel·tangent                               // 当前切向速度
alt       = r - planetRadius                          // 相对表面高度
radialSpeed = clamp(deltaR / τ, -vRadMax, +vRadMax)   // 径向收拢（仅倾倒段/高空用）

// 显式俯仰程序（重力转弯近似，2026-09-02 修正）：
//   ① alt < altPitchStart（竖直起飞段）：
//        radialTarget = vAscent           全量竖直爬升，对抗重力
//        tanTarget    = vTan              切向保持现状（防突变）
//   ② altPitchStart ≤ alt < altPitchEnd（倾倒段）：
//        t = (alt - altPitchStart)/(altPitchEnd - altPitchStart)
//        radialTarget = vAscent·(1-t) + radialSpeed·t    竖直 → 收拢
//        tanTarget    = vTan·(1-t)     + vC·t            当前 → vC
//   ③ alt ≥ altPitchEnd（高空）：radialTarget = radialSpeed, tanTarget = vC
desiredVel = radialOut·radialTarget + tangent·tanTarget
dv = desiredVel - vel
if |dv| < deadband:  return (zero, arrived=false)     // 不烧
else:               return (dv,  arrived=…)

到达判定（窗口内才切给入轨）：
arrived = |deltaR| < tolR 且  ||vel| - vC| < tolV
```

**为什么不能纯追踪 vC（2026-09-02 教训）**：`dv=(vC·tan+300·out)-vel` 在低空 v≪vC 时方向 ≈96% 切向，径向推力分量（≈1 m/s²）压不住重力（8 m/s²）→ 火箭贴地表水平加速坠落，永不竖直爬升。必须显式先竖直起飞、再渐进倾倒。

**控制器无记忆**：无积分器、无历史，每步只由 `(pos, vel, 参数)` 决定。纯函数化 → 可单测、载入存档不漂移。

### 4.3 物理侧复用

控制器每步对 group：`EndBurn()`（清残余）→ `StartBurn(dv)`（`burnUseRcs=true` 全矢量免对准）。实际推力 / 工质消耗 / 质量变化仍在 [ComputeGroupPhysics](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Base/Game/SpaceGameComp.cs#L709-L813) 的 `HasActiveBurn` 分支处理——**非圆轨起点正好能跑，不需要新物理**。

### 4.4 冻结参数（初值，单测内可调）

| 参数 | 值 | 说明 |
|---|---|---|
| `r_target` | R + 500 km | 与现有入轨高度一致 |
| `τ` | 600 s | 径向收拢时间常数 |
| `vRadMax` | 300 m/s | 径向收拢速度上限（控重力损失） |
| `deadband` | 0.5 m/s | 与 `nodeDV` 阈值同量级 |
| `tolR` / `tolV` | 10 km / 10 m/s | 到达窗口（复用 `CircularizeDvThreshold`） |
| `vAscent` | 500 m/s | 竖直起飞段目标爬升速度（2026-09-02 新增） |
| `altPitchStart` | 20 km | 倾倒开始高度（相对表面）（2026-09-02 新增） |
| `altPitchEnd` | 250 km | 倾倒完成高度（相对表面）（2026-09-02 新增；实测 250km vs 400km 仅差 ~35 m/s，时序几乎不影响 ΔV） |

### 4.5 交接

`arrived` 为真 → 控制器清 burn → 调 [BeginCircularize](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Base/Game/SpaceGameComp.cs#L1962)。它自带工质可行性检查 + 两段式真实圆轨化：引导已近圆轨就免费完成（nodeDV < 0.5），差一点就补一次真实 burn。**交接安全，无需新逻辑**。

### 4.6 已知取舍（先声明，不修）

分段俯仰（竖直起飞→倾倒→追踪 vC）比能量最优重力转弯略费 dV，但对游戏够用且极其稳健。**旧版纯追踪 vC 在低 TWR 下会坠地（2026-09-02 实证），已废弃**。将来想更省：第一阶段先爬到转移弧远地点、第二阶段再圆轨化——需要额外规划一层，现在不做。

```
LaunchFromGround（改造）
  └─ GroundStateAtLaunch(pad, t) → 出生 (p+alt, v_surface)    // 天地映射，取代随机角度瞬移
```

## 6. 与分级的解耦（明确边界）

- 制导控制器只认 `IPropulsionSource`（现在是 `SpaceMapComp` 虚拟推进 / 实体 `PropulsionData`，将来切到当前级的推进源）。**分级 = 切换推进源 + 干质量跳变**，不影响控制律。
- 分级方案（后置）：方案 A 逻辑分级（Part 内 `StageData[]`，分离 = 干质量 -= 该级 + ve/ṁ 切换，回调 `IRocketStageHooks.StageSeparate` 做回收）vs 方案 B 物理分级（group 挂多 stage entity）。除非要"抛掉助推级成为可撞击残骸"，否则方案 A 足够。
- 燃料预算的现实（§4.1）是分级的第一驱动力：第一级化学出大气（ΔV~4500, 质量比 3.7），上面级核热/离子（Defs 已有 ve=9000 / ve=30000）圆轨化（ΔV~3000, 质量比 1.4）。
