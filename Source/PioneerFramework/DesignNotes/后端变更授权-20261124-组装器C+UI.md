## 变更前的死路（为什么必须加这个方法）

现状：`Complete` 是**没有出口的状态** —— `CanEditDesign` 只认 `Idle/Designing`（:75），`StartBuild` 拒绝 `Complete`（:696），
唯一能离开 `Complete` 的 `StartNewRocket`（:645）会走 `ResetToIdle`（:652）**把设计一起清空**。
所以 C+ 的「完工 → 编辑设计」现在只能由 UI 侧保存 11 字段快照、调 `StartNewRocket`、再把快照灌回去（:790-823）——
一次绕过后端的、易漏字段的假接口。

`ReopenDesign` 把这件事放回后端，语义严格限定：

```csharp
public bool ReopenDesign()
{
    if (state != AssemblerState.Complete) return false;   // 只从 Complete 回 Designing
    state = AssemblerState.Designing;
    workDone = 0f;
    workRequired = 0f;      // StartBuild 会在 :726-727 重算，置 0 只表示"还没开工"
    launchTicksLeft = 0;
    Design.fuelAmount = 0f; // FinishBuild 完工时加过油（:1025），回设计态必须清掉
    return true;
}
```

- **保留**：`design` 对象本身（parts / 级标签 / 载荷 / 机舱 / 尺寸）——不重建、不拷贝。
- **不碰**：`parent` / `Map` / 时间基 / 物理步 / `Tick()` / 存档字段（`PostExposeData` 无新增）。
- **之后必须重新 `StartBuild`**：`Designing` 不是可发射态，`BeginLaunch` 仍要求 `Complete`（:762）。

## 判据

1. **测试（3 条，过滤 `RocketAssembler`，基线 43 → 46 全绿）**
   - `ReopenDesign_FromComplete_KeepsDesignAndClearsWork`：`StartBuild` → `ForceComplete()`（:1011，`Building→Complete` 的免 Thing 入口）
     → `ReopenDesign()` true；`State==Designing`；`CanEditDesign`；`WorkDone==0`；`WorkRequired==0`；`LaunchTicksLeft==0`；
     `Design.fuelAmount==0`；parts 的 defName 与顺序逐项不变；随后 `StartBuild` 仍 true。
   - `ReopenDesign_RejectsNonCompleteStates`：`Idle` / `Designing` / `Building` 三态调用均 false 且状态不变。
   - `ReopenDesign_ThenBeginLaunchIsRejected`：回到设计态后 `BeginLaunch` false（理由含「完成」）。
2. **构建**：`-c Debug` 与 `-c Release` 均 **0 error**，新增警告 **0**（基线 260，全为既存 CA1305/CA1826）。
3. **锁**：`tools/check-backend-lock.ps1` 报 backend paths = **2**（comp + DLL），且命中的是**本件**（不是 20261111 那份粗粒度放行）。
4. **交付件**：`tools/rebuild-dll.ps1` 重建后 `tools/check-committed-dll.ps1` 哈希一致。
5. **游戏内（唯一尚未做过的一步）**：重启 RimWorld → 选中组装器 → gizmo「火箭组装器」**直接打开 C+**；
   走完 `完工 → 编辑设计（设计仍在）→ 重新建造 → 完工 → 发射`。
