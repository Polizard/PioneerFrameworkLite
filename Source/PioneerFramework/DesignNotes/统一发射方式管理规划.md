# 统一发射方式管理规划（火箭：原版 TransportPod / PFL 入轨）

> 日期：2026-08-21
> 状态：已按用户审查意见定稿并进入实现
> 目标：把当前“火箭自带原版发射”和“发射台调试直发”合并成一套统一入口，并向玩家提供发射方式选择。
>
> **用户决定**
> 1. 口袋地图不在发射时处理；是否生成口袋地图应在“设计航天器”阶段区分“航天舱室 / 普通运输仓”。当前设计界面缺失，该项暂缓，仅记录此设计。
> 2. 剩余三点按建议执行：记住上次选择、原版模式使用原版条件、使用独立发射窗口。

---

## 1. 背景与问题

当前 PFL 的火箭存在两条互不联通的发射路径：

1. **点选火箭 → 原版 TransportPod 发射**
   - 火箭 Def 带 `CompProperties_Launchable_TransportPod` + `CompProperties_Transporter`。
   - 走 RimWorld 原版 `CompLaunchable`：选择世界目标，消耗燃料，作为运输舱发射到原版地格。
   - 这条路径不会创建 PFL `SpaceEntity`，也不会把舱内口袋地图带到轨道。

2. **点选发射台 → PFL 调试直发**
   - `CompAssemblyPad` 提供“直接发射 (调试)”按钮。
   - 走 `LaunchService.LaunchFromGround`，生成 `SpaceEntity` + 口袋地图 + 入轨机动。
   - 但是按钮是调试级，没有正式 UI、没有发射方式选择、没有和火箭自身的原版发射入口统一。

因此需要一个**统一发射管理器**：

- 所有 PFL 建造的火箭都从同一个入口发射；
- 入口上可选择“原版发射”或“PFL 入轨发射”；
- 两种方式共用设计、状态、燃料/条件校验、离港特效、回收逻辑；
- 避免玩家误用原版发射导致 PFL 轨道实体/舱内地图丢失。

---

## 2. 目标

1. 提供统一发射 API，任何调用方（火箭 Gizmo、发射台 Gizmo、未来 DMS:NF 接入点）都走同一入口。
2. 玩家在发射时能明确选择：
   - **原版 TransportPod 发射**：发射到世界地图地格/原版运输舱流程。
   - **PFL 入轨发射**：生成 `SpaceEntity`，携带舱内口袋地图进入轨道。
3. 发射方式可持久化，至少能为当前火箭/发射台记住上次选择。
4. 不破坏非 PFL 火箭的原版发射能力。
5. 离港特效、助推器回收、发射台状态机在两种模式下都正确触发。

---

## 3. 现状梳理

| 模块 | 现状 | 问题 |
|------|------|------|
| `CompAssemblyPad` | 状态机：空闲/设计中/建造中/已完工；有调试直发 | 没有正式发射入口，没有方式选择 |
| `Building_AssemblyPad` | 实现 `INotifyLaunchableLaunch` | 只在原版发射后触发 FX/回收，不负责状态复位 |
| `CompLaunchable` | 原版发射 Gizmo 直接出现在火箭上 | 与 PFL 发射入口并列，玩家容易走错路径 |
| `LaunchService` | PFL 入轨核心，`LaunchFromGround` | 已是正式形态，但缺少 UI/方式路由 |
| `CompRocketPocketMap` | 已能生成/关联舱内地图 | 未参与发射方式选择 |

---

## 4. 方案概述

### 4.1 新增发射方式枚举

```csharp
public enum RocketLaunchMode
{
    VanillaTransportPod, // 原版：世界地格运输舱发射
    PflOrbit             // PFL：生成轨道实体 + 舱内地图入轨
}
```

### 4.2 核心：统一发射管理器

新增 `RocketLaunchManager`（建议放在 `PioneerFramework.Launch`），作为唯一发射入口。

对外只暴露：

```csharp
public static class RocketLaunchManager
{
    // 当前火箭是否属于 PFL 统一管理范围
    public static bool IsManagedRocket(Thing rocket);

    // 获取发射上下文（火箭、发射台、设计、舱内地图、燃料等）
    public static bool TryGetLaunchContext(Thing rocket, out RocketLaunchContext context);

    // 查询某方式是否可发射，返回原因列表
    public static List<string> GetLaunchBlockReasons(RocketLaunchContext ctx, RocketLaunchMode mode);

    // 打开统一发射窗口（由 Gizmo 调用）
    public static void OpenLaunchDialog(Thing rocket);

    // 执行指定方式发射
    public static bool TryLaunch(Thing rocket, RocketLaunchMode mode);
}
```

`RocketLaunchContext` 为快照/引用集合：

```csharp
public class RocketLaunchContext
{
    public Thing Rocket;
    public CompAssemblyPad Pad;
    public RocketDesignSpec Spec;
    public Map PocketMap;
    public CompLaunchable VanillaLaunchable;
    public CompRocketPocketMap PocketMapComp;
}
```

### 4.3 统一入口位置

- **火箭 Gizmo**：给 PFL 火箭新增“发射…”Gizmo，替代/隐藏原版 `CompLaunchable` 的发射 Gizmo。
- **发射台 Gizmo**：`CompAssemblyPad` 的“发射…”按钮也调用同一个 `RocketLaunchManager.OpenLaunchDialog`。
- 两处入口最终都打开同一个发射窗口，不再保留“调试直发”作为唯一正式入口。

### 4.4 屏蔽原版发射 Gizmo 的范围

只屏蔽 **PFL 管理范围内的火箭**，判断依据：

- 火箭上存在 `CompRocketPocketMap`；或
- 火箭位于带 `CompAssemblyPad` 的发射台上；或
- 火箭由 PFL 总装流程建造（`RocketDesignSpec` 可追溯）。

非 PFL 火箭、原版运输舱保持原版发射逻辑不变。

实现方式：

- Harmony Patch `CompLaunchable.CompGetGizmosExtra`，对 PFL 管理火箭过滤掉原版“发射”相关 Gizmo；
- 或者不屏蔽，而是通过 Comps 排序/交互让玩家优先看到统一入口。**推荐前者**，避免双入口误操作。

## 5. 发射窗口交互设计

### 5.1 窗口内容

建议新增 `Dialog_RocketLaunch`，第一版只做功能可用：

- 火箭信息：型号、框架尺寸、燃料、载荷、舱内人员数。
- 状态检查：
  - PFL 模式：推进器、燃料、控制台、密封舱室。
  - 原版模式：使用 `CompLaunchable.CanLaunch` 的燃料/装载/连接燃料口检查。
- 发射方式选择：
  - 原版 TransportPod 发射（说明：飞往世界地格，不生成 PFL 轨道实体）
  - PFL 入轨发射（说明：生成轨道实体，舱内地图随火箭入轨）
- 确认按钮：
  - 原版模式 → 关闭窗口并调用 `CompLaunchable.StartChoosingDestination`，由原版世界目标选择流程接管。
  - PFL 模式 → 直接调用 `RocketLaunchManager.TryLaunch(ctx, RocketLaunchMode.PflOrbit)`。

### 5.2 默认方式

- PFL 总装建造的火箭默认 `PflOrbit`。
- 玩家可在窗口中临时切换，也可在发射台/火箭上保存偏好。
- `CompAssemblyPad` 持久化 `RocketLaunchMode`，读档后恢复。

## 6. 两种发射路径的职责划分

### 6.1 原版 TransportPod 路径

流程：

1. `RocketLaunchManager.TryLaunch(VanillaTransportPod)`
2. 确认火箭可发射、燃料足够、连接燃料口。
3. 调用 `CompLaunchable.StartChoosingDestination()` 进入原版世界目标选择。
4. `CompLaunchable.TryLaunch` 成功后：
   - `Building_AssemblyPad.Notify_LaunchableLaunched` 继续负责发射特效/助推器回收。
   - 由管理器（或 Harmony 补丁）把 `CompAssemblyPad` 状态复位为 `Idle`，清理设计/舱内地图引用。

注意：

- 原版发射不会创建 PFL `SpaceEntity`。
- 如果玩家已生成 PFL 舱内口袋地图，选择原版发射时需要明确处置：优先提示“舱内地图不会随原版发射入轨”，并允许玩家选择**保留**或**销毁**。规划建议：默认销毁，避免孤立地图；后续可支持“原版发射也携带舱内内容”的扩展。

### 6.2 PFL 入轨路径

流程：

1. `RocketLaunchManager.TryLaunch(PflOrbit)`
2. 执行现有 `RocketLaunchConditions.Validate`。
3. 调用 `LaunchService.LaunchFromGround` 或新封装的正式入口。
4. 成功后：
   - 生成/关联 `SpaceEntity` + `SpaceEntityGroup`；
   - 复用/生成舱内口袋地图；
   - 注入虚拟推进；
   - 执行两段式圆轨化；
   - 地面火箭销毁，发射台保留并回 `Idle`。

## 7. 发射台状态机整合

建议保留现有状态，新增一个瞬时“发射中”仅用于 UI 防重复点击/进度显示：

```
Idle -> Designing -> Building -> Completed -> Idle
                        |              |
                        +--- 发射中 ---+
```

- 两种模式发射成功后都应把发射台回 `Idle`。
- 原版发射成功通过 `INotifyLaunchableLaunch` 或 `CompLaunchable.TryLaunch` 后回调，由管理器清状态。
- PFL 发射失败时保持 `Completed`，保留舱内地图供玩家修复后重试。

---

## 8. 存档与兼容

需要新增/扩展存档字段：

- `CompAssemblyPad`：`RocketLaunchMode`（默认 `PflOrbit`）。
- `CompRocketPocketMap`：无新增必要，已有地图 ID。
- `RocketLaunchManager` 无全局状态，不需要独立存档。

兼容性：

- 旧存档没有 `RocketLaunchMode` 字段时，默认按 `PflOrbit` 处理。
- 非 PFL 火箭完全不走新管理器，原版发射不变。
- 后续 DMS:NF 火箭可通过挂 `CompRocketPocketMap` / 关联发射台自动纳入统一管理。
