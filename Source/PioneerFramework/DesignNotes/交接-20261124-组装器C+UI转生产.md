## 2. 三个必须先知道的坑

### 2.1 文件在 `Presentation/Windows/`，namespace 却是 `PioneerFramework.GroundAssembly`

这不是笔误：C+ 窗口与 `CompRocketAssembler` 同命名空间，gizmo 那行才能直接 `new Window_RocketAssemblerC(this)` 而不用 using。
**不要"按目录顺手改 namespace"** —— 一改 `CompRocketAssembler.cs` 的 gizmo 立刻编译错。

### 2.2 `ReopenDesign()` 的边界（只认 `Complete`）

```
Complete --ReopenDesign()--> Designing     （保留 design：零件/级标签/载荷/机舱/尺寸）
Designing --StartBuild()--> Building        （工时在 StartBuild 里重算）
```

- 只在 `state == Complete` 时返回 true；`Idle/Designing/Building/Launching` 一律 false 且状态不变。
- 清 `workDone / workRequired / launchTicksLeft / Design.fuelAmount`（完工时 `FinishBuild` 加过油）。
- **不碰** `parent` / `Map` / 时间基 / 物理步 / 存档字段。
- `StartNewRocket()` 仍然只给 L0 的「下一枚」（它会 `ResetToIdle` 把设计清空）。
- 附带行为面扩大：`DoLaunch` 失败与 `CancelLaunch` 也停在 `Complete` ⇒ 它们同样获得"回去改设计"的出口。

### 2.3 旧窗口 `Gameplay/GroundAssembly/Window_RocketAssembler.cs`

**已无任何调用方**（全库只剩它自己的类声明），保留作回退。
但 `旧版航天器发射路径退役-20261121.md:28` 把它列进"不得删除"清单 —— 要删它，先改那份授权件，别直接删。

## 3. ⚠️ 新授权件必须 `git add -f`（否则 PR 上 CI 必红）

`.gitignore:59-61` 的规则是：

```
Source/PioneerFramework/DesignNotes/*
!Source/PioneerFramework/DesignNotes/TODO.md
!Source/PioneerFramework/DesignNotes/交接-*.md
```

⇒ **`后端变更授权-*.md` 不在例外里，默认被忽略**。而 CI 的后端锁检查
（`.github/workflows/ci.yml` 的 `Backend lock check` → `tools/check-backend-lock.ps1:64-72`）
是**在检出的工作目录里找这个文件名**；授权件不进 commit，干净检出里就没有它 ⇒ 任何动后端的 PR **永久红**。

- 本分支 2026-11-24 那份授权件是用 **`git add -f`** 加进去的（`.gitignore` 未改）。
- **以后每新增一份授权件，都要 `git add -f <路径>`**。已跟踪的文件不受 .gitignore 影响，之后的修改正常 `git add` 即可。
- 本文件（`交接-*.md`）命中例外，正常 `git add` 就会进库 —— 这也是它被命名为"交接"的原因之一。
