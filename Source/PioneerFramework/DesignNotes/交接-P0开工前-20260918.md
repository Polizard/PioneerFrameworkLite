## 1. ⚠ 不要重新辩论的三件事

**(1) "要不要基于 MJ2 重写 / 我们的核心是不是更强"。** 已裁定，且是**用实测数字**裁的，不是口味：
MJ 约 **120 种自动能力** vs 我们约 **5 种**；工具箱我们只覆盖 **≈25–30%** 且**缺整族**（双曲动力学全部 / 任何约束优化器 / 可复用求根极小化 / 自适应 ODE + 事件 / 无量纲化 / SOI）。
**关键**：我方**仅有的两处真深度**（CW、连续律）是**两个格子**，抵不过**六个整族的缺席**。
⇒ 别再写"我们的 X 比 MJ 好"这种句子，除非你**同时**给出它在哪一族里、那一族我们缺不缺。

**(2) "七连败是不是只是运气/个别 bug"。** 个别是真 bug（§29 冻结向量、§27 死区），但**贯穿性机制**是：
$$\textbf{全部评估都是"我们的 A vs 我们的 B"，我们从来\emph{没有外部坐标原点}。}$$
于是判据只能自定，而自定的判据反复出错（§14.6 拿开环成本判闭环 → §19.2 拿静态最优判滚动执行 → §19.6 又拿同一个错判据挑视界，**同一个坑三次**）。
**MJ 当底盘消掉的就是这场判据辩论**——它同时是**参照系**（§13），不只是功能基座。

**(3) "我们特有的东西是不是都该删"。** 不是。台账把它分成了三类：**特有 regime（真价值，保留并推广）** vs **自造债务（可删）** vs **两边都有做法不同（优化战场）**。
判据不是"好不好"，而是**"MJ 为什么没有它"**：KSP 里不需要（CW），还是 MJ 的架构限制（多圈 Lambert 被 `nrev=0` 锁住）。

## 3. P0 的第一步（按此顺序，别跳）

1. **先跑 `tools/test-all.ps1` 记下基线**（0 错误 / 新增警告 0 / 纯测试只增不减 / Release 字节一致）。
   ⚠ **基线数字不要写进任何文档**——它会漂，写死了就会制造假警报（本项目有过先例）。
2. **先建 `ThirdParty/MechJebLib/` 与 R1 的跨求解器互证台**，**再**开始移植。
   理由：**手性/轴约定一旦错（R1），后面每一个移植物都会给出"看起来合理"的错数**，而没有互证台就抓不到。
   互证三层：`OrbitView` ↔ `OrbitMath` ↔ 数值传播求根（同一 `(r,v)` 下周期、最近接近时刻必须一致）。
3. 再按"小 → 大"移植：`Scale` → 求根/极小化（`Bisection`/`BrentRoot`/`Newton`/`BrentMin`）→ `Shepperd`+`Farnocchia`（**顺手根治 Q11**）→ `Angles` 全套 → `Astro` 几何与事件块。
4. 然后 `OrbitView` + 逐字 `OrbitExtensions` + **1 个 Operation 端到端**（= P-1 判据 A4，L2 oracle 模板成型）。
5. **收工按 V1/V2 点删**（见 §14.5）：**"被删除的东西"逐项 `git grep` 必须零调用点**；**一项没归零，这一批就没完成**。
