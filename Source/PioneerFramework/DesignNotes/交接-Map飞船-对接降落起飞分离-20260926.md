## 0. 现场一句话

我们要在**不依赖 Odyssey DLC** 的前提下，自建一套"船就活在地图里"的飞船系统：
船在三种形态之间循环（**地面建筑群 → 搬运态 → 含图编队**），
**起飞 / 降落 / 对接 / 分离这四条链其实是同一个"搬运原语"的四个端点**；
"这艘船还是不是一艘船"由**连通分量数 = 1** 判定（拓扑算法已实测可行）。
现在的问题不是"能不能做"，而是**六个语义还没裁定**（§8）——它们不定，代码写出来就是猜。

### 3.3 不装 DLC 时会"静默变哑/变 null"的东西（**碰了就踩**）

`TerrainDef.IsSubstructure` 硬要 `OdysseyActive` ⇒ **我们自己的地形打了 `Substructure` tag 也恒为 false**：
**不能复用原版对底架的判定，只能复用原版的基础设施**，必须自带 `IsMySubstructure(cell)`。
另有三处**核心声明但零守卫、却依赖 Odyssey Def** 的真雷：
`SubstructureGrid` 的绘制/`MarkDirty`（摸 null 的 `ThingDefOf.GravEngine`/`StatDefOf.SubstructureSupport`）、
`SectionLayer_GravshipMask.RegenerateGravshipShadowMask`（硬取 `TerrainDefOf.Space`）、
往 `extraGenStepDefs` 塞 null def（`orderby x.def.order` NRE）。
反向的雷：`GravshipCapturer`/`GravshipRenderer` 不装 DLC 是**静默失败（回调不触发 ⇒ 流程卡死等待）**，比抛异常难查。

### 3.4 连通判据已实测（**不要重做，也不要重辩**）

实验室 `Source/TopologyLab/`，四判据**每一步与暴力全量对拍**，完整套件 `exit=0`（864 例随机 × ≤1500 步 × 两配对 + 200 例批量 + 14 边界）。
250×250 = 62,500 格实测：全量重算 1.4–1.9 ms；**单格增删 4.6 µs（4/8 配对）/ 24.6 µs（8/4）**；
批量 1000 格 1.8 µs/格；最坏情况（砍断哑铃的桥）扫 31,125 格 = O(分量)，接回扫 0 格。
**两条必须继承的结论**：① 前景与背景必须**互补配对**（(4,8) 或 (8,4)，混用破坏 Jordan 定理）；
② 批量删除的修复闸门必须按**正的部分之和**判断，不能看净值。

## 4. 统一模型（全案的骨架）

```
形态 A：地面建筑群          在普通 Map 上的一堆建筑（玩家在地上的船）
形态 B：搬运态 ShipStorage   无图，只活在几个 tick 内（不是一种持久状态）
形态 C：含图编队             轨道上的船 = SpaceEntity/Group + HasMap/MapId（1 图 = 1 船）
```

**一个原语**：`搬运原语`——把一块**连通区域的全内容**从一张图搬到另一张图，或搬进搬运态：
逐格快照（地形/屋顶/气体/房间温度真空 + 每件 Thing 的相对格/朝向/HP + 区域/存储组/设计/电力连接/故事状态 + Pawn 的相对格/朝向/征召），
逐格还原，**单 tick 原子完成**。

**四条链 = 这个原语的四个端点**：

| 链 | 从 | 到 | 用户编号 |
|---|---|---|---|
| 起飞 | 地面图（A） | **新建**船内图 + Group（C） | R4 |
| 降落 | 船内图（C） | 目标地表图（既有图或新建） | R5 |
| 对接 | A 船内图（C） | B 船内图（C），落点须与 B 现有船连通 | R3 |
| 分离 | 一张图内的两块 | 两张图，各自"1 图 1 船" | R2 |

⇒ **写一次搬运原语，四条链都是它的调用方**。不要为任何一条链另写一套搬运。

### P0 前置清理：隐性 Odyssey 依赖（与方案解耦，先做）

- 做什么：§3.2 的五条（重点：三张图换**自建空间 Biome**，`BiomeDef.inVacuum=true`；`SpacePocket` 兜底换成自建；核 `IsSpaceFloor` 到底在保护什么）。
- 判据：不装 Odyssey 时三张口袋图能生成（或显式降级并有日志）；`.cs` 里 `ModsConfig`/`Odyssey` 零命中（注释除外）。
- 探针：一条"口袋图生成自检"用例（`PflTestKit`）：断言图生成成功 + `map.Biome` 非 null + 关键 Def 解析成功。
- 为什么先做：它是 D2 的落地检查，**与四条链完全解耦**，可以独立验收。

### P1 搬运容器（`ShipStorage`）——D8 的"新的飞船储存方式"

- 必带清单（照 Odyssey `Gravship` 字段面推 + **我们额外要三样它没有的**）：
  - 通用：每件 Thing/Pawn 的相对格 + 朝向（Pawn 另带是否征召）/ 电力开关与 `connectParent` / 屋顶 / 地基 / 表层地形 + 地形色 / 地形上的设计 / 气体 / 区域 / 包围盒与占用矩形 / **房间温度与真空** / 推进器 / 外部门 / 场延伸器位置 / 故事状态 / 自动屠宰配置 / 目的地与出发 tile / 航程百分比 / 朝向
  - **额外① 伤害两套口径对齐**（地表 `Thing.hitPoints` ↔ 轨道 `SpacePart` HP，否则出现"轨道被打穿、落地完好"）
  - **额外② 对接端口状态**（`DockingPorts` 现在恒空，对接语义一成立它就得跟着船走）
  - **额外③ 地面桥换绑**（`SpacecraftBridge` 四 id：起飞解绑、落地重绑；注意 `RebindBridge` 是**无条件覆盖**，要防重入）
- 健壮性四条：**单 tick 原子** / **幂等**（同一转换触发两次不能搬两遍）/ **短命**（见下）/ **搬运中不外泄**（转换期间把图 owner 置成显式"搬运中"标记，让所有反查点统一看到"正在搬"而不是"没有"）。
- ★ **搬运态必须短命**：明确规定它只活几个 tick，**轨道飞行一律用形态 C（含图）** ⇒ Pawn 的需求/生长/事件继续跑在地图语义上，我们不必为"没有图的船"重写整套。
- 判据：**装箱—还原往返不变式**（逐项比对完全一致）+ 幂等 + 单 tick 原子。
- 探针：`PflTestKit.Kind.Invariant`（涉及 RimWorld 类型，纯核跑不了 ⇒ 游戏内挂；跑不了的子项**显式登记为 Unchecked**，不许折算成 PASS）。
- 红线：**本步不做拓扑、不做 UI、不做对接**。

### P2 连通判据接入（把实验室搬进来）

- 前置：**§8 的未裁定项①"砖是什么"必须先定**（它决定孔洞有没有物理意义）。
- 做什么：自建 `IsMySubstructure(cell)` + 分区/计数（复用实验室算法与判据）；**不复用** `TerrainDef.IsSubstructure`（§3.3）。
- 角相碰语义要与**寻路（4 邻域通行）/ 房间 region / 气密真空**三套系统对齐——同一个"两格只在角上相碰"，三者答案可能不同。
- 判据：变更序列逐步与暴力全量对拍（计数 / 恒等式 `w%4==0 && w/4==c−h` / 分区）。
- 探针：一条"地图上建拆序列回放"用例，每步对拍。

### P3 图生命周期（补 `DestroyGroup` 的洞）——**四条链的地基**

- 裁定语义：编队被销毁时它那张图怎么办（封存 / 销毁并处理船员 / 交给接任者）。
- 硬要求：**任意 tick 边界（含存档点）上，每张图恰有一个 owner，或处于显式"搬运中"**。
  `FindPocketMap`/`GetMapComp` 一销毁就返回 null ⇒ 中间态会被外部读成"有图但进不去"。
- 现状必须改：`CheckPlanetCollision` 与 `TryLandAtTile` 末尾直呼 `DestroyGroup`（现成的孤儿图泄漏面）。
- 判据：不产生孤儿图；**存档往返后不变式仍成立**（合并到既有 S11 读档口径）。
- 探针：读档后断言"每图恰一 owner 或显式搬运中"。
- 参考范式：`MapArchiveManager` 那套带 `Phase` 的可恢复阶段机（若不做单 tick 原子，就必须做成这种）。

### P4 降落（R5）

- 做什么：把 `TryLandAtTile` 从"扣料 + 销毁"改成"扣料 + **搬运到目标图**（既有图或新建）+ **接上地面桥**"。
- **前置裁定：Δv 账**（§8 未裁定项②）。
- 落点：`EciToTile` 星下点 + `LandingQuote` 距离门 + **时间窗口**（落点随自转/轨道移动）。
- 判据：落地后图存在且内容逐项一致（往返不变式）；桥有效；重复触发幂等。
- 探针：扩 `LandingAcceptanceRunner` 四条（图存在 / 内容一致 / 桥有效 / 幂等）。
- 保留可观测：现有 `lastLandingConsumedKg` / `lastLandingQuotedDeltaV` 两字段与消息（验收要从日志读数看，别只靠"看起来对"）。

### P5 起飞（R4）

- 现状分界：现有 `LaunchFromGround` 是**真爬升 + 圆轨化**，但它**不搬 Thing/Pawn**、且**要求已有舱内图** ⇒ 新链必须补"把地表集群搬进船内图"。
- 顺手必做：**船内图尺寸按船包围盒自适应**（现在写死 50×50 ⇒ 大船起飞丢件；Odyssey 的 `canResizeToGravship` 是先例，我们自己实现）。
- D2 允许保留的只有"基础设施"：`GenStepWithParams` + `MapGenerator.GenerateMap(extraGenStepDefs)` 注入通道、`SectionLayer` 反射自动注册、`LayerSubMesh`、`CameraDriver`/`CameraShaker`（过场自写时白拿）。
- 判据：起飞后地表不留残件（或明确登记留什么）；船内内容一致；Group 的 `HasMap`/`MapId` 正确。
- 探针：起→降**闭环往返不变式**。

### P6 对接（R3）

- 触发：速度匹配 + 位置接近（阈值先例 `dist<400 && relv<15`，见 §3.1）。
- 落点约束：**与目标图现有船连通**（用 P2 的判据）+ **放不下就拒绝**（**绝不用清场式降落**——那会删掉队友的反应堆）。
- 对接后：端口状态随船、编队合并、**"1 图 1 船"不变式成立**。
- 判据：不连通则拒绝（负向契约）；连通则合并后 `c == 1`；重复触发幂等；**存档落在确认中途可恢复**。
- 探针：一组几何用例（贴合 / 不贴合 / 只在角上相碰）+ 不变式。

### P7 分离（R2）

- 触发：机动前检查连通分量 > 1 ⇒ 分裂。
- **前置裁定："哪块保图"的规则**（§8 未裁定项⑥）——必须**确定性**且**玩家可见**（不许隐藏策略替玩家选）。
- 判据：分裂后每张图 1 船；两份内容各自完整（往返不变式分两边各查一次）；**确定性**（同输入多次跑结果一致，不依赖遍历顺序）。
- 探针：确定性用例（重复跑比对）。

### P8（可砍）表现与内容

- 表现：抓图 / 地形帘幕 / 音效 / 运镜（`CameraDriver.PanToMapLocAndSize`、`CameraShaker.DoShake`、`SectionLayer_IndoorMask.BakeGravshipIndoorMesh` 都是核心的，可白拿；要自写的只是"抓图 + 帘幕"几十行）。
- 内容：材料 / 研究 / 仪式与质量 / 落地事故 Def / 派系。
- **砍掉不影响机制成立** ⇒ 默认最后做或不做。

## 9. 开放未知 / 风险登记

1. **不装 Odyssey 时三张口袋图的现状未验证**（§3.2 第 1 条）——P0 会实测；若发现已坏，先修再谈方案。
2. **`ownerEntityId` 单值与"搬运中"状态**：中间态必须对全部反查点可解释（`GetMyEntity`/操舵台/瞄准/相机/登船，共 4 个 owner 反查点 + 6 处 first-wins 读取点）。
3. **两套"层"**：Odyssey 的 `Orbit` 层（玩家装了 DLC 时）与我们的 `Moon` 层互不理会；天地往返我们走 ECI（`GetSurfaceState`），不走 PlanetLayer 的 tile 语义——**别把两套混起来用**。
4. **共存风险**：`canLaunchGravship=false` 只挡起飞**不挡建造** ⇒ 玩家装了 DLC 时仍能在我们船上盖重力引擎；要靠我们的判定不认它的引擎，或直接在我们的图上禁建。
5. **时间尺度**：任何"飞行时长"都要先和我们时间尺度对齐（游戏内一天 = 60000 s；我们在这上面栽过）。
6. **`Room.Vacuum` 的真空判定要自写**（`VacuumUtility.GetVacuum`/`IsRoomAirtight` 不装 DLC 恒 0/false；但 `BiomeDef.inVacuum`/`Room.Vacuum`/`ExposedToSpace`/房间更新器自动填值都是核心的，白拿）。
   顺带补上现在的弱占位：`RocketLaunchConditions.HasSealedRoom` 只是"存在一个不贴地图边缘的房间"。
