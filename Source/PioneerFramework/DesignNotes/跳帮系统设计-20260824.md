## 1. 背景（Problem）

PFL 的太空战斗已有完整远程链路（`CombatManager` 射弹 / 命中 / 提前量，空间站对射是核心玩法），但缺少**近距离夺取**手段：突破了护盾/装甲之后，船体内部没有攻防入口。跳帮 = 直接向目标空间站内部 Map 投送战斗人员，与对射互补。

核心需求：
- 两种投送形态：**单兵 EVA**（小而脆、难命中、可多点突入）与**穿梭机**（大而韧、载人多、可反复往返）。
- 统一架构：一个飞行物体 = 一个物理 group + 一个实体 + 一个编号。
- 士兵本体 = 母船内部 Map 的 pawn，跳帮期间转"未生成"抽象状态，登陆后以原生 pawn 战斗。
- 穿梭机定位 = **通用运输工具**（Map ⇄ 3D 太空 ⇄ Map），跳帮只是其中一种用途；运输模式矩阵见 §5.1。

## 2. 核心概念

| 概念 | 定义 |
|---|---|
| **BoardingUnit** | 跳帮飞行单位。一个在太空中飞行的物体 = 独立 group + 临时 3D 实体 + 编号，由 BoardingManager 登记管理 |
| **落点** | 出发前在目标空间站内部 Map 选定的可站立格，存为目标空间站**局部系 3D 偏移**；空间站在轨道上动，世界目标点每步重算 = `targetGroupPos + 落点偏移` |
| **BoardingMember** | 成员 = 母船 Map pawn 的引用（`LookMode.Reference`）。飞行中 pawn 为未生成（DeSpawn）状态，登陆时 Spawn 进目标 Map |
| **ShuttleId** | 穿梭机稳定身份，贯穿"停泊 Map Thing ⇄ 飞行 3D 实体"两态，撤离升空时用同一 id 重建飞行态 |
| **运输模式** | 穿梭机 = Map ⇄ 3D 太空 ⇄ Map 通用运输。起降端两种类型：普通 Map（RW 原版交互）/ 空间站口袋 Map（PFL 落点机制）。2×2 矩阵四种模式，**第一版只做口袋 ⇄ 口袋**（含跳帮），见 §5.1 |
| **布置跳帮界面** | 起跳前专门 UI：选单位 → 进目标空间站内部 Map → 每单位选落点（可站立格过滤）→ 出发 |

## 3. 架构总览

```
布置跳帮界面（起跳前）
  └─ 选单位（穿梭机 / 单兵 pawn）→ 目标空间站内部 Map 选落点 → 确认出发

BoardingManager（GameComp，唯一管理器：跳帮单位 + 穿梭机全生命周期）
  ├─ 编号：独立递增序列 nextBoardingId，一个飞行物体一个编号，跨 3D/Map 两态身份
  ├─ 起飞：乘客上船(DeSpawn) → 穿梭机销毁 Map Thing / 单兵建实体
  │        → 注册 BoardingUnit → 建临时 3D 实体
  ├─ 飞行：目标 = targetGroupPos + 落点偏移（移动目标点，复用接近引导）
  ├─ 降落：距移动落点 < 阈值 + 相对速度 < 阈值 → 单兵 pawn Spawn 落点 /
  │        穿梭机生成停靠 Thing（继承 ShuttleId）→ 乘客下船 → 注销
  └─ 序列化：nextBoardingId + List<BoardingUnit>（3D 状态快照，载入重建实体）

CombatManager（唯一耦合点）
  └─ 碰撞分派识别分支：跳帮单位低速 → 转降落判定；高速 → 正常船-船碰撞爆炸
```

**职责边界**：BoardingManager **不做**——实体/group 创建（归 SpaceGameComp / 调用方）、Map/pawn 生成（归 SpaceMapGenerator / 跳帮流程）、物理积分（归 SpaceGameComp，BoardingManager 只读位置做逻辑）。

## 4. BoardingManager 设计

文件：`Base/Game/BoardingManager.cs`（`GameComponent`，挂 `Current.Game`，与 SpaceGameComp / CombatManager 平级）

```csharp
public class BoardingUnit : IExposable
{
    public int id;                        // BoardingManager 独立递增编号（跨 3D/Map 两态身份）
    public VesselType type;               // 单兵 / 穿梭机
    public int groupId;                   // 所属物理 group（临时 3D 实体）
    public int entityId;                  // 单兵=该兵实体；穿梭机=穿梭机实体
    public List<BoardingMember> members;  // 乘客池（穿梭机 N / 单兵 1）；BoardingMember 持 Pawn 引用
    public int targetGroupId;             // 目标空间站 group
    public int targetPartId;              // 目标 Part（落点局部系基准）
    public DVector3 landingLocalOffset;   // 落点 = 目标空间站局部系 3D 偏移
    public BoardingState state;           // Flying → Landing → Landed / Done / Destroyed
    // 3D 状态快照（飞行中存档用）：位置/速度/旋转
}
```

- **编号**：`nextBoardingId` 独立递增（与 groupId/entityId 分离——现有 id 是"扫 max+1"式分配，见 `CompDebugShipSpawner.GetNextGroupId`，BoardingManager 用自己的序列避免冲突与扫描）。
- **驱动节奏**：每 2 tick（与 `CombatManager.GameComponentTick` 碰撞同节奏，即物理步），不需要每 tick。
- **存 id 不存对象引用**：groupId/entityId 载入后经 SpaceGameComp 懒解析；BoardingMember 的 Pawn 用 `LookMode.Reference`（RimWorld 原生）。

## 5. 跳帮单位形态

同一基座（无 Map 纯物理 `SpaceEntity` + group + 成员池）的两个配置：

| | 单兵（EVA） | 奥德赛穿梭机 |
|---|---|---|
| 实体 | 无 Map SpaceEntity，2~5m | 无 Map SpaceEntity，50~100m |
| 推进 | `PropulsionData`（EVA 背包，小 ve/ṁ） | `PropulsionData`（强推进，独立机动） |
| 成员 | 1（BoardingMember） | N（乘客池） |
| 耐久 | **小型命中盒 + 少量 HP**：炮火可擦伤，小目标仍难命中 | part HP 装甲；**被击毁 = 乘客全灭** |
| 落点 | 各选一点（可分散多点突入） | 一个停机落点，全体乘客落附近 |

- 每单位**独立 group**（单兵罕见，N 个独立 group 的 `Parallel.ForEach` 积分开销可接受）。
- 接舷/降落判定 = **逐单位独立判定**（group 级），单兵与穿梭机同构。

### 5.1 穿梭机运输模式（2×2 矩阵）

穿梭机是通用运输工具，起降端有两种类型，交互各不同：

| 起端 ↘ 终端 | 普通 Map（地面） | 空间站口袋 Map（太空） |
|---|---|---|
| **普通 Map（地面）** | RW 原版穿梭机（原版已有） | 地面 → 太空（后置） |
| **空间站口袋 Map（太空）** | 太空 → 地面（后置） | 太空 → 太空（**第一版**） |

- **飞行段完全统一**：无 Map 3D 实体 + 移动目标点引导，与起降端类型无关。
- **普通 Map 端**：RW 原版穿梭机交互（地面降落选位，原版已有能力）。
- **口袋 Map 端**：本设计落点机制（可站立格 + 局部系偏移）。
- **第一版范围**：只实现**空间站口袋 ⇄ 空间站口袋**（含跳帮）。太空 ↔ 地面（涉及普通 Map 端）全部后置。
- **后置依赖**：普通 Map 在 3D 太空无现成锚点（RW 普通 Map 无经纬度概念，需先定行星表面方位映射方案），见决策 #16。

## 6. 士兵来源与成员迁移

```
母船内部 Map pawn（Spawn，玩家可操作）
  → 上船/出发：DeSpawn（未生成状态，RimWorld 原生支持长期存在）→ BoardingMember 持有引用
  → 飞行中：不存在于任何 Map，由 BoardingManager 持有
  → 降落：Spawn 到目标空间站 Map 落点（登舱口）→ RimWorld 原生战斗
  → 撤离：存活 pawn 回停靠点 → DeSpawn → 穿梭机升空
```

- **不销毁不重建 pawn**——装备/技能/名字全保留，"转抽象" = 未生成状态。
- 穿梭机被击毁 → 乘客全部杀死（陪葬，本期不做出生/待救援）。
- 空间站守军与入侵者 = RimWorld 原生 pawn 战斗，mod 只负责"转移 + 落点定位"。

## 7. 布置跳帮界面

- 起跳前**专门界面**（非查看模式内标点）：选参与单位 → 进入目标空间站内部 Map 视图 → 每单位选落点 → 确认出发。
- **落点 = 可站立格**：用 `cell.Walkable(map)` 过滤（隐藏 map 同样有格数据），高亮可行走格选区（参考 RW 降落选位交互：`MapInterface` 高亮 + `ClickedCell`）。
- 落点存为目标空间站局部系 3D 偏移（格子 → 局部系，现成 1:1 映射：Part 尺寸 = mapWidth×50m×mapHeight）。
- **UI 前置依赖**：出发前能打开/操作目标空间站内部 Map（Lite 已有 `EnterHiddenMap`，"跨船远程进入内部 Map"需确认/补入口）。

## 8. 飞行 / 降落机制

- **飞行目标 = 移动目标点**：`targetGroupPos + 落点偏移`（空间站在轨道上转，世界坐标每步重算）。~~复用现有"近距离接近引导"（`RegisterApproachGuidance`：动态重算目标点 + 终端消速）~~ → **实现改为 BoardingManager 专属持续引导**（见 §8.1，决策 #12 修正）。
- **降落判定**（替代原始"接触即跳帮"）：距移动落点 < 阈值 且 相对速度 < 阈值（低速，如 20m/s 级）→ 降落成功。
- 简化收益：触发语义从"碰到空间站外壳"变成"到达预定落点"，**边界清晰**：

```
对准落点 + 低速到达 → 降落成功（单兵 Spawn pawn / 穿梭机生成停靠 Thing 在选定格）
没对准 + 高速接触   → 船-船碰撞爆炸（失败：没对准就是撞船）
没对准 + 低速接触   → 动量交换/弹开（失败，可重新机动对准）
飞行中被炮火拦截    → 击毁（单兵死亡 / 穿梭机乘客全灭）
```

### 8.1 专属持续引导（实现，替代通用接近引导）

> 实测（2026-08-25 游戏日志）否定"复用接近引导"：通用引导 `UpdateRendezvousGuidance` 有 **30 tick 检查节流 + 60 tick burn 冷却**，单位大部分时间自由漂移；且 dist>3km 走**巡航 Lambert 转移**，对 3-8km 近距离算出 60+ m/s 大 dv，烧完轨道打乱 → relv 拉到 50 → 反弹 → 单位卡在 5km 巡航边缘反复振荡（20 分钟只收拢 2km）。另有目标站 OrbitKeeping 耗尽后的持续漂移（relv 10-16）。
>
> **BoardingManager 自驱持续引导**（每 2 tick = 物理步，在 `TickFlying` 内）：
> ```
> if (dist < 400 && relv < 15) → Land()          // 降落判定优先
> group.EndBurn()                                  // 清上一物理步残余 burn
> 收拢速度 = min(25 m/s, dist / 200)              // 远距离快进，接近时按 dist/τ 减速
> 期望速度 = 目标站速度 + 朝落点方向 × 收拢速度
> dv = 期望速度 - 当前速度
> if (|dv| > 0.5) group.StartBurn(dv)             // 缓释 dV，物理积分逐步施加
> ```
> - **目标站速度项**持续消速（含轨道保持漂移）→ relv 压到个位数；**朝落点项**按 `dist/200` 减速保证贴附前自然减速。
> - 移动落点每物理步重算：`targetGroupPos + entity.Position + 姿态旋转(落点偏移)`（`BoardingMath.WorldAimPoint`，纯函数可单测）。
> - 验证（游戏日志）：单兵 dist 2355→393m（~5 分钟，relv 2.2）降落；3 兵各自降落；穿梭机 dist 378m / relv 11 降落。

## 9. 碰撞拦截（CombatManager 分支）

- 跳帮单位 `IsCollidable = true` → 进 CombatGrid（`SyncAllShipsToGrid`）→ 射弹可命中（被拦截是玩法张力）。
- [CheckShipCollisions](../Combat/CombatManager.cs) 碰撞分派处加**识别分支**：一方是 BoardingManager 注册的单位且 `vRel < 接舷阈值` → 转降落判定（不弹飞、不爆炸）；高速 → 正常爆炸。
- 单兵命中盒：小型（比视觉略大，避免"永远擦过"无敌）+ 少量 HP（炮火可擦伤）。

## 10. 穿梭机生命周期（Map Thing ⇄ 3D 实体二象性）

```
停泊态（持久）                      飞行态（临时）
  Map 建筑 Thing                      BoardingUnit + 临时 SpaceEntity/group
  ShuttleId 字段                      ShuttleId（不变）
  乘客 pawn Spawn 在旁               乘客 pawn DeSpawn（成员引用）
     │ 起飞：上船(DeSpawn) → 销毁 Thing → 建飞行记录 + 3D 实体
     │      初始位置 = 停泊点对应 3D 坐标，速度 = 母船 group 速度（同步）
     ▼
  飞行：BoardingManager 驱动降落判定/任务；SpaceGameComp 驱动物理
     │ 降落：接舷判定通过 → 目标 Map 生成停靠 Thing（继承 ShuttleId）
     │      → 乘客下船(Spawn) → 销毁 3D 实体 → 注销飞行记录
     ▼
停泊态（目标 Map，持久）——ShuttleId 贯穿，撤离时用它再起飞
```

- **采用"飞行态临时实体"而非"3D 实体常驻休眠"**。关键依据：物理积分循环 `Parallel.ForEach(groups.Values)` **只检查 `IsMovable`、不检查 `IsActive`**（[SpaceGameComp.cs](../Base/Game/SpaceGameComp.cs)）——"停泊休眠"会让穿梭机 group 继续被积分，必须 `IsMovable=false` 才能跳过，且停泊态还得另做表示物。临时实体方案：停泊态 = 原生 Thing（序列化/渲染/交互全免费），飞行态 = BoardingUnit 承载 3D 状态快照（载入后重建），穿梭机数量稀少，临时创建 GC 成本可忽略。
- **序列化分工**：停泊态靠 Thing 原生序列化；飞行态靠 BoardingManager 序列化 `BoardingUnit`（完整 3D 状态快照 + 乘客引用 + 落点 + 目标），载入后重建临时实体。

## 11. 坐标映射

- 落点格子 → 目标空间站局部系偏移：`MapCoordMapper`（P1-3 已有设计）的格 → 局部米映射，1:1（Part 尺寸 = mapWidth×50m×mapHeight）。
- 世界目标点：`groupPos + entity.Position + 落点偏移`（含 `entity.Rotation` 姿态换算，与 F2 炮塔/命中链路同一套换算约定）。
