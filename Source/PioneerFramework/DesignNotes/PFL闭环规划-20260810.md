# 先驱框架Lite（PFL）闭环规划

> 创建日期：2026-08-10
> 定位：PFL 作为 DMS:NF（The Deadman's Switch: New Frontier）前置框架的完整闭环规划。
> 上下文：DMS:NF 是 The Deadman's Switch（基于 RimWorld 的 mod）的 submod；PFL 是 DMS:NF 的纯前置框架。
>
> **状态标记**：⬜ 待办 ｜ 🔵 进行中 ｜ 🟡 待验证 ｜ ✅ 已完成 ｜ ⚪ 已废弃
>
> **优先级**：P0 影响正确性 ｜ P1 架构/功能 ｜ P2 清理简化 ｜ P3 文档

---

## 1. 问题（Problem）

PFL 已完成 M2 裁剪（地月系 + 单 part 船 + 空间站对射底子），但想支撑 DMS:NF 把玩法闭环跑起来，还差四块：

1. **天地往返**：玩家现在没法从地面正经进太空（目前只能靠 `CompDebugShipSpawner` 调试部署），也没法从太空回地面。归档 MasterPlan 把「航天器发射系统」标为 Phase 1 遗漏项。**DMS:NF 额外约束**：发射的不是抽象飞船，而是 5 款型号火箭（CV-1、CV-3、CV-8、CV-10、CV-12），支持分级释放载荷、一级回收、定点返回。目前只有 CV-1、CV-3 两款可用，其余三款暂缓（半废弃状态）。燃料统一用「化合燃料（Chemfuel）」，但消耗量还没定——入轨、变轨耗的 dV 跟原版指标大概率对不上（低轨道/大气层内烧得更狠，以后还会引入更多燃料种类），具体数值待 DMS:NF 确认。PFL 这边先按接口预留，不锁死数值。
2. **对接**：`RendezvousPlanner` 能算交会，但没有对接状态机，也没有人员/物资转移 API。归档 MasterPlan 把「空间站对接系统」标为 Phase 2.2 待办。**DMS:NF 对得上的场景**：上行物资模块（DMSNF_UpboundCargoModulePayload）的「补给轨道设施」，本质就是对接 → 转移物资。
3. **补给循环**：已删 Engine/Propellant/Cargo 组件，`SpaceEntity.RemainingDeltaV` 没有补给路径（测试里硬编码 1e7）。F1 dV 补给、F2 炮塔弹药都依赖这套。**DMS:NF 额外约束**：dV 的燃料来源是 RW 化合燃料（Chemfuel），抽象 float dV 得能跟 RW 的物品类资源对上、能流转。
4. **轨道实体控制/敌对派系**：PFL 只有 `SpaceGameComp` 内部的群组生命周期，缺两样：一是地面统一查询/控制轨道实体的 API（DMS:NF 有「轨道设施控制终端」3×2 建筑）；二是敌对轨道派系的实体生成与事件钩子（DMS:NF 有反卫星袭击、敌方舰船破坏、舰队战、心灵低语轨道放大器）。

已登记的 F1-F3（见 [TODO.md](./TODO.md) §2）是本规划的子集，放进 Phase 1。

---

## 2. 愿景（Vision）

PFL 把「天地往返 + 轨道活动 + 对接 + 补给循环」做成一套完整的**机制层 + 调试级示例**，让 DMS:NF 能在上面搭正式内容（建筑 Def、资源配方、阵营剧情等）。PFL 自己不碰正式 Def/配方/经济数值——这是 PFL 和 DMS:NF 的分工线。

**P1 做完玩家就能端到端跑一遍**：地面造船 → 发射入轨 → 变轨机动 → 空间站对射 → 挨打反馈（Map 内爆炸）→ 着陆返回。这条线先用调试级补给打通，P2 再把资源流转正式化。

| 非目标 | 原因 |

| **DMS:NF 火箭型号 Def（CV-1、CV-3、CV-8、CV-10、CV-12 共 5 款，目前只有 CV-1、CV-3 可用，其余暂缓）、分级配置、回收策略、燃料消耗定额（数值待议）** | 内容层数值，归 DMS:NF；PFL 只给火箭分级/回收的 API 钩子 |

| **轨道设施控制终端 3×2 建筑 UI、军用打击框架交互、弹道导弹（EMP/HE/核弹头）再入表现** | 内容层 UI/数值/剧情，归 DMS:NF；PFL 提供再入路径 API 与敌对轨道实体注册机制 |

## 5. 架构（Architecture）

### 5.1 机制层划分

```
PFL 机制层
├── 天地往返层（SpaceLaunchService）          ← 新增
│   ├── 发射：地面 Map → SpaceEntity 创建 → 轨道注入
│   ├── 着陆：SpaceEntity → 地面 Map 生成 → 着陆
│   ├── 坐标映射：3D 实体坐标 ↔ Map 内坐标（与 F3 共享）
│   ├── 火箭分级钩子：IRocketStageHooks（StageSeparate/StageRecover/StageReturnHome）  ← DMS:NF 火箭型号接入点（CV-1/CV-3 可用，其余暂缓）
│   ├── 载荷承载与部署接口：IPayloadCarrier / IPayloadDeployer（DMS:NF 7 民用 + 4 军用载荷）
│   └── 再入路径 API：ReentryTrajectory（供 DMS:NF 弹道导弹/返回舱复用）
├── 轨道活动层（已有）
│   ├── 轨道物理（NBody/Maneuver/Lambert/Rendezvous）
│   ├── 战斗（CombatManager/ProjectileInstance/TargetingSystem）
│   ├── F2 炮塔桥接（CombatManager.FireFromMapBuilding）  ← 新增
│   ├── 轨道实体查询 API：OrbitalEntityCatalog（按 defName/类型/阵营枚举+状态查询）← DMS:NF 轨道设施控制终端接入点
│   └── 敌对轨道实体注册层：HostileOrbitalRegistry + IOrbitalIncidentEvent（反卫星袭击/敌方舰船/轨道放大器）
├── 对接层（DockingSystem）                    ← 新增（P2）
│   ├── 交会判定（复用 RendezvousPlanner）
│   ├── 对接状态机（Docked 状态）
│   ├── 转移 API（人员/物资）
│   └── 匹配 DMS:NF 场景：上行物资模块 = 对接 → Transfer(物资) → 解对接
└── 补给循环层（ResourceComponentData 基类）   ← 新增（P2 正式化）
    ├── 通用资源组件基类（DMS:NF 继承扩展）
    ├── 流转 API（Map 资源 ↔ 太空使用）
    ├── 燃料映射层：ChemfuelToDeltaVMapper（RW ThingDef Chemfuel ↔ float dV 定量换算，消耗指标待 DMS:NF 定）← DMS:NF 燃料接入
    └── dV 补给正式化（替代 P1 调试补给）
```

### 5.2 与已有代码的衔接

| 新机制 | 衔接点 | 复用/扩展方式 |
|--------|--------|---------------|
| 发射系统 | `SpaceMapGenerator.CreateStationEntity` | 复用单 part 船创建逻辑，加「地面入口」 |
| 着陆系统 | `MoonSurfaceMapGeneration` | 复用地表生成，加「飞船着陆映射」 |
| F3 命中爆炸 | `CombatManager.CheckSegmentGroupHit` 的 `hitEntryPoint` | 新增 3D→Map 坐标映射 |
| 对接 | `RendezvousPlanner` | 复用交会算法，加对接状态机 |
| 资源组件 | `PartComponentData` 基类 | 新增 `ResourceComponentData` 抽象子类 |
| dV 补给 | `SpaceEntity.RefillDeltaV` | P1 调试入口，P2 资源流转正式化 |
| 炮塔开火 | `CombatManager.FireWeapon` | 新增 `FireFromMapBuilding` 方法 |
| 火箭分级钩子 | `SpaceEntity` 生命周期（初始化/推进/销毁） | 新增 `IRocketStageHooks` 接口，`SpaceLaunchService` 在关键节点回调；DMS:NF 各型号（当前 CV-1/CV-3 可用）实现此接口 |
| 载荷承载/部署 | `SpaceEntity` 附加子实体 / 组群（Group） | 新增 `IPayloadCarrier` / `IPayloadDeployer`；部署时 `CreateStationEntity` 创建对应轨道卫星/模块实体 |
| 再入路径 API | 坐标映射（P1-3）+ `SpaceLaunchService` 着陆 | 新增 `ReentryTrajectory`（位置→时间→预计落点），供 DMS:NF 弹道导弹/返回舱计算再入窗口 |
| 燃料映射 | `SpaceEntity.RefillDeltaV` + RW ThingDef `Chemfuel` | 新增 `ChemfuelToDeltaVMapper`：输入 `ThingDef.Chemfuel` 数量 → 输出 dV 值；换算定额由 DMS:NF 配（初稿 1 格=2 单位，待议，且低轨/大气层内消耗会更大） |
| 轨道实体查询 | `SpaceGameComp` 内部 Groups/Entities | 新增 `OrbitalEntityCatalog`：枚举/按 defName 查/按阵营查/按类型查 → DMS:NF 轨道设施控制终端调用 |
| 敌对轨道实体/事件 | `CombatManager` 目标选择 + `SpaceGameComp` 生命周期 | 新增 `HostileOrbitalRegistry`（注册敌对实体 def+生成时机）+ `IOrbitalIncidentEvent`（反卫星袭击/敌方舰船/轨道放大器触发钩子） |

### 5.3 资源模型（组件基类 + DMS:NF 继承扩展）

```
PartComponentData（已有基类）
└── ResourceComponentData（新增，抽象）        ← P2
    ├── DebugResourceComp（PFL 调试示例）       ← P1 临时用，P2 替代
    ├── [DMS:NF] DMS_FuelComp                  ← DMS:NF 继承
    ├── [DMS:NF] DMS_AmmoComp                  ← DMS:NF 继承
    └── [DMS:NF] DMS_CrewComp                  ← DMS:NF 继承

燃料 ↔ dV 映射（平行于组件链）：           ← P2
  ChemfuelToDeltaVMapper
  ├── 输入：RW Thing.Chemfuel 数量（stackCount）
  ├── 换算：燃料数量 → 定量 dV（定额由 DMS:NF 配置；初稿 1 格=2 单位仅作参考，消耗指标待定）
  └── 输出：调用 SpaceEntity.RefillDeltaV(deltaV)
```

- PFL 提供 `ResourceComponentData` 抽象基类（定义 `Amount`/`Capacity`/`TransferTo` 等通用接口）
- PFL 提供 `DebugResourceComp`（调试补给示例，P1 临时用）
- PFL 提供 `ChemfuelToDeltaVMapper`（燃料数量 → float dV 的定量换算，接 RefillDeltaV；换算系数不写死）
- DMS:NF 继承定义具体资源类型，注册到 `ComponentRegistry`；火箭燃料走 `ChemfuelToDeltaVMapper` 路径

## 6. 阶段划分（Phase Breakdown）

### Phase 1：核心闭环（天地往返最小 + F1-F3）

**目标**：打通「地面造船→发射→变轨→对射→挨打反馈→着陆返回」这条线。顺手把 P2/P3 要用的 API 形状（接口签名、回调时机）冻结下来，DMS:NF 那边可以并行开干。

| # | 优先级 | 任务 | 机制 | 衔接 |
|---|--------|------|------|------|
| P1-1 | P0 | 发射系统（瞬间生成版） | `SpaceLaunchService.LaunchFromGround(groundMap, launchPos, shipDef)` → 创建 `SpaceEntity` + 注入轨道 | 复用 `CreateStationEntity` |
| P1-2 | P0 | 着陆系统 | `SpaceLaunchService.LandToGround(entity, targetTile)` → 生成/加载地表 Map + 飞船着陆 | 复用 `MoonSurfaceMapGeneration` |
| P1-3 | P0 | 坐标映射基础设施 | 3D 实体坐标 ↔ part 关联 Map 内坐标映射（F3 与着陆共享） | 新增 `MapCoordMapper` |
| P1-4 | P0 | F1 dV 补给（调试级） | 调试按钮 `RefillDeltaV`（方法已有，补调试入口） | `SpaceEntity.RefillDeltaV` |
| P1-5 | P0 | F2 Map 炮塔开火 | `CombatManager.FireFromMapBuilding(groupId, weaponDef, spawnPos, targetPos)` + `BuildingComp` 基类 | 复用 `FireWeapon` 语义 |
| P1-6 | P0 | F3 命中→Map 爆炸 | `CheckSegmentGroupHit` 命中后：`hitEntryPoint` → `MapCoordMapper` → Map 内生成爆炸 | 复用 P1-3 |
| P1-7 | P1 | 调试入口整合 | `CompDebugShipSpawner` 扩展：发射/着陆/dV 补给/炮塔测试 | 扩展现有调试组件 |
| P1-8 | P1 | 火箭分级钩子**接口**（无实现） | 定义 `IRocketStageHooks`：`StageSeparate(stageIndex)`/`StageRecover(stageIndex, recoverPos)`/`StageReturnHome(stageIndex, homeTile)`；发射/推进/销毁节点回调空实现 | 供 DMS:NF 各型号（CV-1/CV-3）后续接入，P3 正式化实现 |
| P1-9 | P1 | 载荷承载/**部署接口**（无实现） | 定义 `IPayloadCarrier`（承载列表/容量）+ `IPayloadDeployer`（`Deploy(payloadDef, targetOrbit) → SpaceEntity`）；调试入口返回占位实体 | 供 DMS:NF 7 民用 + 4 军用载荷后续接入 |

**P1 验收**：进游戏，调试按钮触发：地面发射 → 变轨 → 对射 → 命中后 Map 内爆炸 → 着陆返回，全程不报错。P1-8/9 的接口能被 DMS:NF 空实现一把编过。

### Phase 2：对接 + 补给循环正式化

**目标**：把资源流转正式化（替掉 P1 的调试补给），加上对接转移。DMS:NF 依赖的查询 API、燃料映射、再入/敌对事件的最小实现也在这阶段做。

| # | 优先级 | 任务 | 机制 | 衔接 |
|---|--------|------|------|------|
| P2-1 | P0 | 通用资源组件基类 | `ResourceComponentData : PartComponentData`（抽象，`Amount`/`Capacity`/`TransferTo`） | 继承已有基类 |
| P2-2 | P0 | dV 补给正式化 | Map 资源（`ResourceComponentData`）→ 流转到 `SpaceEntity.RemainingDeltaV`，替代 P1-4 调试按钮 | 替代 P1-4 |
| P2-3 | P1 | 对接状态机 | `DockingSystem`：交会判定（复用 `RendezvousPlanner`）→ Docked 状态 → 解对接 | 新增状态机 |
| P2-4 | P1 | 转移 API | 人员/物资在对接实体间转移（`DockingSystem.Transfer(from, to, resource)`） | 依赖 P2-1 |
| P2-5 | P2 | 调试示例 | `DebugResourceComp`（PFL 调试补给示例）+ 对接调试按钮 | P2-1 的示例实现 |
| P2-6 | P1 | **燃料映射实现** | `ChemfuelToDeltaVMapper`：RW `Thing.Chemfuel` stackCount → 定量 dV → `RefillDeltaV`；换算系数做成可配置，初稿 1 格=2 单位仅供参考（指标待 DMS:NF 定） | 依赖 P2-2 |
| P2-7 | P1 | **轨道实体查询 API 实现** | `OrbitalEntityCatalog`：枚举/按 defName/类型/阵营/轨道参数查询 `SpaceEntity`；返回快照对象（含位置/速度/健康/剩余 dV） | `SpaceGameComp`  Groups/Entities 只读投影 |
| P2-8 | P1 | **再入路径 API 最小实现** | `ReentryTrajectory.Calculate(entity, targetPos)` → 返回预计落点 + 时间；供 DMS:NF 弹道导弹/返回舱调用 | 复用 P1-3 坐标映射 |
| P2-9 | P1 | **敌对轨道实体注册 + 事件钩子（最小实现）** | `HostileOrbitalRegistry.Register(factionDef, entityDef, triggerConditions)`；`IOrbitalIncidentEvent.Fire(incidentDef)` → 生成 `SpaceEntity` 加入战斗系统目标选择 | 接 `CombatManager` 目标池 |

**P2 验收**：对接状态机能正常进出 Docked；资源组件能流转补给 dV；调试资源组件可以替代 P1 的硬编码补给。燃料能定量转 dV；`OrbitalEntityCatalog` 查询结果正确；敌对轨道注册实体能被战斗系统锁定。

## 7. HOTL 契约

### 7.1 Intent Contract

```yaml
intent: PFL 提供天地往返+轨道活动+对接+补给循环的完整机制层，支撑 DMS:NF 玩法闭环
constraints:
  - 不破坏 M2 裁剪架构（单 part 化/无装配/无 Morton）
  - 不引入 full 版装配/跨行星系/地表探索
  - PFL 不含正式 Def/配方/经济数值（归 DMS:NF）
  - 资源类型可由 DMS:NF 继承扩展（不硬编码枚举）
```
