## 2. 裁定（后端，定案，不再讨论）

**R1 · 一个入口。**
```csharp
internal enum GroupBirthKind { Instantiated, Continuation, Emitted }
public void RegisterGroup(SpaceEntityGroup group, GroupBirthKind kind, SpaceEntityGroup? source = null);
```
**删除单参重载**。20+ 调用点由编译器逼着表态——这是"统一性"最便宜的实现方式。

**R2 · 三个种类，语义只有这三行。**

| kind | 谁 | 状态来源 | 入 `groups` | 上屏 | 对账 |
|---|---|---|---|---|---|
| `Instantiated` | 发射、空间站、调试、AI 遭遇 | 自持（已提交时刻） | 立即 | 立即 | 无 |
| `Continuation` | 抛级、载荷舱释放 | 由 `source` 的已提交态切出 | 立即 | 立即 | 无 |
| `Emitted` | 导弹、弹丸（从运动平台发射） | 母体局部系偏移 + 相对速度 | **对账后** | 对账后 | 有 |

**R3 · `Emitted` 不进 `groups`，进 `pendingBirths`。**
理由：正确性靠构造，不靠"记得在每个消费者里加过滤"。`groups` 永远只含状态已提交的体 ⇒ 碰撞/探测/制导/AVM **一行都不用改**，也不存在"下一处新消费者又漏了"。
代价：存档要跟着改——`pendingBirths` 单独 Scribe，`RestorePhysicsClockAnchor` 从它重算 pending 计数（语义不变，只换容器）。存档格式变化必须带向后兼容读取。

**R4 · 消亡对称。**
`UnregisterGroup` / `DestroyGroup` 同样调 `MarkPhysicsEvent()`；批次内（`IsPhysicsBatchActive`）延后到批次结束，与出生侧同一 guard。
不变量：**任何成员变化（生或死）= 一个提交边界**。

**R5 · 对账有限时。**
最多等 **2 个物理区间**（1× 档 4 s / 8× 档 32 s / 1÷60 档 0.067 s）；超时 → `DestroyGroup` + `PhysicsLogWarning`（带 groupId、birthTick、sourceId）。不允许"永久隐形但仍在物理里"。

**R6 · 抛级与载荷释放是 `Continuation`，明确不套对账。**
子体与母体来自同一份提交态（质量/位置/速度是切分恒等式），没有外部参照要等。给它们套 `Emitted` 会白等一整个区间并制造一帧空窗 ⇒ **禁止**。

**R7 · 字段契约按"是否改变物理状态"分类。**
我们的新字段进 `CelestialShipInputCopy.g.cs` 时二选一：
- 改变物理状态（储能、温度、装药/工质、装甲、部件集、控制核心状态…）⇒ **复制 + 发布**；
- 纯派生/可重建（各类缓存、聚合戳、调试计数）⇒ **显式排除条目 + 一句理由**。
分类由 `CelestialShipFieldCoverageTests` 的失败清单驱动，不靠人肉记。

## 3. 判据（可执行，收口时逐条验）

1. **抛级零位移**：分离同一物理步内，子组 `positionSystem` 与"母组按级号切分算出的位姿"**逐位相等**（0 误差），且当帧 `GroupIsVisibleAt == true`。
2. **Emitted 不进视图**：对账前断言 `pendingBirths.Count > 0 && groups.ContainsKey(id) == false`，且 `CollectPartContacts` 的候选计数不含它；对账后位置复原误差 < 1e-6。
3. **拓扑对称**：分离帧与销毁帧各多一个 `PhysicsTimeLine.Epochs` 项；`Commit` 不跨 epoch（复用 `PhysicsTimeLine.Commit` 的既有断言）。
4. **存档往返**：pending 组重载后仍 pending、对账 tick 不变；已提交组不受影响；旧档（无 `pendingBirths` 字段）能正常读。
5. **编译器门**：全仓 `RegisterGroup(` 只剩入口 1 处（+ `pendingBirths` 对账处），单参重载不存在。
