# 飞船部件数据结构体系化设计

> 日期：2026-08-05
> 状态：设计讨论已收敛，待细化实施
> 目标：把飞船部件从「形状枚举 + 平铺字段」重构为「无反射组件组合模型」，为完整游戏内容（反应堆 / 护盾 / 散热板 / 传感器等新部件角色）铺路
> 已确认决策：组件组合模型（B）· 无反射（string + 显式注册表）· 纯数据 + 事件回调 · Def 预置 + 模板覆盖 · 设计层参数落进实例 · 空间换时间
> 主题 A 决策（2026-08-05）：模板**引用 Def + 覆盖**（通用属性跟随 Def）· **全量快照**覆盖（Def 预置 = 新建模板初始值，模板固化）· **允许多实例叠加**（同 TypeId 多组件）
> 主题 B 决策（2026-08-05）：SpacePart 组件存储 = **强类型字段 + 扩展逃生口**（框架组件走强类型 List，mod 组件走 TypeId+blob 扩展容器，对外统一 `AddComponent` / `EnumerateComponents` 语义）· 注册表 = **分散注册**（组件类自身 `[StaticConstructorOnStartup]` 注册）
> 主题 C 决策（2026-08-05）：几何形状**先只实现 Cube**（几何注册表起步注册 Cube；SphericalCorner 等按需后加——注意现有 SphericalCorner 部件/模板的兼容读取）· 编辑 UI = **组件自绘编辑区**（组件数据类实现可选 `IShipPartEditUI` 接口）
> 主题 D 决策（2026-08-05，stats 体系）：聚合模型 = **ShipStats struct**（组件实现 `AccumulateStats(ref ShipStats)`，双级缓存：部件级 cachedStats + 实体级 shipStats）· 能耗闭环**先聚合后闭环**（供电/过温惩罚后续接）· 燃耗真实化（dV→推进剂→质量动态）**暂不接入**

## 一、背景与动机

### 1.1 现状：四层数据流

```
设计层（用户蓝图）   ShipPartTemplate(.part) → Ship3D(.ship) → ShipPartInstance（布局实例）
内容层（Def 原型）   ShipPartDef（ShipPartDefs 注册表，7 个默认）+ WeaponDef + RoomTypeDef
运行时层（存档）     SpacePart（SpaceEntity.parts，IExposable）
消费方               CombatManager / CombatGrid / 质量计算 / 3D 视图
```

关键链路 `Ship3D.ToSpaceParts()` 把蓝图实例翻译成 SpacePart 时，只保留 `defName`（由 shapeType 映射），template 里的引擎 / 储罐 / 货舱参数**全部丢失**。

### 1.2 五个病灶（按体系化紧迫度排序）

| # | 病灶 | 现状位置 |
|---|------|----------|
| 1 | **形状枚举身兼两职**：`ShipPartShape` 同时装几何（Cube / SphericalCorner）与功能（Engine / Weapon / Tank / CargoHold / RoomModule），全代码 21 处 switch 散打；功能判定靠形状巧合（`shapeType == CargoHold` 决定质量加成、`shapeType == RoomModule` 决定舱室判定） | ShipPartDef.cs / SpacePart.cs L56 / L79 |
| 2 | **设计层参数进不了物理**：exhaustVelocity / massFlowRate / tankDryMass / tankWetMass / cargoCapacity 只在设计窗口与调试摘要被读，SpacePart 无对应字段；运行时 dV 仍是 `RemainingDeltaV` 裸数字 | ShipPartInstance.cs / SpacePart.cs |
| 3 | **双轨定义**：ShipPartDef 与 ShipPartTemplate 字段大面积重叠，template 本质是"每个用户一份的 Def"，一方改另一方不知，运行时只认 Def | ShipPartDef.cs / ShipPartTemplate.cs |
| 4 | **质量计算硬编码**：`SpacePart.Mass` 里 `if CargoHold m += cargoCapacity`，加新角色就要来加分支（违反开放-封闭） | SpacePart.cs L50-L60 |
| 5 | **SpacePart 字段平铺**：武器挂载 / 舱室参数全部平铺，MasterPlan 的 stats 待办（thrust / powerGen / heatDissipation）一旦做还得继续平铺 | SpacePart.cs |

## 二、目标架构

### 2.1 四层数据流（重构后）

```
内容层   ShipPartDef        几何(纯形状) + 通用属性(massBase / hpMax / armor) + 预置组件集
设计层   ShipPartTemplate   几何覆盖(customBounds) + 组件覆盖(增删 / 调参)
运行时   SpacePart          几何 + 通用 + 组件实例数据(序列化落盘) + 热缓存[Unsaved]
消费方   Combat / 物理 / UI  只读热缓存，不遍历组件
```

### 2.2 职责划分

| 层 | 持有组件数据 | 作用 |
|----|-------------|------|
| ShipPartDef（原型） | 预置组件集（如"标准引擎"预置一个 Engine 组件） | 内容层默认，可批量定义部件类型 |
| ShipPartTemplate（用户设计） | 用户调整后的组件参数 | 设计层覆盖（覆盖参数 / 增删组件） |
| SpacePart（运行时） | 实例化后的组件数据（**序列化落盘**） | 运行时真相 |

继承链显式化：**实例继承模板，模板继承原型**，覆盖点明确。`ToSpaceParts()` 将模板组件数据拷贝进 SpacePart，用户调教的引擎参数真实进入物理。

## 三、组件体系设计

### 3.1 基类：PartComponentData

- 纯数据（IExposable 手写序列化）
- `TypeId`（string，注册表键）
- 事件回调（低频，不进 tick）：`OnAttached` / `OnDamaged` / `OnDestroyed` / `PostLoad`

### 3.2 组件子类清单

| 组件子类 | 承载数据 | 对应现状平铺字段 |
|----------|----------|-------------------|
| `EngineComponentData` | exhaustVelocity, massFlowRate | （当前未进运行时） |
| `PropellantTankComponentData` | dryMass, wetMass | 同上 |
| `CargoComponentData` | capacity | cargoCapacity |
| `WeaponMountComponentData` | weaponDefName, turretRotationSpeed, trackingArc, muzzleOffset | 4 个武器挂载字段 |
| `RoomComponentData` | roomTypeDefName, mapSize | 3 个舱室字段 |
| 未来 | Reactor / Shield / Radiator / Sensor / ... | — |

### 3.3 注册表（无反射）

静态 `Dictionary<string, Func<PartComponentData>>`，每个组件类在静态构造器显式注册（与 ShipPartDefs 同模式）。实例化 / 反序列化 / mod 扩展都走这张表，**只在低频路径调用**（建船 / 读档 / 改部件）。

- 支持外部 mod 注册自定义组件（注册回调，不改框架代码）
- 热路径（战斗 / 物理）完全不碰注册表与组件遍历

## 四、空间换时间性能策略

### 4.1 热路径 vs 变更路径

| 路径 | 读什么 | 成本 |
|------|--------|------|
| 热路径（碰撞 / 网格 / 质量 / dV） | `cachedMass` / `cachedTotalThrust` / `cachedTotalPropellant` / 武器引用 | 一个 float 读取 |
| 变更路径（放置 / 损坏 / 读档 / 装货） | 遍历组件 → 重算聚合 → 版本号置脏 | 低频，每船 <30 部件，百来次乘法 |

### 4.2 热缓存清单（SpacePart [Unsaved] 字段）

- `cachedMass`（替代 SpacePart.Mass 的 if-else + 特判）
- `cachedTotalThrust` / `cachedTotalPropellant`（为 dV / 燃烧系统铺路）
- 武器实例引用（现有 `weaponInstance`）

新角色（反应堆增重、护盾增重）自动计入聚合，无需改代码——病灶 4 根治。

### 4.3 版本号脏标记

复用战斗优化已用熟的「版本号脏标记」模式：组件变更 → `InvalidateStats()`（置脏 + 版本号自增），聚合缓存只在此刻重算。

> 反面教材对照：`UpdateWeapons` 每 2 tick 全量重建武器列表，是"该变更驱动却按节拍驱动"的教训。组件模型的 `OnDamaged / OnDestroyed` 回调天然把变更点收口，缓存失效一处集中。

## 九、stats 体系与新部件角色规划（主题 D，2026-08-05）

### 9.1 ShipStats 聚合模型

组件携带**语义字段**（物理直觉），聚合时折算为统一单位：

```
ShipStats（struct）
  ├── mass / thrust / powerGen / powerDraw / heatDissipation
  ├── propellant / powerStorage / shieldCapacity / sensorRange
  └── ...
组件实现接口：void AccumulateStats(ref ShipStats s)
```

**双级缓存（空间换时间）**：
- 部件级 `cachedStats`：组件变更时重算（遍历部件内组件）
- 实体级 `shipStats`：部件集变更时重算（遍历部件）
- 热路径只读最终 float，两级都只在低频变更时置脏

加新 stat = ShipStats 加字段 + 组件 Accumulate 加一行；加新组件 = 实现 AccumulateStats 自动生效。无 if-else 特判。

### 9.2 新部件角色清单（内容路线图）

| 组件 | 产出 | 消耗 | 聚合贡献 |
|------|------|------|----------|
| EngineComponentData | 推力 | 推进剂（电推则耗电） | thrust↑, powerDraw↑, propellant↓ |
| PropellantTankComponentData | 推进剂存储 | — | propellant↑, mass↑（湿重） |
| ReactorComponentData | 电力 | 燃料/推进剂 | powerGen↑, propellant↓, mass↑ |
| BatteryComponentData | 电力存储 | — | powerStorage↑ |
| WeaponMountComponentData | 伤害 | 电力 | powerDraw↑ |
| ShieldComponentData | 防护 | 电力 | powerDraw↑, shieldCapacity↑ |
| RadiatorComponentData | 散热 | — | heatDissipation↑ |
| SensorComponentData | 探测 | 电力（小） | powerDraw↑, sensorRange↑ |
| CargoHoldComponentData | 货运 | — | mass↑（载重）, capacity↑ |

### 9.3 能耗闭环（战略深度，后续阶段）

三轴闭环：**供电**（Reactor → 电网 → 引擎/武器/护盾/传感器）· **燃料**（PropellantTank → 引擎/反应堆）· **热**（产热 → Radiator 散热，散热不足 → 过温惩罚）。

简化策略：功率平衡秒级刷新（60 tick）按优先级分配（推进 > 护盾 > 武器 > 传感器）；热不做传导网络，只做"总产热 vs 总散热"过温惩罚；推进剂先聚合总量，逐罐模拟后续再说。

### 9.4 燃耗真实化路径（分步，暂缓）

1. **（已完成决策）** ShipStats 聚合到位——纯数值流
2. dV 消耗换算燃耗 `Δm = Δv·m/ve`（BurnSystem / 轨道保持接入），质量动态 → 火箭方程
3. 供电不足 → 武器停火 / 引擎降推（闭环接入战斗）

## 十、ShipStats 字段集 v0.1（2026-08-05）

### 10.1 字段清单

| 字段 | 单位 | 来源组件 | 折算规则 | 消费方 |
|------|------|----------|----------|--------|
| `mass` | kg | 全部 | `massBase` + Σ组件贡献 | 物理/碰撞/推进（已接入） |
| `thrust` | N | Engine | Σ(ve × ṁ) | 推进（燃耗阶段） |
| `powerGen` | W | Reactor | Σ | 供电闭环 |
| `powerDraw` | W | Engine/Weapon/Shield/Sensor | Σ标称功耗 | 供电闭环 |
| `heatProduction` | W | Reactor/Weapon/Engine | Σ | 过温闭环 |
| `heatDissipation` | W | Radiator | Σ | 过温闭环 |
| `propellant` | kg | PropellantTank | Σ(wet − dry) | 燃耗阶段 |
| `powerStorage` | J | Battery | Σ | 供电闭环 |
| `shieldCapacity` | 点 | Shield | Σ | 战斗 |
| `sensorRange` | m | Sensor | **待定**（max / Σ） | 战斗 AI |
| `cargoCapacity` | kg | CargoHold | Σ | 货运 |

### 10.2 折算规则与注意事项

- **`heatProduction` 成对补入**：9.3 闭环原只列散热端，产热端必须成对（Reactor 持续产热、Weapon 开火产热、Engine 燃烧产热），否则"散热不足 → 过温"无从判定。
- **`powerDraw` 存"满负荷标称功耗"**：武器仅开火时拉电，引擎仅燃烧时拉电；闭环阶段按活动状态折算实际负载，聚合阶段先存标称。
- **`mass` 新口径**：结构质量 `massBase` + 各组件自重，替代现有 `def.mass + CargoHold 特判`。

### 10.3 待定项（暂停讨论，下次续）

- [ ] `sensorRange` 聚合语义：取 max（物理直觉：探测 = 最远能看多远）vs 求和（堆叠探测距离）
- [ ] 储罐对 `mass` 的贡献口径：湿重满值（推进剂静态满箱，接燃耗时 mass 随 propellant 动态，衔接 9.4 第 2 步）vs 干重
