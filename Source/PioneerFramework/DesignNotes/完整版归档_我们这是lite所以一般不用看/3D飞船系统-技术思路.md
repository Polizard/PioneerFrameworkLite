# 3D 飞船系统 — 技术思路概要

## 一句话目标

在 RimWorld (Unity) Mod 中实现一个 **Gizmo 触发的弹窗式 3D 飞船装配/查看系统**，玩家在 3D 空间中组装引擎、散热板、反应堆、舱室等部件，每个舱室部件永久对应一张 RW 2D 地图，双方实时双向同步（"扎小人"）。

---

## 设计简化（重要）

这些简化是整套方案可行的关键前提：

1. **永不损坏的框架** — 飞船有一个"骨架"框架，部件挂在上面。部件可以被打烂，但框架不毁，船不会四分五裂。无需处理级联解体。
2. **二阶段建造流程** — 玩家先在 3D 视口中自由摆放部件（无惩罚），满意后按下"生成框架"按钮，系统根据当前布局锁定框架质量。生成后框架锁死，部件损坏不影响。
3. **宽松的建造逻辑** — 不需要 KSP 式的节点匹配。**空间允许即可**，部件之间不重叠就放得下。
4. **形状** — 棱锥体、棱柱体、角球体、圆柱体、球体。（Unity 中球体本质上是高面数角球体，圆柱体是高面数棱柱体。）
5. **自由朝向** — 每个部件的旋转四元数任意指定，后果自负。

## 核心数据结构

### 关于"框架"

框架**不存在于游戏世界中**——它不是玩家需要建造或定义的物体。框架的质量和外形**完全从部件布局派生**，由运行时实时计算得出。见下方「紧凑度 → 框架质量」章节。

### 部件定义

```
ShipPartDef (XML + C#):
  - mesh: "Parts/Engine_NuclearFusion.fbx"
  - shapeType: Prism | Pyramid | SphericalCorner | Cylinder | Sphere
  - bounds: (3, 2, 5)              # 轴对齐包围盒尺寸（基础尺寸，随旋转变化）
  - mass: 2.5                      # 部件自身质量
  - stats: [thrust, powerGen, heatDissipation, ...]

  - isRoomModule: true              # 是否是舱室
  - roomMapSize: (15, 15)           # 对应的 RW Map 尺寸
  - roomMapDef: "Map_EngineRoom"    # 地图模板
```

### 运行时实例

```
Ship3D (WorldObject):
  - parts: List<ShipPartInstance>   # 所有已装配的部件
  - roomMaps: Dict<PartID, Map>     # 舱室部件 → Map 的映射

ShipPartInstance:
  - def: ShipPartDef
  - position: (x, y, z)            # 相对于飞船原点的位置
  - rotation: (qx, qy, qz, qw)    # 四元数，任意朝向
  - hp: float                      # 当前耐久
  - roomMap: Map (if isRoomModule) # 对应的 RW 2D 地图
```

### 装配验证（空间允许检测）

```
bool CanPlace(Ship3D ship, ShipPartInstance newPart):
  // 1. 获取部件的 OBB（有向包围盒，由 bounds × rotation 计算）
  obb = ComputeOBB(newPart.bounds, newPart.position, newPart.rotation)

  // 2. 检查是否与已有部件重叠
  for each existingPart in ship.parts:
    if OBB_Overlap(obb, ComputeOBB(existingPart)):
      return false

  return true
```

## 紧凑度 → 框架质量

框架质量由部件布局实时计算，采用**转动惯量（跨度²）**的思想：

```
float ComputeFrameMass(List<ShipPartInstance> parts):
    // 1. 计算质心（所有部件位置的平均值）
    centroid = Σ(part.position) / parts.Count

    // 2. 每个部件对质量的贡献 = 距离质心距离² × 系数
    totalSpan = 0
    for each part in parts:
        distSq = (part.position - centroid).sqrMagnitude
        totalSpan += distSq

    // 3. 框架质量
     return totalSpan × frameMassCoefficient
 ```

 **效果**：
 - 部件紧密堆在一起 → 跨度²小 → 框架质量小 → 推重比高 ✓
 - 部件散开放 → 每个部件都离质心远 → 距离→平方增长 → 框架质量大 → 推重比低 ✗
 - O(n) 一次遍历，几行代码，几乎零开销

 **计算时机**：框架质量**仅在玩家主动按下"生成框架"按钮时计算一次**。在此之前是自由装配阶段，部件随意摆放无惩罚。计算后框架质量锁定，部件损坏不影响该数值。

## 关于形状的技术说明

在 Unity 中：

| 形状 | Mesh 生成方式 | 碰撞检测用 | 面数 |
|------|-------------|-----------|------|
| 棱锥体 | 自定义 Mesh（4-6 三角面） | OBB 近似 | 低 |
| 棱柱体 | 自定义 Mesh（三角/六角柱） | OBB 近似 | 中 |
| 角球体 | 程序化生成 1/8 球面 | OBB 近似 | 可控 |
| 圆柱体 | 内置 Cylinder（默认 48 段） | OBB 近似 | 中 |
| 球体 | 内置 Sphere（经线 20 段） | OBB 近似 | 中 |

**关键**：碰撞检测统一用 OBB 近似即可，细碎形状差异只体现在视觉 Mesh 上。这显著简化了「空间允许」的检测逻辑。

## 实现路线（建议 MVP）

### Phase 0：技术预研（1-2 天）
- 确认 RW 使用的 Unity 具体版本
- 验证 `new Camera + RenderTexture` 在 RW Mod 上下文中能否正常工作
- 验证 RW Window 中 GUI.DrawTexture 渲染 RenderTexture

### Phase 1：框架 + 一个方块（骨架验证）
- 定义一个 ShipFrameworkDef（10x6x8 的 Box）
- 在 3D 弹窗中显示这个框架的线框
- 在框架内放一个方块部件，验证「空间允许」检测
- 实现鼠标 Orbit 控制（旋转/平移/缩放）

### Phase 2：一个舱室部件 + 对应 Map（扎小人闭环）
- 一个部件标记 isRoomModule
- 放置时创建对应的 10x10 RW Map
- **双向同步**：3D 部件掉 HP → Map 出现破损；Map 内修复 → 3D 状态恢复

### Phase 3：多部件 + 多种形状
- 棱锥/棱柱/角球/圆柱/球体 的 Mesh 生成
- 任意朝向放置
- 部件列表 UI（选中、删除、查看属性）

### Phase 4：完整游戏集成
- 3D 太空战斗（远程命中 → 部件损伤）
- 接舷战（展开为 Map 内战斗）
- 多 Map 优化（无人 Map 降频）
- 存档/读档

## 不影响现有系统

- 3D 系统完全**独立**于现有 PW 的轨道规划、战斗结算、物资管理
- 现有代码（OrbitTransferPlanner 等）不需要改动
- 装配产生的数据可序列化为标准 RW savegame 的一部分

---

## 风险和注意事项

- **Unity 版本兼容**：必须先确认 RW 的 Unity 版本
- **3D 模型来源**：棱锥/棱柱/角球体需要程序化生成或 ProBuilder
- **多 Map 性能**：舱室数量多时需降频 Tick 机制
- **存档兼容**：3D 飞船数据需序列化到 RW 存档
- **UI/UX 一致性**：3D 弹窗需要融入 RimWorld 的视觉风格
