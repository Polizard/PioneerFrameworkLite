### 0.2 实现期新增决策（设计稿未写、编码时定）

|---|---|---|---|
| I1 | 锚点 group 的 `IsActive` | **false**（设计只写了 `IsMovable`/`IsCollidable` = false） | 全库「遍历 groups 的飞船消费方」（渲染 / 索敌 / 目标列表 / 战斗网格 / 交会候选，约 30 处）几乎都以 `IsActive` 为首道门——置 false 一次覆盖全部站点，无需逐处补 `IsSurfaceAnchor`；另在 `GetGridForGroup` 与绘制循环各留一道**显式**过滤作双保险。语义也成立：锚点不是"在活动"的实体 |
| I2 | 锚点天体归属 | `ResolveBodyIdForTile`：按 PlanetLayer 反查天体，无匹配退回地球（bodyId 1） | §12 把"世界 tile → 天体归属映射"列为后续项；此处做了最小版（遍历天体比对 layer），月球据点可直接归属月球，不阻塞后续精确化 |
| I3 | 锚点位置口径 | **群组坐标系**（根行星 = 原点）：`bodyPosInGroupFrame + 固连方向 × R_body`，**不含自转相位**。天体位置取 `SpaceEntityGroup.GetCentralBodyOffset` 口径（行星 → 零；卫星 → 绕行星偏移） | 群组系是碰撞检查（`SpaceGameComp.GetBodyWorldOffset`）、圆轨解析（`GetCircularPositionAtTick`）、N 体积分器（`NBodyIntegrator` 用 `GetBodyLocalPosition`）共用的口径，锚点必须同系。⚠ **初版误用 `CelestialBodyManager.GetBodyWorldPosition`**（递归到恒星的绝对位置，地球绕日 `orbitRadius` = 120,000 km）→ 2026-09-10 游戏内日志 `pos=(116920,3284,-3453)km` 暴露：地球锚点被甩到 12 万 km 外，且该值随地球公转时变（连"静态初始化"都站不住） |
| I6 | 自检里"锚点位置"的校验口径 | 用 `group.GetCentralBodyOffset` **独立反推**，不重算被测实现的输入 | 初版自检与实现同错（两边都调 `GetBodyWorldPosition`）→ 12 万 km 的帧错误被判 PASS。**教训：自检不得复用被测代码的中间量，否则验的是自洽性而不是正确性**；现另加"根行星锚点 `|pos| == R_body`"这条与天体绝对位置无关的硬校验 |
| I4 | 读档重建范围 | 反查索引与锚点登记表**均不序列化**，读档后惰性重建 | 派生数据不落盘 = 不存在第二事实源；`indexesReady=false` 时首次调用重建（悬挂引用校验 + 同星座内去重 + 重建索引与登记表） |
| I5 | 锚点释放时机 | 成员摘除后「无星座引用」即 `DestroyGroup`（`MaybeReleaseAnchor`） | 落实 §5 注释里的"最后引用移除 → DestroyGroup"；据点被摧毁的惰性回收复用同一路径 |

## 1. 背景（Problem）

PFL 的轨道实体管理集中在 `SpaceGameComp`（`groups` 字典），但缺少**组织/命名层**：

1. **卫星没有"归属编组"概念**：DMS:NF 载荷部署（`IPayloadDeployer`，R10 约束部署实体必须入独立 Group）会产生大量卫星，玩家/阵营无法按用途把它们组织起来（如"通信星座""侦察星座"）。
2. **已有枚举规划只按属性**：PFL 闭环规划中的 `OrbitalEntityCatalog` 按 defName/类型/阵营枚举——是"属性查询"维度；**缺"归属/用途分组"**这一维度（星座正是补位）。
3. **星座不等于 Group**：`SpaceEntityGroup` 是最小轨道单元（1 颗卫星 = 1 Group），星座是"群的群"——跨 Group 的逻辑集合，语义层级高于既有群组概念。

## 2. 定位与设计原则

一句话定位：**薄层组织组件**——在 `SpaceGameComp` 之上维护"星座列表 → Group 成员"的编组关系，不碰物理/轨道/燃烧；轨道能力全部复用 Group 既有 API。

| 原则 | 内容 |
|---|---|
| **零 Tick** | 不覆盖 `GameComponentTick`。星座只在「成员加入 / 被销毁」时做维护，其余时刻零开销 |
| **纯事件驱动** | 维护动作由事件触发，**同步完成于事件当帧**，不排队不攒批 |
| **实时查询** | 星座功能被调用时才起作用；查询实时读 `SpaceGameComp.groups`，无派生缓存 → 零漂移风险 |
| **纯运行时** | 星座实例运行时动态创建，无 Def、无注册（GameComponent 子类自动实例化） |
| **纯 API** | 本期不写 UI，仅对外提供 API 与单测 |

## 3. 核心概念

| 概念 | 定义 |
|---|---|
| **星座（Constellation）** | 命名编组实例：`ConstellationId + Name + 成员列表`。纯运行时创建，玩家可重命名 |
| **成员（ConstellationMember）** | 一个轨道 Group 的引用（groupId），卫星/空间站或**锚点 group** 统一；带可选元数据（role/slotIndex/deployedBy，本期不启用） |
| **锚点 group（AnchorGroup）** | 为地表据点合成的不动 Group：`IsMovable=false` / `IsCollidable=false` / `IsSurfaceAnchor=true`，位置 = `bodyCenter + R_body × dir(tile)`；据点入编 = 懒创建锚点 group 后按普通 group 加入 |
| **多归属** | 一个 Group 可同时属于多个星座（如一颗星既在通信星座又在对月链路星座） |
| **反查索引（reverseIndex）** | `groupId → 星座Id集` 的派生索引，单表，由触发器增量维护，读档重建 |
| **触发器（Trigger）** | 星座维护的唯二入口：成员加入、成员被销毁 |
| **准入条件** | 圆轨（`IsCircularOrbit == true`）**或**锚点 group（`IsSurfaceAnchor == true`）；深空自由飞行体 / 导弹 / 机动中飞船不能入编 |
| **资格保留** | 成员资格 = 组织身份，与轨道状态解耦：退出圆轨 / 变轨不踢出，状态查询实时读；"有效成员"口径由查询层实时过滤圆轨成员实现 |
| **成员失效统一** | 全部成员（卫星 + 锚点）走 `GroupDestroyed` 事件收尸；锚点 group 的"据点被摧毁"无原版事件 → 星座查询侧**惰性校验**（`anchorWorldObjectId` 对应 `Settlement.Destroyed` → 移除 + DestroyGroup 锚点） |

## 4. 整体架构

```
ConstellationGameComp : GameComponent            ← 独立组件，不覆盖 GameComponentTick
├── List<Constellation> constellations           ← 核心数据（IExposable，单一事实源）
├── Dictionary<int, HashSet<int>> reverseIndex   ← 派生索引：groupId → 星座Id集（多归属）
├── Dictionary<int, int> settlementToAnchor      ← 据点 → 锚点 group 登记表（防重复创建 + 惰性回收）
├── ConstellationId 分配器（扫 max+1，与 AllocGroupId 同规则）
└── 惰性事件订阅（首次使用时才 subscribe，避开 GameComponent 构造顺序问题）

     读取 groups             订阅 GroupDestroyed
SpaceGameComp.groups  ←  DestroyGroup 内新增事件（唯一侵入点）
```

- 组件构造器/首次使用时对 `SpaceGameComp` 惰性订阅销毁事件（RimWorld 不保证 GameComponent 构造顺序，构造期取组件可能为 null）。
- 唯一对既有代码的侵入：`SpaceGameComp.DestroyGroup` 内新增 `public event Action<int> GroupDestroyed;`，与现有 `OnGroupDestroyed → CombatManager` 同位置 fire。

## 5. 数据结构设计

```csharp
/// 成员：星座内的一个轨道 Group（groupId），卫星/空间站或锚点 group 统一；带可选元数据
public struct ConstellationMember : IExposable
{
    public int groupId;                   // 唯一键：同一星座内不重复
    public string role;                   // 角色标签（"comms"/"nav"/"relay"…）——本期不启用，全空
    public int slotIndex;                 // 槽位号，-1 = 未分配（Walker 相位布局预留）——本期不启用
    public string deployedBy;             // 部署来源载荷 Def 名（追溯用）——本期不启用
}

public class Constellation : IExposable
{
    public int ConstellationId;              // 独立分配器（扫 max+1）
    public string Name;                      // 可重命名
    public List<ConstellationMember> Members;   // 单一事实源（truth）
}

// ── 锚点 group：地表据点的合成 group（借 SpaceGameComp 的 group 通道，星座成员类型保持单一）──
// SpaceEntityGroup 新增字段：public bool IsSurfaceAnchor = false;  public int anchorWorldObjectId = -1;
// 位置 = bodyPosInGroupFrame + R_body × dir(tile)：
//   · 坐标系 = **群组坐标系（根行星 = 原点）**，与碰撞/圆轨解析/N 体积分同系；
//   · bodyPosInGroupFrame 取 SpaceEntityGroup.GetCentralBodyOffset 口径（行星 → 零；卫星 → 绕行星偏移），
//     ⚠ 不是 GetBodyWorldPosition（那是递归到恒星的绝对位置，地球绕日 120,000 km —— 见 §0.2 I3 的踩坑）；
//   · dir(tile) = 该天体 PlanetLayer 的 Find.WorldGrid.GetTileCenter(tile).normalized（固连系，不含自转相位）
// 天体自转未建模 → 地球锚点位置恒定；月球锚点随公转平移（本期静态初始化，不刷新，见 §12）
// 物理层对 IsMovable=false 已有系统性跳过（ApplyPendingImpulses L823 / UpdateAllMovements L859）
// 渲染/可视化管理器须按 IsSurfaceAnchor 过滤，不得当飞船绘制

public class ConstellationGameComp : GameComponent
{
    private List<Constellation> constellations;
    private Dictionary<int, HashSet<int>> reverseIndex;       // groupId → 星座Id集（多归属）
    private Dictionary<int, int> settlementToAnchor;          // WorldObject.ID → 锚点 groupId
    // EnsureAnchorGroup(woId)：查 Settlement → tile → 天体 → 建锚点 group（懒创建，防重复）
    // ReleaseAnchorGroup(groupId)：最后引用移除 / 据点销毁 → DestroyGroup（复用收尸链路）
}
```

设计要点：

- **单一事实源**：成员元数据只存星座侧；reverseIndex 是派生物，任何时刻可由 `constellations` 全量重建 → 杜绝双写不一致。
- **多归属**：reverseIndex 用 `HashSet<int>`，天然支持一颗星属于多个星座。
- **无派生缓存**：聚合查询（成员数/在轨数/按中心天体分布）不做常驻缓存——星座规模小（典型 <50 成员），查询时遍历即可；后续仅在确成热路径后再加脏标记缓存。

## 6. 触发器设计（仅 2 个）

| 触发器 | 挂点 | 维护动作 |
|---|---|---|
| **加入** | `AddMember(groupId)`（组件自身，统一）；`AddSettlementMember(cid, woId)` 便捷入口（内部 `EnsureAnchorGroup` → `AddMember`） | 校验（圆轨 或 锚点）+ reverseIndex 同步 |
| **被销毁** | 订阅 `SpaceGameComp.GroupDestroyed`（[DestroyGroup](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Base/Game/SpaceGameComp.cs#L266-L297) 内 fire）——卫星与锚点 group **统一**走此事件 | 按 reverseIndex 从**全部**所属星座移除成员 + 索引同步；锚点 group 额外清理 `settlementToAnchor` |

**锚点惰性回收**：据点被摧毁（原版无事件）→ 星座查询 `GetMembersWithState` 时对锚点成员反查 `Settlement.Destroyed` → 移除成员 + `ReleaseAnchorGroup`（DestroyGroup）→ 星座收尸链路自动完成剩余清理。

**被否决的触发器**（早期方案有 4 个，讨论后砍掉 2 个）：

| 触发器 | 否决原因 |
|---|---|
| 退出圆轨 | 资格保留语义下不触发任何结构维护；在轨状态由查询实时读 `group.IsCircularOrbit` |
| 改变归属（阵营归属） | 查询实时读 `group.FactionId`，同理无需维护 |

> 术语确认：「改变归属」指**阵营归属**（FactionId 变化），非中心天体。A 路线（薄到底）下它不需要触发器。

**审计结论（供实现参考）**：销毁路径的调用点分散（BoardingManager/战斗均调用 `DestroyGroup`），但 `DestroyGroup` 是**唯一收束点**，加一个事件即可覆盖全部路径，与 `OnGroupDestroyed → CombatManager` 先例一致。

## 9. 序列化要点

- `Constellation` / `ConstellationMember` 全 `IExposable`；成员列表 `Scribe_Collections(LookMode.Deep)`。
- 读档顺序：`LoadGameComponentNow` → 重建 reverseIndex + settlementToAnchor（由 `constellations` 全量推导，锚点成员经 `IsSurfaceAnchor` 识别）→ 校验悬挂引用（groupId 不在 `SpaceGameComp.groups` → 移除成员 + Log.Warning）。若此刻 groups 未就绪，**惰性延后到首次查询**。
- ConstellationId 分配器读档后重新扫 max+1（与 AllocGroupId 行为一致，防 id 复用冲突）。

## 10. 设计决策记录

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 系统定位边界 | **薄层**：只做组织/列表维护 | 轨道保持等能力复用 Group 既有 API；符合 PFL 机制层分工，不过度设计 |

| D4 | 星座实例来源 | **纯运行时动态创建** | 无 Def 体系膨胀，符合机制层定位 |
| D5 | 维护模式 | **零 Tick + 纯事件驱动** | 星座只在变化时维护、调用时起作用；同步完成不攒批 |
| D6 | 触发器数量 | **2 个**（加入/被销毁） | 退出圆轨/阵营归属变化实时读即可，无派生缓存可失效 |
| D7 | UI 范围 | **纯 API** | 本期不写窗口，DMS:NF 侧需要时再提供 |
| D8 | 成员准入与离轨语义 | **仅圆轨可加入 + 资格保留** | 圆轨是准入门槛（排除深空自由飞行体/导弹）；退出圆轨不踢出（资格 = 组织身份）。依据：任何机动（规划/燃烧/修正烧）都触发 `ExitCircularOrbit`（ManeuverPlanner L648、SpaceGameComp ApplyPendingImpulses），踢出会让星座成员形同虚设；"有效成员"由查询层实时过滤 |
| D9 | 成员类型泛化 | **⚪ 已废弃**（被 D11 锚点方案替代） | 曾拟 Orbital + GroundSettlement 双 kind + 双表 reverseIndex；Settlement 是原版类无法实现接口，复杂度高，弃用 |
| D10 | 成员统一视图 | **⚪ 已废弃**（被 D11 锚点方案替代） | 曾拟 `IConstellationMember` 视图接口 + 双 adapter；锚点方案打回单类型后不再需要 |
| D11 | 地表据点入编 | **锚点 group（`IsSurfaceAnchor` 合成不动 Group）** | 每个据点懒创建锚点 group 入 `SpaceGameComp.groups`（`IsMovable=false` / `IsCollidable=false`，物理层已有系统跳过 ApplyPendingImpulses L823 / UpdateAllMovements L859）；成员类型统一为 groupId，星座核心最薄；位置 = `bodyCenter + R_body × dir(tile)`（天体自转未建模 → 解析简单，`GetTileCenter` 现成）；为未来天地统一位置（组网通信）铺路 |
