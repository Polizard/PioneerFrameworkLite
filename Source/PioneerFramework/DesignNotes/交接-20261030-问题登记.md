## 2. 问题①：抛级不产生分离（位置/速度/级号三处都不严格）

### 2.1 现场证据（全部实测代码，非推测）

1. **新组直接抄父组轨道状态，零偏置零相对速度** ——
   `SpaceGameComp.TrySeparateStage`（`Base/Game/SpaceGameComp.cs:985`）：
   `group.CurrentOrbit = new OrbitState { positionSystem = parent…, velocitySystem = parent…, rotation = parent… }`（:1011–1016）；
   新实体 `new SpaceEntity(...)` 的 `Position` **不设**（默认 0，:1020–1028），
   而零件 `positionShip` 原样跟着走（`entity.SetParts(jettisoned)`）⇒ **两组的原点、姿态、速度完全重合**。
   ⇒ 全仓 grep 无任何"分离冲量/相对速度/轴向偏置"（`separationImpulse|分离.*冲量` 均 0 命中）。
2. **零件是精确贴面** —— `DesignPartAssembler` 按 `stackLength` 逐站推进（`zCursor -= stackLength`），
   站与站之间**零间隙**、也不插级间环 ⇒ 切分点两侧的 part 面贴面（穿透量恰 0，任何姿态/数值抖动就变负）。
3. **级号允许在堆叠里交错** —— `StagePartition.Split`（`Base/Core/StagePartition.cs:24`）只按
   `part.stageId == maxStage` 分两堆，**不看堆叠顺序**；而设计侧 `+级/−级`（`ShiftPartStage`）只改数字：
   `EnginePlacementError` 只要求"本级内引擎在该级末尾"，**不要求同级连成一块** ⇒
   像 `[控制0, 罐1, 引擎0, 罐1, 引擎1]` 这种设计**能过设计门**，切组后两组的 z 区间**真的互相穿插**。
4. **两组都是可碰撞体** —— 新组 `IsCollidable = true`（`SpaceGameComp.cs:1008`），
   父组由 `LaunchService` 建组时 `IsCollidable = true`（`Launch/LaunchService.cs:158`）
   ⇒ 交叠从下一物理 tick 起就进 `CombatManager`：`CollectPartContacts` → `CollisionSolver.Resolve`
   → **最多 8 轮位置投影**（`Combat/CombatManager.cs:3786–3821`）⇒ 抖动 / 被弹开 / 速度解算注入能量。
5. **新组原点不是它自己的原点** —— 被抛级的 part 坐标仍以**父组原点**为基准（例如 z≈−40…−46 m），
   新组的 `positionSystem` 却是父组原点 ⇒ 它的轨道状态/质心记账带一个"半条船"的系统偏移。
   （这正是用户说的"位置不严格"的另一半；视觉上两级也仍贴在原位，看起来像没分开。）

### 2.2 结论

抛级现在只是**逻辑切组**：没有任何几何分离、没有相对速度、也没有"同级必须连续"的几何保证。
在**两级块连续**且**完全静止**的顺境下可能只是"贴在一起不动"；一旦级号交错、或碰撞求解器判到穿透，
就变成用户看到的"分离时交叠"。

### 2.3 修复方向（**待批，不擅自开工**）

## 8. 讨论：C 是不是"最根本"的？

### 8.1 结论

**是"位置口径"的根本，但不是"分离交叠"的根本。**

- C 单独做，**世界坐标一个零件都不动**（§8.2）⇒ 该叠还是叠。治交叠的必需项是 **A（几何上同级不穿插）+ B（真的给位移/速度）**。
- 但 C 确实碰到了一个更深的病：2026-10-28 用"叠零件"替代舱盒之后，`positionSystem` 的语义
  **从"舱盒中心"悄悄变成了"机头"**，而所有"船在哪"的消费者没跟着复核 ⇒ 全船带一个**随姿态旋转的半条船偏移**
  （当前火箭 30–60 m）。这才是"位置不严格"的全貌，不只抛级才有。
- 物理层**已经**是 COM-aware：`CollisionBodyState.CenterOfMassWorld = Position + R·com`、
  `CollisionSolver` 的力臂用 `contact − comWorld`、引擎力矩走 `GetEngineTorqueAboutCom`、限速读 `p1..p3`（绕质心）。
  ⇒ 原点≠质心**没有**让碰撞/力矩算错，所以 C 不是"物理正确性"修复，而是"读数与近距判据"修复。
- 要立的不变量**不是**"原点 = 质心"（质心会随烧油漂，追它会把轨道积分/存档/相机搅乱），而是：
  **"`positionSystem` = 装配/分离那一刻的质心；之后 COM 相对它漂，需要'船中心'的消费者必须加 `InertiaResult.com`。"**

### 8.2 为什么 C 单独治不了交叠（一行代数）

零件世界位置 = `groupPos + R·(entityPos + partPos)`。重定原点 = `partPos' = partPos − c`、`groupPos' = groupPos + R·c`
⇒ 世界位置**逐件不变**（只差浮点舍入）。两组仍重合、仍贴面、仍同速度 ⇒ 现象不变。

### 8.3 C 的真实收益（按消费者列，当前火箭 R·com ≈ 30–60 m）

| 消费者 | 现状读的是 | C 之后 | 影响 |
|---|---|---|---|
| 碰撞冲量/角速度 | **已是 COM**（`CenterOfMassWorld`） | 不变 | 无（C 不修这个） |
| 引擎力矩/姿态限速 | **已是质心**（`GetEngineTorqueAboutCom` / `p1..p3`） | 不变 | 无 |
| 轨道要素/远地点读数 | `positionBody`（原点） | 质心 | 5,000 km 轨道上相对 1e-5，**只是读数好看** |
| 高度/气动密度 | 同上 | 质心 | 8 km 标高处 40 m ≈ 0.5% 密度 ⇒ 0.5% 阻力，可忽略 |
| **落地/触地判据** | 同上 | 质心 | **早/晚触发几十米**（真影响） |
| **对接/交会距离门** | 两组原点互比 | 各自质心 | 10 m 级的"到位门"会被几十米偏移吃掉 ⇒ **假通过/假失败** |
| 相机/选中焦点 | 同上 | 质心 | 视觉上"船不在选中框中心" |
| 地图锚定（有图件） | `ownerPart.positionShip` | **例外：不能动** | 动了会挪图 ⇒ C2 必须跳过有图实体 |

### 8.4 三个粒度（成本/风险递增）

- **C1（推荐，和 B 同批）**：只在 `TrySeparateStage` 里重定被抛级 —— `partPos -= c`（体轴）、
  `positionSystem += R·c`、速度不变；世界位置逐件不变。代价 ~15 行 + 2 条判据
  （"世界位置不变" + "新组 `com≈0`"）。收益：碎片自己那一组的高度/落地/读数自洽。
- **C2（单独立案）**：装配时全局重定（`LaunchService` 装配完 → `RecenterToCom(entity)`），让**每条**无图火箭原点 = COM。
  代价：发射链 1 处 + **地图锚定例外**（有图实体不重定）+ 落地/对接/相机判据回归。
  收益：所有无图船的"船在哪"一次性对齐。
- **C′（不建议）**：改 `GetGroupPos` 返回 COM —— 会与碰撞里 `Position=原点 / COM=Position+R·com` 双计，
  且全仓 ~30 处调用点语义一起变；风险/收益最差。

### 8.5 建议顺序（每步都"先加读数再改"）

3. **C2 + "船在哪"消费者清单**（落地/对接/相机/轨道读数）——单独立案，因为它改的是全局前提。
### 8.6 用户方案（2026-10-30 12:4x）与评估：两组都重定到各自质心 + 严格速度

> 用户原话："我们之后要把分离产生的两个 Group 的原点都取在质心，速度按照分离时的角速度和速度和原整体与新
> group 的质心位置来严格计算。"

**评估：方向正确，而且比我上一轮的框法更硬 —— 这是"模型自洽"级的问题，不只是读数。**

**8.6.1 为什么"原点=质心"是对的（新证据，上一轮没写）**

- 积分器把 `CurrentOrbit.positionSystem/velocitySystem` **当点质量状态**积分（引力/气动/轨道全按它算），
  而碰撞层把 `velocitySystem` **当质心速度**用（`CollisionBodyState.Velocity` 注释就是"质心线速度"，
  `CenterOfMassWorld = Position + R·com`）。⇒ 存储状态**本来就该是质心状态**；
  机头原点等价于让"质心速度"少了 `ω×r_com` 那一项（1°/s × 45 m ⇒ **0.8 m/s** 的系统误差）。
- 仓里已有同口径先例：`DzhanibekovDemo` 用 `DVector3.Rotate(bodyOmega, rotation)` 把 ω 旋到世界系
  （⇒ **`angularVelocity` 是世界系**）；`StructureSpatialService` 的子体状态就是
  `V + Cross(ω, offset)` —— 正是用户要的"刚体速度场"。

**8.6.2 严格式子（按用户三条落成公式）**

体轴系（`R` = 体→世界、`ω` = `group.angularVelocity` 世界系）：

```
c_A, c_B        = 两半的质量加权质心（体轴；质量口径必须与 InertiaTensor.Compose 一致
                  = part.Mass + 罐内 tank.massKg，否则 c_A/c_B 与 c_whole 不自洽）
r_i             = R·(c_i − c_whole)                  世界系、相对整体质心
V_i             = V_whole + ω × r_i                  ← 刚体速度场（用户要的"严格"）
ω_i             = ω                                  （分裂瞬间两边角速度相同）
partPos_i      -= c_i                                体轴平移
positionSystem_i += R·c_i                            世界几何**逐件不变**（可逐位验收）
```

守恒自动成立（两行）：
`Σ m_i V_i = (Σm_i) V + ω×Σ(m_i r_i) = m_whole V`（因为 `Σ m_i r_i = 0`）；
`L = Σ(I_i ω + m_i r_i×V_i) = (I_A+I_B)ω + 平行轴项 = I_whole ω`。

**8.6.3 必须补一件：严格刚体分裂在 ω≈0 时相对速度为 0**

火箭正常姿态受控（ω≈0）时 `V_A = V_B = V` ⇒ **仍然贴着走**（甚至被碰撞求解器推）。所以还要分离机构：
沿分离面法线的一对**等大反向冲量** `J`（`Δv_i = J/m_i`，动量守恒）+ **0.5 m 初始间隙** + **1 步碰撞豁免**。
物理步长 = 2 s（`UPDATE_INTERVAL_TICKS=2`）⇒ 1 m/s 一步就是 2 m，足够。真实值 0.3–2 m/s。
若冲量不通过各自质心（异形级），再补 `Δω_i = I_i⁻¹ (r_apply,i × J_i)`；对称串联时该力矩 ≈ 0。

**8.6.4 三个实现坑（动手前必须钉）**

1. **质量口径**：`InertiaTensor.Compose` 用的是 `part.Mass + 罐内 massKg`（损毁罐不算燃料）；
   分离算 `c_A/c_B` 必须同一函数/同一规则，否则 `Σ m_i r_i ≠ 0` ⇒ 动量不守恒（差在几十 kg 级上就看得见）。
2. **惯性缓存**：只改 `partPos` **不会**自增 `partSetVersion` ⇒ 必须 `InvalidateStats()`（顺带触发 `PartPropulsionBuilder`
   重建，正好和抛级重建同处）否则 `InertiaResult.com` 还是旧值、`com` 不归零。
3. **母舰也跳**：`Δpos = R·c_A`（几十 m）、`Δv = ω×r_A`（≤ ~1 m/s）。这是把参数化改对，但引导/落地判据要回归一次，
   并在抛级那一步打一条 `[抛级·帧] 母舰 Δpos/Δv | 两组 com | 最小间距` 的即时读数（先探针后改的规矩）。

**8.6.5 范围建议**

- **C2 先做**（装配即质心原点，所有无图船，含调试 spawner/载荷展开）：否则"分离才重定"会让同一种船有两种口径
  （单级船永远机头原点）。
- **分离**用 8.6.2 的公式 + 8.6.3 的机构冲量/间隙/豁免（= B + C1 的严格版）。
- **A 仍是前提**：级号交错 ⇒ 两半几何互相穿插，"严格公式"描述的也不是一个合法的刚体分裂。
- **地图件例外**：`MapCoordMapper` 锚在 `ownerPart.positionShip`，有图实体不重定（或同步挪锚点，后置）。

**8.6.6 待裁参数**

`J`（0.3 / 1 / 2 m/s 等效）、初始间隙（0.5 m？）、碰撞豁免（1–2 步？）、母舰反向 Δv 按质量分配要不要做、
C2 是否与分离同批（我的建议：C2 与分离同批，否则口径会分叉）。
### 8.7 性能审视（2026-10-30 用户追问"这套方案到底多大消耗、怎么削减"）

**结论：这套方案不碰任何每 tick 路径，成本全在事件上（装配 1 次 / 抛级 1–3 次每飞行），μs 级；
抛级后两组各少一半件，碰撞配对成本反而下降。真正的红线是"别把它做成每 tick 维护的不变量"。**

**8.7.1 逐项成本（口径 = Release；Debug 慢 2–6×；N = 件数，典型 15–30，上限 256）**

| 步骤 | 触发 | 复杂度 | N=30 | N=256 |
|---|---|---|---|---|
| 装配重定（Σm/Σm·p 一遍 → c；平移 `partPos`；`+R·c`） | 每次发射 1 次 | O(N) | ~2–5 µs | ~20–40 µs |
| 惯性重算（`Compose` + 3×3 Jacobi） | 每次事件 1 次（抛级本来也要重算） | O(N) | ~2–5 µs | ~20–40 µs |
| 分离帧（c_A/c_B + `V+ω×r` + 平移） | 每次抛级 1 次 | O(N) 一遍 | ~2–4 µs | ~20 µs |
| 机构冲量 + 0.5 m 间隙（并入同一趟平移） | 同上 | O(N) | ~1 µs | ~8 µs |
| 碰撞豁免（`int graceUntilTick`，配对循环里一次比较） | 每步每组对 | O(1) | ns 级，且**省掉**重叠时 8 轮位置投影 | 同 |
| **每 tick 新增** | — | — | **0** | **0** |

**8.7.2 三种"会变贵"的写法（明确不要）**

1. **每 tick 追质心**（"每步检查 com≈0 并修正"）= O(N)/步；256 件船就是每步上万次浮点 × 组数 ⇒ 纯浪费。
   重定只允许发生在**装配 / 分离**两个事件。
2. 用 `InvalidateStats()` 做重定：它会 `RebuildMapless` + `InvalidateSignal` + `SyncStageFeedValves` + `RefreshWheelCapacity`，
   而抛级路径**已经**显式重建过一次推进 ⇒ 双跑。改用窄入口 `BumpPartGeometryVersion()`（只 `statsDirty=true; partSetVersion++`）。
3. 豁免实现成"每步扫描组对/建 HashSet" ⇒ 把 O(1) 变 O(G²)。用组上的 `gyaceUntilTick` + 配对时比较即可。

**8.7.3 削减清单（按收益排序）**

1. **事件化**：只在装配/分离做，不在 Step 里。
2. **一遍遍历多累加器**：`Σm_A, Σm_A·p, Σm_B, Σm_B·p` 一次算完；`m_whole` 直接用 `InertiaResult.mass`（已有），不重算。
3. **质量快路径**：`part.Mass + (tank?.massKg ?? 0)`，同趟把 `PropellantTankComponentData` 取出来缓存
   （`GetComponent<T>` 是组件列表线性扫描，别在循环里调两次）。
4. **窄失效**：`BumpPartGeometryVersion()` 代替 `InvalidateStats()`；惯性缓存由 `partSetVersion` 触发一次重算即可。
5. **只对无图组**重定（有图件锚在 `ownerPart.positionShip`，跳过 ⇒ 零成本零风险）。
6. **间隙并入平移**：`partPos = partPos − c_i ± gap/2` 一趟写完，不另开循环、不重建几何。
7. **探针先上**：`PerfProbe.ExtraClockStart/End(slot)`（已有 API，不必动 `ColStage*` 枚举）包住两个事件；
   判据 = 事件 < 0.1 ms 且 **抛级那一帧之后每步耗时分布不劣化**（同场景同件数、前后对比）。
8. **别塞进 `SpaceEntityGroup.Inertia` 的缓存重建路径**：那条路径被 `partSetVersion` 频繁触发，
   把重定放进去会把"事件成本"变成"每次缓存失效成本"。
9. 顺手（可做可不做）：`CenterOfMassWorld` 加 `if (com.sqrMagnitude > 1e-12)` 早退 —— 重定后 com≈0，
   每次接触求解省一次四元数旋转（ns 级，纯白送）。

**8.7.4 净收益面（白送）**

- 抛级后每个组只有一半件 ⇒ 组内 part 对 ~O(n²) 下降约 4×（母舰侧），碰撞配对/接触成本下降。
- 首步跳过两组接触求解（豁免）⇒ 省掉"重叠时最多 8 轮位置投影 × ≤8 接触"的那一段。
- 8.7.2 第 2 条若照做，还省掉一次 `RebuildMapless`。

**8.7.5 结论**

这套方案**不需要新增算力预算**（事件 μs 级）；要守的只有三条：事件化、一遍过、窄失效。
若实测超预算（Debug > 200 µs），第一刀是把两半质心在**装配时**缓存到实体上（`bodyComOffset`），
抛级时直接用，省掉一次全扫描。
### 8.8 施工前正确性复核（2026-10-30）：核心对，但有 5 个洞必须先钉

**站得住的部分**

1. **重定是纯重参数化**：`partPos -= c`、`groupPos += R·c` ⇒ 世界坐标逐件不变（可逐位验收）。
2. **`V_i = V + ω×r_i` 是刚体速度场**（`r_i = R(c_i − c_whole)`）⇒ 动量 **和** 角动量都精确守恒：
   `Σm_i V_i = mV + ω×Σ(m_i r_i) = mV`；`Σ[I_i ω + m_i r_i×V_i] = (I_A+I_B)ω + 平行轴项 = I_whole ω`。
3. `ω_i = ω`（无冲量极限下两边瞬时速度场一致）。
4. 质量口径必须与 `InertiaTensor.Compose` 同源：`part.Mass + 罐内 massKg`（损毁罐不算燃料）。

**五个洞（按严重度）**

1. **分离方向要按几何，不能按级号/−Z**：`ReverseStages`/`+级−级` 允许级号与几何脱钩，
   被抛级可能几何上在"上面" ⇒ 沿 −Z 推 = 把两级推到一起。⇒ `n_body = normalize(c_B − c_A)`；
   `|c_B − c_A| < eps`（两组质心重合/穿插）⇒ **拒绝分离**并报设计非法（A 门应在装配期先拦）。
2. **冲量必须"线性 + 角量成对"施加，否则不对称级丢角动量**：
   `ΔL = (r_A−r_B)×J + [I_AΔω_A + I_BΔω_B]`；取 `Δω_i = I_i⁻¹((x_sep−c_i)×J_i)` 时两项**精确抵消** = 0。
   ⇒ 上一轮写的"异形级再补 Δω"不是可选项，是守恒的必要项（对称串联时它恰好为 0，所以才显得"不用"）。
3. **重定要平移 `partPos`，不要改 `entity.Position`**：`MapCoordMapper.ShipToMapLocal/MapToShip` 只用
   `ownerPart.positionShip`（**不加** `entity.Position`），而 Inertia / Engine / `MapCoordMapper:94` /
   `AutonomousVehicleManager` / `ShipMapBackgroundCamera` / `CombatManager:986` 都加。今天无图火箭
   `entity.Position` 恒 0 ⇒ 两边都对；改成非 0 后前者错位。⇒ 无图单实体船**保持 E=0，平移 partPos**。
4. **`InertiaResult` 缓存不会因"位置变了"自动失效**：stamp = `entitySetVersion ^ partSetVersion ^ tankMassVersion`，
   位置不在其中。抛级路径里 `RemovePart`/`SetParts` 恰好 bump 了，但**没有代码保证**以后不在中间读 ⇒
   加窄入口 `BumpPartGeometryVersion()`（`statsDirty = true; partSetVersion++`），重定末尾必调。
5. **重定是"换参"事件 ⇒ 所有存了绝对位置/速度快照的读数都看到一次跳变**：
   `burnDiagR/V/Tick`（"实收 vs 指令"对账会把跳变算成冲量）· `burnPreBurnOrbit`（旧帧绝对轨道）·
   `positionBody` 派生的制导读数 · 近距门（`ApproachCompletionDistance = 300 m`）。
   ⇒ 重定后 `burnDiagTick = −1` 重新基线 + `burnPreBurnOrbit` 重取；抛级帧打一行
   `[抛级·帧] 母舰 Δpos/Δv | 两组 com | 相对速度`。

**两个必须成立的前提（已核）**

- `entity.Rotation` 必须等于组旋转（Inertia/Engine 用组旋转；launch 时两者同值）⇒ 重定前 assert。
- `ω` 是**世界系**（`DzhanibekovDemo` 用 `Rotate(bodyOmega, rotation)`；`SteeringController.GetRotationWorldAngularVelocity`）；
  `R` = 体→世界（`DVector3.Rotate(part.positionShip, rotation)` 的口径）。

**修正后的算法顺序（10 步）**

```
1 读 V, ω, R（父舰当前状态，先读后改）
2 一遍扫全件：m_A,m_B,c_A,c_B（质量口径 = part.Mass + 罐内燃料；顺带 c_whole 与 InertiaResult.com 对账）
3 n_body = normalize(c_B − c_A)（< eps ⇒ 拒绝分离）
4 新组：P_B = P + R·c_B；V_B = V + ω×R(c_B−c_whole)；ω_B = ω；partPos -= c_B
5 父舰：P_A = P + R·c_A；V_A = V + ω×R(c_A−c_whole)；ω_A = ω；partPos -= c_A
6 冲量：J 沿 n_body（世界 n = R·n_body）；Δv_A = −J/m_A、Δv_B = +J/m_B
7 角量：Δω_i = I_i⁻¹((x_sep − c_i) × J_i)（对称级 ≈ 0，异形级必须算）
8 窄失效（BumpPartGeometryVersion）+ 各一次推进重建（父舰 RebuildMapless / 新组 BuildForMapless）
9 诊断重基线（burnDiagTick = −1；burnPreBurnOrbit 重取）
10 读数：[抛级·帧] 母舰 Δpos/Δv | 两组 com | 相对速度 | 两组件数/质量
```

**判据矩阵（先落纯核 `StageSeparationCore`，再集成）**

| # | 判据 | 容差 |
|---|---|---|
| 1 | 世界位置逐件不变 | 1e-9 相对 |
| 2 | 质心守恒 `m_A c_A + m_B c_B = m c` | 1e-9 |
| 3 | 动量守恒（含冲量） | 1e-9 相对 |
| 4 | 角动量守恒（含 Δω） | 1e-9 相对 |
| 5 | 新组 `|com| ≈ 0` | < 1e-6 m |
| 6 | 方向与标签无关（`ReverseStages` 后 n 仍背离） | 断言 |
| 7 | 对称级 `Δω≈0`；异形级 `Δω≠0` | 1e-9 / 非零 |
| 8 | 相对速度 = `J/m_A + J/m_B` ± ω×r 分量 | 1e-9 |
| 9 | 集成：件数/质量/推进池/两组 com | 逐项 |
| 10 | 读数对账：母舰 `Δpos = R·c_A`、`Δv = ω×r_A` | 1e-6 |

**会改变观感/行为的三点（写进交接，别当 bug 报）**

- **旋转支点从"机头"变成"质心"**（C2 之后）：姿态机动时船不再以机头为支点摆尾 —— 是修正，但看得见。
- 抛级瞬间母舰位置/速度各跳一次（几十 m / ≤ ~1 m/s，量级 = ω×c）⇒ 读数与"实收"对账必须重基线。
- 旧存档的船仍是机头原点（各自自洽）；新船/新分离才用新口径 ⇒ 混编编队的相对距离有几十米偏置（门限 300 m 级，可容忍但要记录）。
### 8.9 第二次复核（2026-10-30 12:5x）：4 个新洞 + 撤回上轮 2 条

**新洞（按严重度）**

- **N1（真 bug，且不只影响本方案）**：`TrySeparateStage` 建子实体时**没有复制父实体旋转**
  （`SpaceGameComp.cs:1020–1029` 只设 GroupId/HasMap/IsMovable/…）。而
  `CombatManager.CollectPartAabbs` 用的是 **`entity.Rotation`**（`entityRot = EffectiveRotation(entity.Rotation)`），
  绘制用的却是**组旋转** ⇒ 碎片在飞行中（R≠identity）**碰撞盒朝向与画面不一致**。
  ⇒ 修：`child.SetRotation(parentEntity.Rotation)`（并顺手 assert 父实体旋转 == 组旋转）。
- **N2（边界，现网可触发）**：`StagePartition.Split` 只切 `stageId == max`；若设计里**没有更低的级**
  （全部件都是 stageId=1，例如用"加入级"全填 1），`kept` 为空 ⇒ **父组变空壳**：`Inertia.HasData=false`、
  质量 0、`SetParts` 在 0 件时**不刷新 bounds**。⇒ 分离入口加 `kept.Count == 0 ⇒ 拒绝`（reason `would-orphan`）。
- **N3（设计门缺口，待裁）**：控制核心可以放在**将被抛掉的 max 级**里 ⇒ 抛级后 `SyncControlCorePresence` 归零 ⇒
  **永久失控**。建议加门：**控制核心必须在保留下来的那一级（= 最小 stageId）**，否则拒绝设计。
- **N4（顺序坑）**：平移 `partPos` 必须发生在 `SetParts` / `OnPartsChanged` **之前**（那两者才刷新 bounds/stats/
  控制核心/地图链）；否则缓存的 bounds 与几何不同步。⇒ 子组：先平移 jettisoned 的 `partPos`，再 `SetParts`；
  父组：先 `RemovePart` 循环，再平移 kept 的 `partPos`，最后 `OnPartsChanged(true)`（或 `SetParts(自家列表)`）。

**撤回上一轮 2 条**

- **撤回①"Δω 是守恒的必要项"**：若冲量沿**两半质心连线** `u = (c_B − c_A)/|c_B − c_A|`（中心冲量），
  则 `ΔL = (c_A − c_B)×J = −|Δc|·u×(j u) = 0` ⇒ **Δω = 0 且角动量精确守恒**。
  只有把冲量改成沿**结构轴**（与 u 不平行）时才需要 `Δω_i = I_i⁻¹((x_sep−c_i)×J_i)` 去抵消那一项。
  ⇒ 采用 `u` 做方向：更简单、可证、且物理上是"沿质心连线推开"。
- **撤回②"加窄入口 `BumpPartGeometryVersion`"**：`OnPartsChanged(true)` 才是唯一收口（bump `partSetVersion` +
  bounds + 控制核心 + 地图链）；**手写 `partSetVersion++` 会漏掉后面三项**。代价与现有 `RemovePart` 同级，
  批量移除优化后一次事件只跑一次。

**复核确认（好消息）**

- 碰撞只在**接近**（`vRel > 0`，`CombatManager.cs:1389`）时施加冲量；`vRel <= 0` 的分支只做**位置投影**
  （`max(穿透, 0.001) m`/接触）⇒ **分离冲量不会被碰撞求解器吃掉**；分离速度 ~1 m/s，远低于 CCD/爆炸阈值。
- `IsActive` 默认 **true**（碎片会被正常积分）；`DetachComponents()` 只调 `OnDetached()`，而**全仓无 `OnDetached` 重写**
  ⇒ 现有"先 `SetParts(jettisoned)` 后 `RemovePart`"的顺序**不会把子组件的组件摘掉**。
- `SetParts` 会 `SyncNextPartIdFromParts` + `SyncControlCorePresence` + `NotifyMapLinksChanged` + `InvalidateStats`
  ⇒ 子组状态自洽。

**判据矩阵的两处修订**

- 第 4 条（角动量）保持；第 7 条改为：**中心冲量 ⇒ `Δω ≡ 0`**（断言）+（可选）结构轴变体下 `Δω ≠ 0` 且 L 仍守恒。
- 第 9 条加两项：**子实体旋转 == 父实体旋转**；**父组件数 > 0**（否则拒绝分离）。

### 8.12 第四次批判性复核（2026-10-30 13:0x）：3 条反直觉修正 + 2 条简化（无新算式错误）

**R1（判据必须改口径）**：判据 #1"世界位置逐件不变"**不能按逐位判**。重定后
`world_new = P + R·c + Rotate(p − c, R)`，而 `world_old = P + Rotate(p, R)`；
浮点的旋转**不满足** `Rotate(p−c)+Rotate(c) = Rotate(p)`（~1e-16 相对）⇒ 必须按 **1e-9 相对容差**判。
写"逐位不变"的判据会假红，而写"逐位"又去凑数值就是软化 —— 口径只能是容差。

**R2（统一成一条规则，少一套公式）**：重定 = **`P += R·c；V += ω×(R·c)；partPos −= c`**（**c 相对"当前原点"**）。
理由：存储速度是**原点那一点的速度**，换原点到体轴 `c` 处 ⇒ 新原点的速度 = `V + ω×(R·c)`。
于是：**装配期重定（c = `InertiaResult.com`）与分离期两半重定（c = c_A / c_B）是同一个操作**，
上一轮公式里的 `c_whole` 项只在"不重定"时才有意义 ⇒ 删掉，少一套推导。
⚠ 装配期发射时 `ω = 0` ⇒ 速度不变（但 helper 仍要写 `V += ω×R·c`，否则将来旋转中装配就错）。

**R3（删两个魔数）**：**初始间隙 0.5 m 与碰撞豁免都不必要** ——
分离方向（`vRel<0`）只走位置投影（`max(穿透,0.001)`，零穿透 ⇒ 1 mm/接触）；且 1 m/s 在 2 s 步长下
**第一步就分开 2 m**。⇒ 不引入"瞬移间隙"，也不引入"豁免计数字段"（少两个参数、少一个状态）。

**R4（参数换成物理语义）**：冲量参数不要直接给 `J`，给**相对分离速度** `v_rel`（0.3 / 1 / 2 m/s），
`J = v_rel / (1/m_A + 1/m_B)` ⇒ 两半 Δv = `J/m` 自动按质量分配，读数也直观。

**R5（装配期接线顺序）**：C2 必须在 `LaunchService` 的 `SetParts(...)` **之后**、`RocketLaunchController` 接管**之前**
（否则制导会先读到"机头原点"的出生点）；重定后世界几何不变 ⇒ 出生点/安全半径判据（`R+10km < R+100km`）不受影响。

**本轮"试图打破但没打破"的清单**（都查了实现/推导）：
`velocitySystem` 到底是不是原点速度（是；朝向积分左乘世界 ω ⇒ 刚体速度场 = `V+ω×(x−O)`）；
质心/动量/角动量三条守恒（含中心冲量 ⇒ `ΔL=0`）；质心在轴上的前提（并联环对称 + 目录件 boundsX==boundsZ 保证
每级 c 落在体轴上 ⇒ `u` 与结构轴一致，无需 Δω）；碰撞只对接近施加冲量；AABB/bounds 全按 part 逐件；
主线程相位与 `pendingImpulse` 时机；`OrbitState`/`OrbitDirty`；`IsActive`/`DetachComponents`/`SetParts`/地图链。

**结论**：算式层无新增洞；本轮把"判据口径、统一规则、删魔数、参数语义、接线顺序"磨了一遍。
