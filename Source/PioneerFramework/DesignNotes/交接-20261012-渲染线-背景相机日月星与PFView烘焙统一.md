**28. 渲染时钟连续化 —— "别的航天器整体位置在抖"治本（2026-10-12 12:40，本件最新的一块 · ⏳ 待验）**：
用户分流实测（10-11 晚）：**不是**表示切换（原话"**大小形状没变，但整体位置在抖**"）⇒ 真根 = **渲染时间轴是阶梯**：
`TimeScaleManager.GetPhysicsTickSafe()` 由**整数** `TicksGame` 推出 ⇒ 位置每 tick 跳一格；两台站不同轨道时相对速度可达 km/s
（每 tick 相对位移上千米）⇒ **渲染帧率高于 tick 率时，肉眼就是"抖"**（量级：几百 km 外的标记载体每 tick 走零点几~几像素）。
修三件：① **新增 `TimeScaleManager.GetRenderTick()`**：物理 tick + **子 tick 相位**（按真实帧时长实测、滑动平均；
相位**减去**走过的 tick 数 ⇒ 无跳变；暂停/掉帧夹在 [0,1]）；② **消费侧全改连续时钟** —— PFView（`RenderScene` 的时间、
渲染原点 `GetRenderOrigin`、编组位置、射弹外推基准）与**世界视图**（`PhysicsTickNow()`）；
③ **积分轨（非圆轨）组按速度外推**：`pos + v·(renderTick − SpaceGameComp.LastPhysicsStepTick)`
（与射弹那条"渲染位置解析化"同一手法；圆轨本就是**支持子 tick** 的解析函数，喂连续时间即严格连续）。
⛔ 两条纪律：**原点与物体必须同钟**（否则相对位置照样跳）；**只做相位平滑、不改时间基准**（平均值仍严格等于物理 tick）。
读数：`[PFView·抖动]`（每 300 帧一行）= 被观察组的**帧间位移 平均/最大/停滞帧/每帧 tick 推进**
——**验证口径：停滞帧 ≈ 0 且 最大/平均 ≈ 1**（阶梯时间轴的签名是"大量停滞帧 + 偶发大跳"）。

### 2.5 补丁上的细节：山 / 河 / 路（10-10 19:11，我们自己的画法）

**用户口径**：「先整山、河、路，**用我们自己的方式**而不是 RW 原版的方式整。」

**三条具体做法**（`PFView/PFViewSurfaceDetails.cs` 的文件头有同款说明；本批拒绝的正是"甲：把原版世界层 submesh 重投影过来"）：

1. **CPU 合成，不走 GPU 材质**：细节直接画进烘焙回读出来的像素（`Color32[]`），**不碰**原版那批世界材质
   （`WorldMaterials.Rivers/Roads/VertexColor…` 是给世界相机那条渲染路造的，"在离屏相机 + 命令缓冲里成不成立"不可离线验证）。
   副产品：细节核心是纯 C# ⇒ **10 条 headless 用例**钉住（混合/带的走向/软边/零长度退化/穹顶/模糊守恒/平场不动/径向对称/哈希）。
2. **山 = 高度场 + 无方向高通**（不是"每格一块山图标"）：有起伏的格撒穹顶（半径/权重按 `hilliness` 四档 + 高程加成 +
   确定性抖动）⇒ 高度场 ⇒ `h − 低通(h)` ⇒ 隆起亮、凹陷暗。**"无方向"是刻意的**：PFView 的昼夜由太阳方向光给
   （终止线是真的），烘一个固定光向进去会与它打架；无方向高通只表达起伏、不表态光从哪来。
   幅度按"典型起伏"**自动标定** ⇒ 山脉密的星和疏的星看起来一样明显；总幅度 = `ReliefStrength`（0.22，头号观感旋钮）。
3. **河 / 路 = 自己画的双层带**（岸 → 芯 / 描边 → 路面）：宽度由数据（`widthOnWorld`、`GetLayerWidth`）换算成
   补丁像素后**夹进可见区间**（数据里 0.2 格的细流在 ~8 px/格 上不足 1 px ⇒ 不夹 = 什么都没画）。
   **颜色口径**：数据里有的用数据（路的 `RoadWorldLayerDef.color`，逐层按 `order` 叠）、原版**写死在代码里**的
   用我们的（河色，原版是 `WorldDrawLayer_Rivers.riverColor` 的硬编码 (73,82,100)）。

**另外两处**：补丁图**开 mipmap + 三线性**（细线 1–3 px 在无 mip 贴图上缩到远景会闪；+33% 显存）；
细节在**两条自检之后**才画（自检数的是"地形画上了没有"，细节会把它改花）。

**19:29 追加（用户首份观感 + 显存意见）**：
- **河/路"一节一节"的三个成因**（查实，各对应一个修；症状由用户实测报回）：
  ① **半透明宽带把山体明暗透出来**（出厂岸 = `芯×1.8+0.6 px` 的 alpha 0.60 带）⇒ **全部改不透明**（= 用户要的"纯色"；
  顺带不透明重叠是**幂等**的）；② **逐段"岸→芯"画**，后一段的岸会压住前一段的芯（弯折处）⇒ **按层两遍画**
  （先把所有岸铺完再画所有芯；路 = 按 `RoadWorldLayerDef.order` 逐层、所有段先铺该层）；
  ③ **细线在远景被 mip 平均值化掉**（3 px 的芯在默认缩放下落到 mip 2 ⇒ 有效 0.8 px）⇒ **加粗一档**
  （`RiverWidthScale 1.7` / `RoadWidthScale 1.4`）。
  另加"防缝"：**不假设链数据对称**（对面没存回这条链 ⇒ 本侧必须画，否则每两格一个缝）+
  宽度取**两侧 def 的较宽者**（河道降级/道路过渡段会跳变）。
- **显存**：`Compress(true)`（RGBA32 ⇒ DXT5；**必须在 `EncodeToPNG` 之后**，压缩后 CPU 像素就取不回来了）
  ⇒ 48 → **12 MiB**；`UnloadReloadable()` 在 PFView 收起时放掉**有旁挂文件**的补丁图（下次打开重载一次）。
  **没做 DXT1（6 MiB）**：Unity 按有无 alpha 选格式，要 DXT1 得换成 RGB24，而细节合成走 `GetPixels32/SetPixels32`
  —— 格式兼容性离线验不了，不为 6 MiB 赌一次游戏内失败。

**22:31 追加（用户第二次观感：改细 / 河色取海色 / 噪点再弱）**：
- 粗细：`RiverWidthScale/RoadWidthScale` **1.7/1.4 → 0.8/0.6**（比 19:11 首版还细一档）；河岸描边 `RiverBankBorderPx` 0.9 → 0.6。
- **河色 = 海洋底色**：不再自定河色，**直接用烘焙的 clear color**（= 背景 biome 贴图平均色；本局 Ocean ≈ (59,71,90)）——
  海洋格画的就是那张 Ocean 贴图 ⇒ 河、海、帽外基底同一色，**河口接海无缝**。岸色 = 水色 × 0.72（只压暗一点点）。
- **山体噪点压到一点点**：`ReliefStrength` **0.22 → 0.08** + 低通半径系数 0.8 → 1.1（尺度更大 ⇒ 成"整片起伏"而非细碎噪点）。
- 机制不动（不透明纯色 / 按层两遍 / 防缝 / 压缩 / 卸载 / 无方向高通 全保留）。

### 2.6 大气表现：天空 × 日照 · 厚度一半的壳 · 分层雾（10-10 22:56）

**用户口径**：「摄像机越深入天空盒越蔚蓝」+「在有大气层的天体外周根据**大气层高度的一半**画一个**半透明壳子**——定义的是高层大气」，
三条裁定：① 搞日照；② 壳在厚度一半；③ 分层（天空满 α、物体 α×0.3）。

**三件各在哪**（`PFView/PFViewAtmosphere.cs` = 纯核心，`MainTabWindow_PFView.Atmosphere.cs` = 渲染）：

- **天空 = 相机的 `clear color`**（这个场景的"天空盒"就是它）⇒ 每帧按 α 混向 `CelestialBodyDef.atmosphereColor`（新增字段，默认天蓝）。
  **为什么不是整帧叠色**：天空要**满 α**、物体只要 **0.3**（用户口径）—— 换个方式就得做像素掩码，不值当。
- **α = `ρ(h)/ρ₀ × 日照`**：与阻力**共用同一条 ρ(h)**（"两条真相"是本仓库反复踩的坑）；**缺席即零**（月球没有蓝天空）；
  日照因子只读 PFView 那盏方向光（与星球明暗面**同一出处**），晨昏线附近给 0.15 的渐变。

## 4. 现场操作提醒（渲染线专属坑，逐条都踩过）

1. **改 DLL 必须重启游戏**（游戏只在启动时读 DLL）。
2. **ECall 规则**：headless（xunit）里 `Quaternion.LookRotation/AngleAxis/Euler` **与 `Matrix4x4.TRS`（2026-10-11 实测补登）**
   一调即抛 `SecurityException` ⇒ 纯核心/可测代码一律纯算术（`TileTangentFrame` 教训）；
   ⇒ **要测矩阵/四元数就先把"纯算术接缝"抽出来**（样例 = `ShipModelRenderer.PartViewTransform`：返回位置/尺寸两个 Vector3，
   矩阵构造留在只跑游戏的那一行）。
3. **自转符号不许手写**：唯一权威 = `SurfaceFrame.EciToFixed/FixedToEci`；姿态相位从基向量的像反推（矩阵列），写死 `Ry(±ωt)` 踩过（近档 tile 消失事故）。
4. **GUI 相位里 GL/`DrawMeshNow` 是 no-op**：离屏烤图 = 临时正交相机 + `CommandBuffer` + `cam.Render()`；回读 `RenderTexture.active` + `ReadPixels`；释放顺序 render → 摘 → release → `targetTexture=null` → 销毁相机（乱序 ⇒ `_unity_self` 红字）。
5. **Standard 材质剔背面**：自建网格绕序按"径向法线 vs 叉积"定；错了的病症 = "日志说画了 N 个、屏幕全空"。
   （补丁网格是**双面发** triangle 的正面用法：绕序不赌，同色 + 不混合 ⇒ 无副作用。）
6. **运行时对象显式销毁**；清理口**不许吞持久数据**（销毁烘焙图 = 收起 PFView 就丢成果，踩过）。
7. **补丁的三条专属口径**（补丁区域那批，别踩）：
   - 旁挂图名带 `_patch`，且加载时**必须正方形**（旧整球图是 2:1 ⇒ 自动忽略；拿错图当补丁画的症状 = "地形错位"）；
   - 补丁网格的径向外扩 ε **必须大于网格弦高**（`PatchEpsilon` 就是干这个的；小了 ⇒ 环心缩进基底球、基底贴图一片片透出来）；
   - 补丁与基底球**共用同一个 TRS 矩阵**（顶点都在"半径 0.5 的方向空间"）—— 自己另造一套坐标就会远景挪位时错开。
8. **细节（山/河/路）三条专属口径**（19:11 那批）：
   - **CPU 合成**（画进回读像素）—— 别再往"用原版世界材质渲染"那条路上摸：它们在世界相机那条路才有保证，
     而 CPU 画法顺带换来"细节全可 headless 测"；
   - **山不许有光向**：昼夜由太阳方向光给，往贴图里烘固定光向 = 与终止线打架（`ApplyRelief_DirectionFree_IsRadiallySymmetric` 钉着这条）；
   - **细节在两条自检之后画**（自检数的是"地形画上了没有"，细节会把它改花）；补丁图**必须带 mipmap**（细线远景会闪）。
9. **画"带子"（河/路）的四条血泪**（19:29 那批，症状 = 用户实测"一节一节"）：
   - **按层两遍画，不许逐段两层画**：逐段"岸→芯"会让后一段的岸压住前一段的芯 ⇒ 拐弯处一段深一段浅
     （判据：`TwoPassLayerOrder_CoreWinsAtJoints_InterleavingBreaksIt` —— "凡被芯覆盖的像素最终必须是芯色"）；
   - **要纯色就别半透明**：半透明带会把底下的山体明暗透出来（沿程一段深一段浅），且重叠处二次混色；
     不透明的额外好处 = 重叠**幂等**；
   - **别假设链数据对称**：河/路的链通常两边各存一份（据此去重），但对面没存回时本侧必须画，否则每两格一个缝；
   - **细线要够粗**：一格 ~8 px 上画 1–3 px 的线，远景一进 mip 就被平均值化掉（看起来断断续续）⇒ 整体加粗一档。
10. **改贴图的两条顺序/生命周期纪律**：`Compress(true)` 必须在 `EncodeToPNG` **之后**（压缩后 CPU 像素取不回来）；
    **卸载必须有读回来的路**，且只卸"盘上有副本"的那种（`UnloadReloadable`：PFView 收起即放显存，旁挂 PNG 负责重载）。

    （盘缘 clear color / 盘内众数 / 亮度比）—— **"看起来不一致"先量出两个数，再决定改哪儿**（本次就是量出"亮度比 0.98 没问题、色相不同"，
    才定位到"拿调制细节图当颜色图"）。⚠ 顺带：`layer.Def.backgroundBiome` 那类**世界着色器的调制贴图不是颜色图**，
    要"颜色"就从**数据区里真实使用的 biome**去取（`ResolveBaseTexture` 的口径）。
17. **⭐ 画的不一定是材料上那个颜色**（2026-10-11 00:47，本线最贵的一条教训）：
    `DrawCelestialSphere()` 会往 **MaterialPropertyBlock 里写 `_Color`** ⇒ **材料上设的 `_Color` 会被覆盖**。
    凡在这条路上传了 `Color.white`，材料里的 `SurfaceReflectance`（0.20）就等于不存在 ⇒ 那个物体比同材料的别人**亮 5 倍**
    （"反射率不一致"从第一天起就是这个；去掉贴图后直接变**纯白**）。
    ⇒ 规矩：**同一材料的物体，绘制时传的 tint 必须与材料自身的 `_Color` 同值**（现在统一走常量 `SurfaceTint`）；
       诊断"某个物体亮得不正常"时，**先看绘制路径有没有覆盖 `_Color`**，别先怀疑贴图/颜色空间。
18. **颜色这一族问题的两条铁律**（2026-10-11 00:40 收口）：
    ① **凡"颜色"一律标清是"显示色"还是"线性值"**：Linear 工程里 `Material.color`/`Camera.backgroundColor` 吃**线性值**，
       显示色要过 `PFViewSurfaceBake.ToRenderColor`（`GammaToLinearSpace`；Gamma 工程直通）。日志里永远打 `activeColorSpace`。
    ② **自检必须同口径比**：拿**线性值**去比**像素字节**会得出 `1.00 ✓` 的假绿（踩过）——要比就比**存盘像素 vs 存盘像素**。
    ③ 顺带：`layer.Def.backgroundBiome` 的贴图是**世界着色器的调制细节图**（不是颜色图）；要"颜色"就从**数据区真实用的 biome**取，
       或者干脆由 Def 指定（现在基底球走的就是 Def 指定这条路）。
19. **太阳/光照只有一个权威**（2026-10-11 01:01）：**世界视图、地图昼夜、PFView 三处必须同源** = `GenCelestial.CurSunPositionInWorldSpace()`
    （本 mod 的 `CalendarAndSunPatch` 已把它改成 physicsTick + 天体自转周期口径）+ **固连→惯性**用 `PFViewBodyRotation`（与地表贴图同一个旋转）。

20. **太阳/星空的画序口径**（2026-10-11 01:29）：**层次用画序表达，不用深度**——`星空盒 RenderQueue.Background(1000)` →
    `太阳盘 1900` → 场景 2000+ ⇒ "除星空外任何东西都能遮挡太阳"是**确定性**的（后画覆盖先画），且**不写深度、不做远裁剪**。

27. **⭐ 渲染时间轴是"阶梯"——快相对运动在高于 tick 率的帧率下就是一格一格跳（2026-10-12，"别的航天器抖"的根）**：
    `TimeScaleManager.GetPhysicsTickSafe()` 由**整数** `TicksGame` 推出 ⇒ 每个**真实 tick 只前进一步**；而渲染跑在帧上
    （帧率常高于 tick 率）。于是"每 tick 走多少"直接决定观感：两台站不同轨道时相对速度可达 **km/s** ⇒ 每 tick 相对位移上千米
    ⇒ 在几百 km 外就是**零点几~几像素/格**的跳动 = 用户报的"抖"（**大小形状不变、只有位置在跳** 是它的签名）。
    · **修法 = 连续渲染时钟**：`TimeScaleManager.GetRenderTick()` = 物理 tick + **子 tick 相位**（按真实帧时长实测、滑均；
      相位**减去**走过的 tick 数、暂停/掉帧夹住）——只做**相位平滑**，平均值仍严格等于物理 tick。
    · **消费侧要有"任意实数 tick 的取位函数"**：圆轨 `GetCircularPositionAtTick(double)` 本就是解析的（注释写着"支持子tick"）；
      积分轨（物理步边界才更新，每 2 tick 一步）按速度外推 `pos + v·Δt`（Δt 零点 = `SpaceGameComp.LastPhysicsStepTick`）
      ——与射弹那条"渲染位置解析化"同一手法。
    · ⛔ **原点与物体必须同钟**（哪怕只差一个来源，相对位置照样跳）；**判"抖/闪"先问"它是按什么时间取的位"**，
      别一上来怀疑 shader/深度（本线为这个误判花过两轮）。读数：`[PFView·抖动]`（帧间位移 平均/最大/停滞帧比例）。
