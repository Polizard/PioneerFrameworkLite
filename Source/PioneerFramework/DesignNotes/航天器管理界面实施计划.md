# 航天器管理界面实施计划

> 状态：待审批
> 日期：2026-08-21
> 性质：正式计划案。本阶段**只做规划，不实现代码**。
> 本文档将作为后续开发的基准；审批通过后再进入实现。

---

## 1. 背景

当前 PFL 地面装配与发射存在两条割裂链路：

- 原版 TransportPod 发射链路。
- PFL 入轨/舱内口袋地图链路。

火箭 Gizmo 与发射台 Gizmo 太多且分界不清；缺少一个统一的“航天器管理”入口来承担设计、装载、发射方式、轨迹规划等完整工作流。

---

## 2. 目标

建立一个**统一航天器管理界面**，从发射台进入，管理当前发射台上的这一艘航天器：

1. 设计航天器。
2. 规划发射方式（原版 / PFL 入轨）。
3. 规划发射轨迹（PFL 首版：目标高度 + 自动圆轨化）。
4. 统一管理舱内进入、装载、人员/物品转移。
5. 收敛火箭与发射台 Gizmo，避免双入口交错。

---

## 3. 范围

### 本期范围

- 发射台 Gizmo 作为“航天器管理”唯一入口。
- 管理范围：**当前发射台上的一艘航天器**。
- 设计 UI：**第一阶段参数表单**，可视化布局后续再做。
- 舱室类型进入设计页，由它决定是否生成舱内口袋地图。
- 舱内地图暂定 5×5，固定出口，并与火箭地面位置连接。
- 采用原版 `MapPortal` / `PocketMapExit` / `Dialog_EnterPortal` 机制实现真正登船。
- 原版目的地选择仍由原版世界目标选择器完成。
- 航天舱室原版着陆后生成持久乘员舱 Building 并重连口袋地图。
- 火箭 Gizmo 只保留“进入火箭舱内”；其余操作收入管理界面。

### 本期不做

- 可视化拖拽设计布局。
- 全殖民地/在轨航天器总列表。
- 已着陆乘员舱的再次发射。
- PFL 着陆/返回地面系统。
- 旧存档兼容（当前开发阶段无下游内容）。
- 正式 DMS:NF Def 与内容解耦（当前全部在 PFL 内开发，解耦后续工作）。

## 4. 术语

| 术语 | 含义 |
|------|------|
| 航天器 | 当前发射台正在管理的完整项目：设计、建造、装载、发射、轨迹 |
| 乘员舱 | 火箭顶部的载人舱段；在航天舱室原版着陆后成为持久 Building |
| 普通运输仓 | 无舱体类型；可 PFL 入轨，但无舱内口袋地图 |
| 航天舱室 | 有舱内口袋地图类型；可 PFL 入轨，也可原版着陆并保留乘员舱 |
| 登船口 | 完工后的火箭本身，在地面代表舱内入口 |
| 舱内出口 | 5×5 口袋地图中的固定出口格，与火箭地面入口格对应 |

## 5. 舱室类型与发射方式限制

舱室类型**不直接决定发射方式**，只决定是否拥有舱体和着陆后行为。

| 类型 | 舱内口袋地图 | PFL 入轨 | 原版 TransportPod | 原版着陆后 |
|------|--------------|----------|-------------------|------------|
| 普通运输仓 | 无 | ✅（无舱体） | ✅ | 按原版运输仓处理：内容物释放，载具溶解 |
| 航天舱室 | ✅ 5×5 | ✅ | ✅ | 目标地格生成持久乘员舱 Building，重连口袋地图 |

### 说明

- 普通运输仓也可以 PFL 入轨，但**不生成舱内地图**。
- 航天舱室两种发射方式都允许。
- 后续如果限制收紧，再调整此矩阵。

## 6. 统一航天器管理界面

### 6.1 入口

- **发射台 Gizmo：“航天器管理”**
- 只管理当前发射台上的这一艘航天器。
- 火箭 Gizmo 不再承担设计/发射/轨迹/装载等管理职责。

### 6.2 窗口结构

建议使用标签页：

| 标签页 | 功能 |
|--------|------|
| 总览 | 当前航天器状态、设计摘要、建造进度、燃料/载荷/人员概况 |
| 设计 | 型号、舱室类型、Part、载荷、框架尺寸、是否生成舱内地图 |
| 施工 | 材料需求、蓝图/框架/完工状态 |
| 舱内 | 进入舱内、装载人员/物品、舱内检查 |
| 发射 | 发射方式选择、条件校验、发射确认 |
| 轨迹 | PFL 目标高度 / 自动圆轨化；原版模式说明由原版目标选择器处理 |

### 6.3 设计页（第一阶段：表单）

- 类型选择：
  - 普通运输仓
  - 航天舱室
- 型号/模板。
- Part 列表：推进器、储罐、分级等。
- 载荷配置：类型、数量、安装位置。
- 框架尺寸。
- 是否生成舱内地图：由舱室类型自动决定，普通运输仓不允许生成。

第二阶段再做可视化布局。

## 7. 登船与舱内转移（采用原版 MapPortal 模式）

参考原版实现：

- `MapPortal`
- `PocketMapExit`
- `PortalContainerProxy`
- `Dialog_EnterPortal`
- `JobDriver_EnterPortal`
- `LordJob_LoadAndEnterPortal`

### 7.1 映射到 PFL

| 原版对象 | PFL 对应 |
|----------|----------|
| `MapPortal` | 火箭 Building（登船口） |
| `PocketMapExit` | 舱内 5×5 地图出口 |
| `PortalContainerProxy` | 火箭的物品转移代理 |
| `Dialog_EnterPortal` | “进入火箭舱内”打开的装载/登船窗口 |
| `JobDriver_EnterPortal` | pawn 真正走进舱内的 Job |
| `PocketMapUtility` | 生成/销毁 5×5 舱内地图 |

### 7.2 流程

1. 玩家点选火箭。
2. 火箭 Gizmo 只有“进入火箭舱内”。
3. 打开类似 `Dialog_EnterPortal` 的窗口：
   - 选择要进入舱内的 pawn。
   - 选择要搬入舱内的物品。
4. 确认后，通过原版搬运/进入 Job：
   - pawn 走到火箭登船口；
   - 完成进入动作；
   - pawn 被转移到舱内 5×5 地图出口格；
   - 物品通过 `PortalContainerProxy` 投放到舱内出口附近。
5. 舱内也有 `PocketMapExit`，玩家/pawn 可从同一出口返回地面。

### 7.3 舱内地图

- 固定尺寸：5×5。
- 只有一个出口格。
- 出口格与地面火箭建筑入口格一一对应。
- 舱内生成内容仍待后续船体轮廓设计，本期仅保证“出口 + 可进入/可携带”。

## 8. 发射管理

### 8.1 发射方式

管理界面“发射”页选择：

- **原版 TransportPod 发射**
  - 管理界面只发起。
  - 目的选择仍由原版世界目标选择器完成。
- **PFL 入轨发射**
  - 使用目标高度参数。
  - 自动执行两段式圆轨化/入轨。

### 8.2 轨迹规划（第一阶段）

- PFL 首版只规划：
  - 目标轨道高度。
  - 近圆轨道。
  - 自动圆轨化。
- 后续再扩展：轨道面、倾角、远地点、转移/交会等。

### 8.3 调试按钮

- 火箭 Gizmo 不再放“强制发射 PFL (调试)”。
- 强制发射按钮移入航天器管理界面的“发射”页，仅在 dev 模式/调试构建下显示。

---

## 9. 原版着陆后的持久乘员舱

### 9.1 普通运输仓

- 原版发射后按原版 TransportPod 行为：
  - 内容物释放到目标地格。
  - 载具按原版逻辑处理。
  - 不生成持久乘员舱，不保留口袋地图。

### 9.2 航天舱室

- 原版发射并着陆后：
  - 目标地格生成持久乘员舱 Building。
  - 该乘员舱重连原 5×5 舱内口袋地图。
  - 它不是一次性运输仓，不会像原版那样溶解。
  - 玩家可以继续进入舱内。
- 乘员舱自身提供 Gizmo：
  - **“撤离乘员舱并拆解”**
  - 指派 pawn 对 Building 执行拆解工作。
  - 可以直接走原版拆解逻辑，不另写复杂逻辑。
- 落地后管理权转移到乘员舱：
  - 原发射台不再远程管理该航天器。
  - 本期乘员舱仅作为可进入的持久建筑存在，不提供再次发射。
- 乘员舱被摧毁时：
  - 物品与 pawn 按 `PortalContainerProxy` / 掉落方式转移到乘员舱所在位置周边。
  - 在轨状态下的摧毁暂按销毁处理，后续再定。

## 10. 数据模型设想

新增/扩展“航天器项目”聚合对象，统一保存：

```text
SpacecraftProject
├── 基础信息
│   ├── 型号/模板
│   ├── 舱室类型：普通运输仓 / 航天舱室
│   └── 是否生成舱内地图
├── 设计数据
│   ├── RocketDesignSpec
│   ├── Part 列表
│   ├── 载荷列表
│   └── 框架尺寸
├── 建造状态
│   ├── 设计中 / 建造中 / 已完工
│   └── 关联地面火箭/蓝图/框架
├── 舱内数据
│   ├── 舱内地图 ID
│   └── 出口/登船口绑定
├── 发射数据
│   ├── 发射方式：原版 / PFL
│   ├── PFL 目标高度
│   ├── PFL 自动圆轨化参数
│   └── 原版目的地（由原版目标选择器处理）
└── 着陆后状态
    ├── 持久乘员舱 Building
    └── 是否已转移管理权
```

当前已有对象继续承担底层职责：

- `CompAssemblyPad`：发射台状态机。
- `CompRocketPocketMap`：火箭舱内地图关联。
- `RocketLaunchManager`：统一发射调度。
- `LaunchService`：PFL 入轨执行。
- `CompLaunchable`：原版发射执行。

## 13. 验收标准

1. 发射台 Gizmo 打开“航天器管理”，管理当前发射台上的航天器。
2. 设计页可选择普通运输仓/航天舱室；普通运输仓不生成舱内地图，航天舱室生成 5×5 地图。
3. 火箭 Gizmo 只剩“进入火箭舱内”。
4. “进入火箭舱内”能打开类 `Dialog_EnterPortal` 窗口，pawn/物品通过 Job 真正进入舱内。
5. 发射页可选择原版/PFL，原版由原版目标选择器接管，PFL 使用目标高度并自动圆轨化。
6. 航天舱室原版着陆后生成持久乘员舱、重连口袋地图；普通运输仓按原版处理。
7. 落地乘员舱提供“撤离乘员舱并拆解”，拆解时物品/pawn 转移到周边。
8. 不兼容旧存档；当前全部在 PFL 内开发。
9. 构建、现有测试、Def 校验保持通过。

## 15. 架构改进与视觉风格升级建议

> 状态：调研结论与升级方向，待审批后落入 P1+ 阶段实施。
> 日期：2026-08-22
> 调研对象：DMSNF `Dialog_DMSColonialOffice`（殖民办公室）**架构实现**（仅作架构对比参考）、复古未来主义 / 瑞士国际主义 / 磁带盒未来主义三种设计风格 DNA、RimWorld 原版 UI 视觉规范。

### 15.1 架构改进建议（基于殖民办公室对比）

将当前 `Window_SpacecraftManagement` 的 `enum Tab + switch` 模式向殖民办公室的 `IPage + Dictionary<Section, IPage>` 多态分发模式靠拢，以满足"开放-封闭"原则。当前架构在新增第 7 个标签页时必须修改 Window 类本身，未来扩展受限。

| 改进点 | 当前实现 | 建议目标 | 优先级 |
|--------|---------|---------|--------|
| 页面组织 | `private enum Tab` + 6 个 `DrawXxxTab(Rect)` + `switch` | `interface ISpacecraftPage { string Title; void Draw(Rect, Window_SpacecraftManagement host); }` + `Dictionary<Section, ISpacecraftPage>` 多态分发 | P1+ |
| 缓存策略 | 每帧 `TryResolveRocketAndContext` 遍历 thingGrid；无文字测量缓存 | 引入"指纹检测"（`lastRocketFingerprint` / `lastDesignFingerprint`），仅在状态变化时重算布局与查询 | P1+ |
| 生命周期 | 依赖 `Window` 默认行为；无 PreOpen/PostClose 自定义 | override `PreOpen` 集中刷新缓存 + 暂停 TimeSpeed；override `PostClose` 清理 `altitudeInputBuffer` 等局部状态 | P1+ |
| UI↔后端边界 | `protected virtual OnXxx()` 占位（继承多态） | 保留 `OnXxx` 虚方法契约，但在 Page 类内调用 `host.OnXxx()` 解耦 Page 与具体业务 | P2 |
| 类封闭性 | `public class` + `protected virtual`（开放继承） | 保持开放式；与殖民办公室 `internal sealed` 不同，PFL 允许下游 Mod 子类化扩展 | 不变 |
| 窗口实例 | 每发射台 Building 一个独立实例 | 保持单 Building 局部管理定位；未来扩展"全殖民地总览"时另起 `MainTabWindow_SpacecraftFleet` 而非污染本类 | 不变 |

> ⚠️ 架构改进**不应在 P1 期同步重写**已完成的前端骨架，避免破坏已通过的 §13 验收。建议作为 P1+（P1 完成后的小型重构）独立提交。

### 15.2 视觉风格定位

**拒绝烂俗科幻感**——不使用 2000 年代抛光金属 + 蓝紫渐变 + 霓虹流光的"赛博朋克 SaaS"美学。

**采用三风格混合**（PFL 作为多下游 Mod 共用框架，确立自身视觉身份，同时与 RimWorld 原版 UI 保持和谐）：

| 风格 | 在 PFL 航天器管理界面中的体现 | 占比 |
|------|-------------------------------|------|
| 瑞士国际主义 Swiss International | 12 列基础栅格、8px 基线节奏、单一 grotesk 字体、左对齐参差、留白作为构图元素、信息层级靠字号字重而非颜色 | 50% |
| 磁带盒未来主义 Cassette Futurism | 暖调近黑背景（CRT 荧光屏辉光）、等宽终端字体用于数字读数、L 形角标、横向状态条带、磁带卷轴式装饰 | 30% |
| 复古未来主义 Retro Futurism | 暖铜/冷青/军绿强调色（替代赛博朋克霓虹）、原子时代几何符号（圆/抛物线/星爆）、火箭轨迹线装饰、网点纹理 | 20% |

**视觉关键词**：工业仪表盘 + 1979 年《异形》Nostromo 控制室 + 1950 年代 NASA 控制台 + Helvetica 排印纪律。

| Title | `GameFont.Medium` | 16 | 600 | 标签页标题"航天器总览"等 |
| Body | `GameFont.Small` | 13 | 400 | 正文、状态字段值 |
| Label | `GameFont.Tiny` | 11 | 500 | 字段标签"发射台状态"等 |
| Caption | `GameFont.Tiny` | 11 | 400 | 元数据、占位提示、调试日志 |
| Mono | `GameFont.Tiny` | 11 | 400 | 数字读数（PocketMapId、坐标、高度） |

> 数字读数（如 PocketMapId #12345、坐标 (x,y,z)、目标高度 400.0 km）使用等宽对齐风格——通过 `Text.CurFontStyle.font` 切换到 `Courier New` 或保持 `GameFont.Tiny` 但用固定宽度 Rect 对齐。磁带未来主义要求"数字像读数而非文本"。

### 15.5 间距与栅格系统（瑞士国际主义纪律）

| 常量 | 值 | 用途 |
|------|-----|------|
| `SafePadH` | 32px | 窗口左右安全内边距 |
| `SafePadV` | 24px | 窗口上下安全内边距 |
| `SectionGap` | 8px | 区块间距（标题/列表/按钮组之间） |
| `RowHeight` | 22px | 信息行高（标签+值） |
| `RowGap` | 4px | 行间额外间距 |
| `ButtonHeight` | 32px | 标准按钮高度 |
| `ButtonGap` | 12px | 按钮组内间距 |
| `CardPad` | 12px | 卡片内边距 |
| `BaselineStep` | 8px | 基线节奏（所有 y 坐标尽量是 8 的倍数） |
| `GridCols` | 12 | 内容区虚拟 12 列栅格（手算划分，不实装 Grid Layout） |

> 所有 y 坐标对齐到 8px 基线节奏；所有 x 坐标对齐到 12 列栅格的列宽。这是瑞士国际主义的"数学网格"纪律在 IMGUI 中的手算实现。

### 15.6 装饰元素风格（磁带盒未来主义 + 复古未来主义）

| 元素 | 实现 | 用途 |
|------|------|------|
| L 形角标 | 四角 L 线（inset=6, arm=14），程序化绘制 | 主内容区四角，磁带卡座铬色感 |
| 横向状态条带 | 3px 实色条 + 主色左边条（`DrawSpecBar` 风格） | 总览页"发射台状态"行、施工页状态机当前态 |
| 网格线背景 | `DrawLightGrid` 浅色 1px 步进 40px | 轨迹页背景，磁带未来主义线框网格感 |
| 序号标签 | `#01` / `#02` 等两位数前缀 | 设计页 Part/载荷列表项 |
| URL 栏历史 | 顶部 26px 条，显示"装配台 #3 → 航天器管理 → 总览"路径 | 磁带未来主义"已录路径"感 |
| 原子时代符号 | 圆 + 抛物线 + 星爆 SVG 风格图标（不实装图片，纯 IMGUI 绘制） | Tab 栏图标、按钮装饰 |
| 网点纹理 | 1px 点阵步进 8px 半透明 | 卡片背景，复古印刷感 |

> 不使用外部图片/Texture2D 资源；所有装饰元素用 `Widgets.DrawLineHorizontal` / `DrawLineVertical` / `DrawBoxSolid` / `GUI.DrawTexture(BaseContent.WhiteTex)` 程序化绘制。

### 15.8 不采用的设计

- **不采用** 2000 年代抛光金属 + 蓝紫渐变 + 霓虹流光的"赛博朋克 SaaS"美学
- **不采用** Synthwave 落日 + 棕榈树 + 紫粉霓虹的"夜驰"美学
- **不采用** Y2K 干净铬凝胶 + 数字乐观主义美学
- **不采用** Star Trek 银河联邦无菌洁净感

理由：上述风格与 PFL 的"工业拖网渔船式航天工程"定位不符，且偏离 RimWorld 原版的实用主义暗色 UI 基调，会破坏 PFL 作为多下游 Mod 共用框架的视觉普适性。
