### 1.1 碰撞宽相性能复核（2026-10-19 上午）

用户问“碰撞是不是优化又不行了”。先量后改：

- 旧读数：日志里 `碰撞=1106µs`（Debug + PerfProbe 探针步的整段值；含 part AABB 收集/组级判定，不等于纯碰撞）。
- 台架（Release，`CollisionContactBench`，256×256 长堆叠）：

| 项目 | 优化前 | 优化后 |
|---|---|---|
| `CollectPartContacts`（每轮位置投影都调） | 445 µs | **78–87 µs** |
| 最深 part 对（生产路径） | 420–429 µs（SAP 事件排序） | **70–71 µs**（有序双指针） |
| `CollisionSolver` 8 接触 × 6 迭代 | 8.2–9.4 µs | 不变 |

改动（都在 `CombatManager`，语义不变）：

1. **裁剪盒预过滤缓存**：`contactFilterA/B` 字段；`CollectPartContacts(..., filterA, filterB)` 先用组交集裁剪盒把 part 缩到少量，再窄相；逐对 `OverlapsClip` 从 n² 次降到 n 次。
2. **有序双指针接触收集**：`TryCollectContactsBySortedSweep`。part 列表沿扫掠轴本来有序（长堆叠按 Y 收集）时，双指针 O(n+k) 枚举区间相交对；不有序才退回 SAP。SAP 仍保留（`CollectContactsBySweepAndPrune`）。
3. **有序双指针最深对**：`DeepestBySortedSweep`。同样先试有序双指针；列表不单调才走原 SAP。结果仍交 `ConsiderPartPair`，并列深度按 `(A.Order,B.Order)` 裁决 ⇒ 与嵌套/SAP 逐位一致。
4. 抽出 `TryPartContact` / `AddContact`，供嵌套、SAP、有序三路共用。

对拍：`CollisionBroadphaseEquivalenceTests` **8 条全过**：有序命中、乱序回退、随机单调（升/降），最深对/接触集合与 `forceNested` 基线一致（深度、接触点、法线逐位同）。

### 1.2 10 km/s 漏撞修复（2026-10-19 中午）

**症状**：10 km/s 演示日志 `[碰撞枚举] t=484 距离=19200m`，之后 319200/619200/… 持续增大，没有 `[ShipCollision]`/`[爆炸]`——整场漏撞。

**根因（两条）**：

1. 新组第一次被 `SyncAllShipsToGrid` 看到时已经在本物理步末尾 ⇒ `shipPrevPositions` 为空，首步扫掠段退化成当前点；2 s × 10 km/s = 20 km，一步直接跨过 800 m 间距。
2. 组级球快筛只看**步末距离**（19.2 km ≫ 半径和 ~14 m）⇒ 在扫掠判定之前整对 `continue`。导弹对本来有豁免，普通船没有。

**修复**：

- `SpaceGameComp.RegisterGroup` 在确认入战斗网格后调 `CombatManager.NoteGroupSpawned(group)`：把**出生位置**记入 `shipLastPositions`（已有记录不覆盖），首步 `prev` 即出生点。
- 球快筛改为 `SegmentHitsSphere(relStart, relEnd, rr²)`：看相对路径线段到原点的最近距离，不再用步末点。导弹豁免保留。
- `OnGroupDestroyed` 顺手清 `shipPrevPositions` / `groupCollisionCache`（原来只清 `shipLastPositions`）。
- 纯函数台架 4 条：穿越原点命中、路径擦过半径内命中、半径外不命中、静止在外不命中。

**游戏内复验（交付件 `3088C056…`）**：

- 10 km/s：`[TOI诊断] prevRel=(800,0,0) curRel=(-19200,0,0) stopRel=(8.1,0,0) n=(1,0,0) vRel=10000 ⇒ 爆炸`；`[爆炸] 半径=13848m 能量=2.5e10J 损伤Part=2`。

- 80 m/s 之后 300 步汇总：平均 17.9µs、最慢 37.9µs、>2000µs 尖峰 0 步。

## §2 碰撞系统现状（代码级）

### 2.1 主入口与顺序

`SpaceGameComp.GameComponentTick` → `CombatManager.OnPhysicsStepCompleted`：

```
UpdateProjectiles()
UpdateWeapons(currentTick)
SyncAllShipsToGrid()          // 更新细网格/上一步位置
CheckShipCollisions()         // 船-船（CombatGrid.EnumerateShipPairs）
ManageProjectileTimeScale()   // 射弹在飞/导弹终末 → Combat 档
```

`SpaceGameComp.UpdateAllMovements` 的物理步长：

- `dtSeconds = UPDATE_INTERVAL_TICKS(2) × TimeScaleManager.PhysicsSpeedMultiplier`
- Normal = 2 s/步；Combat = 1/60 × 2 = 0.0333 s/步；Fast = 8 × 2 = 16 s/步（`SubSteps=8` 时每子步 2 s）。
- 物理步固定每 2 个真实 tick 跑一次 ⇒ **每秒 30 步**，不随流速变；降速只改 dt，不改步频。

### 2.2 CombatGrid（区块系统）

文件：`Source/PioneerFramework/SpatialIndexing/CombatGrid.cs`

- `FINE_CELL_SIZE = 20000.0`（20 km）。
- 每帧 `Dictionary<int frameId, SystemGrid>`；`SystemGrid.cells: Dictionary<(cx,cy,cz), FineCell>`。
- **Group 多格注册**：`CoverBoxOf(min,max)` 用 `floor(min/cell)`、`floor(max/cell)` 得到闭区间格盒；`AddShip` 把 Group 加进格盒覆盖的每一个 `FineCell`；`shipCoveredCells[ship]` 保存 6-int `CoverBox`。
- **扫掠覆盖（2026-10-19 续轮）**：`shipCurrentCells` 存上一步当前覆盖格；`UpdateShipPosition` 注册盒 = `Union(上一步当前格, 本步当前格)`，旧扫掠格不累积；`SettleSweptBox` 在停船后收缩回当前格；注册盒体积 >4096 视为传送、只注册当前格。
- `EnumerateShipPairs`：遍历 `shipCoveredCells`（每艘船一次）与其**扫掠覆盖格**内的船；`pairScratch` 按 GroupId 对去重。复杂度 O(Σ 船覆盖格 × 格内船数)，不是 `GetAllGroups()` 的两两循环。
- 射弹/射线：`WalkSegmentCells` 动态 DDA，沿线段走格，`maxSteps = 三轴格差 + 2`，不固定 3 步。

**当前多格事实**：

- 普通 40 m 船通常 1 格；560 m 长的 256 件船也还是 1 格（20 km 格），除非压边界。
- 超大站体/环段或 AABB 跨边界的船会占多格；`floor(max)` 包含边界格，所以 40 m 船压在边界上也可能注册两格。
- 格盒是矩形过覆盖：长条/L 形/斜放 Group 会圈进空格；下游球/扫掠/SAT 剪掉假候选。

### 2.3 船-船检测链

`CombatManager.CheckShipCollisions()`（`CombatManager.cs:864`）：

```
foreach (a,b) in combatGrid.EnumerateShipPairs()
  if (!active/collidable/same) continue
  ca = GetOrBuildCollisionCache(a); cb = ...
  prevPa = ca.hasPrev ? ca.prevPos : pa
  prevPb = cb.hasPrev ? cb.prevPos : pb
  relStart = prevPb - prevPa; relEnd = pb - pa
  if (!SegmentHitsSphere(relStart, relEnd, (ra+rb)²)) { 导弹豁免; continue }
  bMin/bMax = B 当前盒沿 -relDelta 扩展（相对扫掠盒）
  if (!AabbOverlap(aBox, sweptB)) continue
  导弹分支 / 跳帮分支
  if (当前盒不重叠) ResolveTunneled(...)
  else TryFindDeepestPartPair(...) → CollectPartContacts → ResolveContacts / ResolveImpact
```

关键常量（`CombatManager.cs:48–60`）：

- `CollisionExplosionSpeedThreshold = 50 m/s`：≥50 走真爆炸，<50 走撞击等效。
- `CollisionRestitution = 0.2`；`CollisionRestitutionMinSpeed = 1.0`（低于 1 完全非弹性）。
- `CollisionFriction = 0.25`（生产多接触；单接触旧路径不启用）。
- `CcdPartRefineMaxStepMeters = 2000`：一步相对位移 >2 km 跳过 part 级采样，直接组级停点/响应。
- 爆炸：`R = 8000 + 2·E^(1/3)`，`D0 = 0.005·√E`，`Δv = 500·√E·falloff/mass`；撞击爆炸只损伤，不再施加径向爆风（§10 裁）。

### 2.4 窄相 / 流形 / 求解

- `TryFindDeepestPartPair`：组 AABB 交集裁剪 → 嵌套（小列表）/ 有序双指针（大列表且单调）/ SAP（乱序大列表）/ BVH 仅 `forceBvh` 台架。
- `CollectPartContacts`：最多 8 个接触点，保留最深；形状解析（Sphere–Sphere、Sphere–Capsule、Capsule–Capsule、Sphere–Box、Cylinder–Box 五采样胶囊近似）→ OBB SAT → AABB；`TryPartContact` + `AddContact`。
- `CollisionSolver.Resolve`（`Base/Core/CollisionSolver.cs`）：顺序冲量，含 `ω×r` 接触速度、法向恢复、库仑摩擦、`stackalloc` 数组、无堆分配。
- `ResolveContacts`（`CombatManager.cs:2950`）：先 `CollisionSolver.Resolve(... iterations:6)`，再做最多 8 轮位置投影；每轮重新 `CollectPartAabbs` + `CollectPartContacts` + `SeparatePositions`；仍有接触则 `SeparateByGroupAabbAllAxes` 清残余。
- 位置分离 `SeparatePositions`（约 `:2780`）：只改 `CurrentOrbit.positionSystem`（质量反比），同时刷新 `shipPrevPositions/shipLastPositions`；**不改实体局部位置/姿态**。
- `ResolveTunneled`（`:1272`）：组扫掠 TOI → `RefineTunneledStopToParts`（<2 km 内自适应 8..64 采样 + 8 次二分）→ `ApplyTunneledStop` → 按 vRel 走爆炸/撞击。
- `ApplyTunneledStop`（`:1387`）：圆轨先 `ExitCircularOrbit`，写位置，刷新 prev/last。

### 2.5 射弹命中

`CheckProjectileCollision`（`:566`）→ `CombatGrid.GetShipsNearProjectile` DDA → `CheckSegmentGroupHit`（`:649`）：

- 转为目标参考系（目标上一步位置回退 dt），相对线段；

射弹的连续线段检测本身是精确的（与线段长度无关），不受 10 km/s 影响；问题只在船-船配对。

## §3 正确性现状与已知缺口

### 3.1 跨格高速对漏配对（**已修 · 2026-10-19 续轮**）

**修前缺口**：`EnumerateShipPairs` 只覆盖**当前 AABB 共享格**。两船当前 AABB 分处相邻的两个 20 km 格、一步相对位移 20 km 相撞时，当前覆盖格不共享 ⇒ `CheckShipCollisions` 根本拿不到这对；后面的 `SegmentHitsSphere`/扫掠 AABB/TOI 都没机会执行。10 km/s 演示能过是因为 A 的 AABB 在 x≈1e9 恰好跨格边界，属几何巧合。

**修法（`CombatGrid`，只改宽相注册，不改碰撞响应）**：

- 每船保存 `shipCurrentCells`（上一步当前位置的 AABB 覆盖格）与 `shipCoveredCells`（本步注册格）。
- `UpdateShipPosition`：新注册盒 = `Union(上一步当前盒, 本步当前盒)`；只与上一步**当前**盒求并（不与上一步扫掠盒求并）⇒ 旧路径格在下一步自然移除、不累积。
- `EnumerateShipPairs` 遍历注册盒（语义从"当前覆盖"升级为"扫掠覆盖"）。完备性证明：平移 AABB 的扫掠体包含在两端 AABB 的轴对齐凸包内 ⇒ 路径交点所在格必在两者注册盒中。
- 停船收缩：`SettleSweptBox` 在"本步位置未变"时把扫掠格缩回当前格；同步器每步对未移动的船调用一次，无待收缩状态时 O(1) 早退。不收缩的话停船会永久保留最后一步的跨格格。

### 3.2 其他已知边界

- `CcdPartRefineMaxStepMeters = 2000`：>2 km 一步位移只做组级停点/响应；10 km/s 的 part 级精度不在当前口径。
- `RefineTunneledStopToParts`：samples = ceil(step/(2·minHalf))，夹 8..64；>64 回退组级；件数乘积 >4096 直接回退。
- Cylinder 不是独立形状枚举：用胶囊近似；Cylinder–Box 是 5 点采样（近似）。
- `ResolveContacts` 位置投影最多 8 轮，每轮重收集 part AABB；这是性能优化候选，不是正确性缺陷。
- 无通用“未来 N 步碰撞”预判；无船-船临近自动降速。

## §4 下一轮优化方向（§4.2 已实现；其余待做）

### 4.1 先做正确性台架（不改生产）

建议按顺序写只读台架/探针：

1. **相邻格 10 km/s 配对台架**：两船分处相邻 20 km 格，相对速度 10 km/s，一步跨过；当前实现应红。可加到 `CollisionBroadphaseEquivalenceTests` 或新的 `CollisionPairEnumerationTests`（需要 CombatGrid/游戏脚手架；若难以构造，先在游戏内用调试按钮把两船放到相邻格）。
2. **AABB 平移对拍**：同一多 part 组在 `P` 与 `P+δ` 收集 part 盒，逐字节比较 `box(P+δ) == box(P)+δ`；包含带姿态 part、多实体组、损毁残骸。
3. **CCD 采样对拍**：在采样 t 上比较“重新 `CollectPartAabbs(b, bp)`”与“缓存 `curB` 盒按 `bp-curB` 平移”的 `PartsOverlap`，必须逐位一致。
4. **密集格配对 oracle**：64/128/256 艘独立单 part 船同格；记录 `PairCandidates`、p99/最大步耗时；为后续格内 SAP 做基线。

现有 oracle：`CollisionBroadphaseEquivalenceTests`（8）、`CollisionManifoldTests`（11）、`CollisionSolverTests`（4）、`CollisionPartMathTests`、`CollisionSweptTests`、`CollisionToiTests`、32/32 复杂碰撞一键验收。

### 4.2 配对完备性修复（Phase 1，**已于 2026-10-19 续轮实现**）

> 实际实现 = 本节方案 + 两个必要补丁：**停船收缩 `SettleSweptBox`**（否则停船永久保留最后一步的跨格格）与 **传送体积上限 `MAX_SWEPT_CELLS=4096`**（否则位置跳变会注册数万格）。细节与台架见 §3.1；下面保留原始方案作设计记录。

**扫掠覆盖注册**，而不是固定 27 邻格：

- `CombatGrid` 每船保存 `currentBox` 与 `sweptBox`。
- `UpdateShipPosition`：
  - 新 `currentBox` = 当前组 AABB 的覆盖格；
  - 新 `sweptBox = union(旧 currentBox, 新 currentBox)`；
  - 注册差集：旧 `sweptBox` → 新 `sweptBox`；`currentBox` 更新为新盒。
- 下一步再用新的 current 重算 swept，旧路径格自然移除，不累积。
- `EnumerateShipPairs` 遍历 `sweptBox`；多格船、去重逻辑不变。
- 射弹仍走 DDA；旧路径格会多出“已离开”的假候选，`CheckSegmentGroupHit` 用当前实体 AABB 精确判，不会假命中。
- 成本：10 km/s、20 km 步约多 1–2 格；Fast 16 s 步约多 8 格；密集场景候选数上升，必须实测。
- 好处：不需要固定邻格半径；两船扫掠 AABB 有交集 ⇒ 必共享格 ⇒ 进入现有球/扫掠/TOI 链；响应/求解完全不动。

**不要**做“格内按当前 AABB 裁候选”——那会把扫掠跨步对（包括刚修好的 10 km/s）裁掉。格内裁剪必须用扫掠 AABB。

### 4.3 性能优化（Phase 2，先量后改）

按风险从低到高：

1. **位置迭代复用 part AABB**：`ResolveContacts` 进入投影前收集一次，之后按组位置平移；`SeparatePositions` 只改组位置，已静态确认不碰实体姿态/局部位置。预期减少多 part、迭代 2+ 轮的重复旋转/投影。
2. **CCD 采样复用**：B 侧 part 盒在 `curB` 收集一次，采样点按 `bp-curB` 平移；`RefineTunneledStopToParts` 只读状态，可证等价。
3. **密集格局部 SAP**：`EnumerateShipPairs` 每格内按扫掠 AABB 排序/扫掠，替代 ΣC(k,2) 两两产出；多格船仍按 GroupId 去重。注意必须用扫掠 AABB。
4. **Span/ref 微优化**：`PartAabb` 是大结构体，`List<T>` 索引器复制；接触收集/最深对改 `Span` + `ref readonly`；用 8 条宽相对拍 + 11 流形 + 32/32 验收做 oracle。
5. **暂不做**：位置投影 epsilon（留残余穿透，语义变化）、warm start（改冲量分配/物理结果）。要单独裁定。

### 11.16 2026-10-20：part 级 CCD 的 O(nA×nB) 改成三轴预排序 SAP

- **口径订正**：旧记录的“64/128/256 件最坏 0.76/1.47/5.4 ms”是**64 次采样的合计**，不是单次。当前 Release 复测 brute 单次 = **10.7 / 23.6 / 83.9 µs**，64 采样合计 = **0.685 / 1.507 / 5.371 ms**，与旧总账吻合。

- 修法（`CCCB281E…`）：
  1. `GroupCollisionCache` 在 relParts 重建时按相对 AABB 的 X/Y/Z min 预排序三份下标（含 `EntityPosition`；平移不改变顺序 ⇒ 每 epoch 建一次，所有 CCD 采样复用）。

  3. ≤8 件或缺排序时回退原全量；`nA*nB > 4096` 护栏保持不变（不改变现有 256/128 的行为）。
- Release 台架：64×64 最坏 **10.7 µs → 1.35 µs/次**；64 采样 **685 µs → 86.4 µs**（约 **7.9×**）。
