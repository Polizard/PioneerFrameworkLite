**设计已对齐（本次讨论结论）**：
- ✅ 燃料模型 = 直接接 dV 体系（`PropulsionData` + 工质注入，烧完 `RemainingDeltaV` 归零）

## 0.3 踩坑与经验教训（2026-09-07 实战沉淀，导弹闭环全链排障三天总结）

**"打不中"三层排障的最终顺序**：先验证**测量基准一致**（同 tick 同位），再怀疑控制律，最后才看几何——本次三个根因恰好按反序出现，每个都伪装成"制导缺陷"，各消耗多轮测试：

1. **RimWorld GameComponent tick 顺序无保证（最贵的一课）**：引擎 `Game.FillComponents` 反射收集全部 GameComponent 子类（`GenTypes.AllSubclassesNonAbstract` = `AllTypes.AsParallel().Where(...).ToList()`——**并行 LINQ 无 OrderBy，顺序无契约**，实测倾向全名字母序但不可依赖、可能随启动变化），物理推进（SpaceGameComp）恰好夹在制导（AVM）与碰撞（Combat）中间 → 同 tick 读到差一个物理步的位置（2s ≈ 5.5km @ 2753m/s），制导把导弹引向"旧位置看到的目标"而碰撞盒在别处——表现与"制导发疯/几何不可达"完全同形。**规则：凡"同 tick 读物理位置"的每物理步消费者，一律挂在 SpaceGameComp 推进完成后驱动（`OnPhysicsStepCompleted`），禁止各自 %2 自行 tick——修复不得依赖任何组件顺序假设。** 排查手段：制导日志带 tick+双方坐标，与碰撞日志同 tick 对照——一次定位"谁的位置旧"。
2. **离散采样孔（步末判据）**：碰撞链的球包围快筛用"步末质心距 > 半径和"拒绝——单步相对位移（958m @ 479m/s×2s）大于目标球区跨度（±57m）时整步穿越被漏掉；扫掠"并集盒"同理对端点间空洞无效。低速测试全过、高速必漏，最阴险。**规则：任何"离散端点判据"都要问一句"单步位移 vs 目标尺度"；高速对象用连续段检测（slab）+ 时间对齐复核，且复核必须在快筛**之前**或豁免快筛，否则永远没机会执行。**
3. **制导律的收敛带宽**：PN 视线率版（θ 饱和 20°）在横移目标（异轨交战常态）上横向修正带宽只有 900·sin20°≈308m/s < 实测横差 1000-1800m/s → 3-5km 处 tGo 3-7s 修不完必飞越。**规则：制导律要按"目标横移是常态"设计——横向相对速度直接归零（速度匹配）+ 接近率只加不减巡航，比"预测提前点"鲁棒；且转向率（20°/s）与指令周期（2s）的乘积决定了可收敛的视线旋转率上限，选型前先算带宽。**
4. **时间档位与调试日志的耦合**：Combat 档（1/60）下现实 tick 率不变（60/s），"无门控诊断日志 × 每物理步 × 每对"变成现实 30Hz 刷屏——8725 行/次测试直接拖垮内存。**规则：诊断日志必须带限频门控，使命完成即删；在慢动作档验证前先估算日志行数。**
5. **时间单位换算**：PFL 1 tick = 1 游戏秒（RimWorld 原版 1/60s 直觉不适用）；档位 Normal 1×（60× 现实）/ Combat 1/60×（1× 现实，交战自动切）/ Fast 8×。日志换算、常数标定、玩家观感三者要分开算——"制导周期 2s"在 Combat 档就是 2 现实秒（用户可见），在 Normal 档是 1/30 现实秒。
6. **导弹战斗的 flag 语义**：慢动作 flag 必须钉在"真正进入交战动作"（终末段 attackStartSurface>0），不能按 mission 判定——巡航段 Attack（玩家下命令太晚、导弹已飞出接管边界）会永久锁 1/60 档，把全场景拖进慢动作。
7. **同路径连发 = 追尾互撞**：异 volley 之间无排除（设计如此），同一发射器对同一目标快速连发时后弹沿前弹弹道追上即互撞转化（双双浪费）。**玩法规则：同目标连发要拉开间隔；将来齐射解离需给 N 子弹做散布/到达时间差，否则齐射自相消耗。**
8. **制导参数要与物理步长解耦地标定**：所有控制常数（冲刺 450、横向增益 0.8、接近阈值 300）按"游戏秒/物理步"语义成立即可——物理步细化为 1/30s（Combat）时每步增益自动缩放、行为不变（09-07 实测 G4 在 Combat 下逐 2.7m/s 正常完成冲刺），不要写死"每步 Δv"。
9. **离线仿真器的命中判定也必须扫掠**：导弹迷你仿真用"步末点距目标 < 半径"判命中，900m/步 × 57m 靶必然漏检穿靶步——表现成"全部失败样本都是近失后中止"的假象，与游戏侧 §0.3-2 扫掠盒同根源。**规则：任何离线复现物理的仿真器，命中/事件判定与游戏同口径（连续段检测），否则控制律迭代被假阴性带偏。**
10. **纯数学判据必须有单测**：`RaySlabIntersection` 两个 bug（退化零长线段恒真、"平行且板外"误判命中）都是无依赖纯几何——抽成 `SlabMath` 链入纯测试的**当轮**就被单测抓出（"首拍 8 枚全转化"与其共同暴露）。**规则：几何/数学判据写在游戏大文件里就永远没测试；凡被日志反常指认过的判据，抽出 + 单测固化。**
11. **组重构当步的陈旧几何**：解离/拆组会重定位"位置基准"（组原点移到领弹世界位、实体局部偏移清零）——同 tick 下游消费者若用重构前缓存的组原点，误差可达半队长（队首 +7km），首条指令方向恰与弹体姿态对准 → 主网满推力抢跑（09-08 队首擦过实证）。**规则：任何改变"位置基准"的重构操作，同 tick 内必须重取几何再算指令。**
12. **刚体组冲量模型的质心 loophole**：爆炸冲量 Δv = K·√E·falloff/**组质量** 加给整组、按爆点-**群质心**距离衰减——被打成员的爆点距质心可以很近（队列中间成员 ±1km），残组全体被踢数百 m/s。**规则：成员死亡时序 = 先脱队、后爆炸（A），自家爆炸豁免自家组（B），AoE 击毁当场脱队不留空壳窗口（C）；冲量模型按组质量除法，空组必须守卫（除零 NaN）。**
13. **日志限频必须按消费者分窗**：多实例共享一个限频窗口时被列表首车独占（弹群场景 V1 独占 122 行制导日志、其余 7 枚各 1 行，轨迹无法对照）。**规则：限频状态挂在被记录对象上（每车/每实体），不挂管理器。**

## 1. 背景（Problem）

PFL 的太空战斗已有远程直瞄（`CombatManager` 射弹 / Ray / 提前量）与近距夺取（跳帮），但缺少**会自己规划轨道、能伏击/追击的制导武器**。导弹的价值不在"更快的炮弹"，而在：

- **伏击**：预先部署到目标必经轨道面，熄火静默待机；目标进窗（玩家/AI 判断并下 Attack）后火炬冲刺——低 dV、隐蔽、博弈性强。
- **追击**：玩家/AI 下 Attack 后交会规划（Lambert/Gooding），按机动队列变轨逼近，近点火炬撞击。
- **指挥下的自主（撞击自动）**：给 Attack 即自主完成撞击（fire-and-forget 撞击段）；撞击前的部署/机动由玩家（或日后 AI）指挥；目标变轨触发"甩锁"上报，由玩家/AI 决定下一步（§8）。

同时无人机（Drone）与导弹物理上是同一类物体（无 Map 自主飞行器），只在行为 profile 上分层。本设计把两者统一为 `AutonomousVehicle`，避免两套并行系统。

## 2. 核心概念

| 概念 | 定义 |
|---|---|
| **AutonomousVehicle** | 无 Map 纯物理自主飞行器（`HasMap=false`），= 独立 group + 实体 + 编号，由 AutonomousVehicleManager 登记。导弹 / 无人机是它的两种**行为 profile** |
| **弹群（MissileGroup）** | 同批齐射 N 枚的逻辑单位：巡航只实体化 1 领弹 group + 实体（§5.1 单等效体），N-1 解离时以当前状态克隆为独立子 group。`entityIds` 多实体能力留作子群/marker 用 |
| **火炬（Torch）** | 恒定高加速 burn（`StartBurn` 缓释 dV 状态），导弹不减速、终末反而加速到 terminalSpeed → 单向火炬 |
| **卫星巡航** | 引力主导的轨道运动（圆轨解析 / N 体自由飞行），变轨走机动队列，静默待机 = 熄火圆轨（Standby/Loiter） |
| **作战半径** | = 导弹 `MaxDeltaV`（由注入工质 + ve 推导）。dV 余量即"还能追多远"，可读、可规划、可 UI |
| **甩锁（Lock Lost）** | 目标变轨使交会解失效。不是布尔事件，是连续劣化量，由"解健康度检查"量化；解死亡 → 导弹中止撞击回 Standby + 上报，处置由玩家/AI（§8） |
| **解健康度** | 按当前机动序列飞完，预测近点 vs 目标外推位置的偏差。> 阈值 → 解死亡 → 中止 + 上报 |

  │   └─ 一阶外推重算 dv → 转向（魔动量轮对准主推轴）→ StartBurn（缓释 dV，主推型锥内出力，§7/D15）
  ├─ 终末段（Attack 自动段）：弹群解离 → 逐枚火炬冲刺 → ExitCircularOrbit
  │   ├─ 命中（撞击式 = AABB 转化交接）→ part HP 大额 + F3 Map 落点 + 弹头 AoE（§10）
  │   └─ 目标甩锁 / 失活 → 中止 → 回 Standby（§8/§0.2-K6）；工质尽 → 惯性弹

物理 / 碰撞
  └─ 全程走通用管线（SpaceGameComp 积分 + CombatManager 碰撞），导弹 IsCollidable=true 全程参与
       → 误伤友军 / 被拦截 / 被炮塔近炸引信引爆，全部正常成立（同 volley 互碰排除，§0.2-K1）

## 4. 统一实体 AutonomousVehicle（Missile = Drone）

同一基座（无 Map `SpaceEntity` + group + 成员池）上的两种 profile：

| | Missile（首版） | Drone（后置，留位） |
|---|---|---|
| 语义 | 一次性自杀 | 可复用，带武器巡逻/盘旋 |
| 推进 | `PropulsionData`（强推进，独立机动）| 同左 |
| 工质/弹药 | 注入工质 = 作战半径 | 注入工质 + drone 武器弹药 |
| 终点 | 撞击爆炸 / miss 自爆 / 工质尽惯性弹 | 返航 / 燃尽坠毁（后置） |
| 成员 | N 枚（逻辑计数；巡航实体化 1 领弹，解离克隆 N 独立子群，§5.1）| 1 或 N |

- **导弹 = 无人机的自杀 profile**：实体、制导、碰撞、渲染、Serialization 全复用，profile 只切换"终点行为分支"。
- 文件规划：`Base/Game/AutonomousVehicleManager.cs`（管理器 + `AutonomousVehicle` 数据 + 制导状态机 + profile 分支）。
- **导弹携带 PropulsionData**（[SpaceEntity.PropulsionData](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Base/Core/SpaceEntity.cs#L491-L516)）：`PropellantDef`（工质种类）+ `ve` + `massFlow` + `mass`/`capacity`（kg），发射时领弹按 Def 注入满罐（§5.1 单等效体模型）；`MaxDeltaV` = 作战半径（`ve·ln(wet/dry)` 显示口径）。真实燃烧 = 每步按质量流率扣工质、质量随烧下降 → `RemainingDeltaV` 自然下降 → 燃尽（`BurnExhausted`）火炬熄灭 → 惯性弹。（`WeaponDef.missileFuel` 字段**保留**，重定义为「单枚标准注入工质质量 kg」：既是领弹巡航满罐，也是解离子弹 `capacity` 上限与资源结算基数。）

## 5. 弹群 Group（合并表示，性能核心）

> 已确认真实能力：`SpaceEntityGroup.entityIds`（`HashSet<int>`）+ `AddEntity/RemoveEntity/GetEntityIds` 原生支持多实体；`GetGroupRadius/GetGroupMass` 已按 group 聚合。弹群**无需扩展架构**（巡航段仅领弹 1 实体即可；多实体能力留给解离子 group 与可选 marker，见下）。

```
齐射 N 枚（同炮塔、同初速、同制导律 → 弹道几乎共线）
├── 巡航段：整群 = 1 个 group、1 个物理实体（领弹），参与全局碰撞池
│   ├── 物理：整群按「1 枚标准弹」跑——质量/工质/推力全部单枚口径（§5.1，单源 burn 零改核心）
│   ├── 制导：对领弹重算 dv，群级一次 StartBurn、全体同 ΔV（N 枚轨迹本就一致，共线天然保持）
│   ├── 燃料：只烧领弹这份油；领弹当前剩余 = 每一枚的剩余（N 枚同步同率燃烧，§5.1）
│   └── 编队视觉（可选）：无推进源、质量可忽略的 offset marker 散布 50-200m，仅渲染 / 弹幕走廊 AABB
└── 终末段（dist < 解离阈值）：以领弹当前状态为种子，解离克隆 N 枚独立子 group（§5.1）
    ├── 此时只在目标附近，活跃独立弹 = N，成本可控
    └── 各子弹带瞄准偏置（弹幕覆盖目标船不同部位）
```

**弹群 dV 模型：单等效体 + 解离克隆（2026-09-06 用户定稿，替代早前"共享 dV 池"与同日"均摊扣料制"设想）**：

**巡航段整群按 1 枚标准弹跑**（质量 = 单枚干质量、工质 = 单枚满罐 `missileFuel`、推力 = 单引擎），走 `ComputeGroupPhysics` 现有的**单源 burn 路径，物理核心零改动**：

- **成立依据（单等效体精确性）**：N 枚同配置共线齐射，每枚轨迹由单枚参数（ṁ·ve/(m_dry+M)）决定，**任一时刻 N 枚的位置/速度/剩余 dv 完全相同** → 用 1 个代表体（领弹）即可精确表达全群运动与 dV 口径，不需要逐枚仿真、也不需要"并联引擎并集/N 份扣料"这套记账。
- **资源口径**：发射时按 N 份结算成本（弹药 + N×`missileFuel`）；巡航段实际只扣领弹那份。**逻辑上 N 枚同步同率燃烧 → 领弹的当前剩余就是每一枚的当前剩余**，天然守恒于发射的 N 份，无需均摊扣料。
- **实体构成**：物理实体巡航段只有 1 个（领弹）。N-1 枚在解离前不实例化；如需"编队视觉 / 弹幕走廊 AABB"，用**无推进源、质量可忽略**的 offset marker 装饰（不参与 burn、不影响 dV、不触发离群检测），首版可不做。
- **解离 = 克隆生成（你定的口径）**：到解离点（§待对齐 #2，倾向 5-20km）以领弹**当前状态快照**（pos/vel/姿态/所在天体/轨道参数）为种子，实例化 N 个独立子 group：
  - 每个子体 = 标准弹实体 + `PropulsionData`（`mass` = 领弹当前剩余值，`capacity` = Def `missileFuel` 满罐）+ 各自瞄准偏置；
  - 子弹自此为独立导弹（各自制导 / 碰撞 / 终末火炬），母群退役销毁。
- **相对早稿的差异（两版作废）**：~~共享 dV 池聚合~~（无此 API）与~~均摊扣料制~~（各枚独立等额罐 + ComputeGroupPhysics N 份分摊）均不采用——后者是过度建模，需改热路径扣料，且并不比单等效体更真实。

**为什么这比"排除出碰撞池"对**（决策修正记录）：
- 误伤是玩法（火力网 / 弹幕误杀友军），物理一致性不让步。
- 全程 `IsCollidable=true` → 导弹能被拦截、能误撞第三方、能被炮塔近炸引爆。
- 性能靠"共线弹合并表示"这个**数据结构优化**（同质实体批量表示），而非"排除出系统"（破坏语义）。

**待对齐细节**（#1 已于 2026-09-06 对齐，#2/#3 开工前定）：
1. ✅ ~~巡航段全群共享 dv（质心制导）~~ **已对齐**：单等效体下领弹即全群 → "质心制导"退化为单体制导，天然一致（§5.1）；offset marker 仅影响渲染与走廊 AABB，不影响物理与 dV。

## 6. 发射链路（FireWeapon Missile 分支）

- 发射器 = 现有 `CompMapTurret` 挂 `weaponType=Missile` 的 `WeaponDef`，齐射复用 `FireVolley`——一次齐射 `missileCount` 枚 = 一个弹群，规模由 Def 控制。
- `CombatManager.FireWeapon` 新增 `WeaponType.Missile` 分支（现只有 Ray/Projectile 分支，[FireWeapon](../Combat/CombatManager.cs)）：
  - 出膛点 = `spawnPos`（炮口），**出生点 = 出膛点沿出膛方向外推到母船 AABB 外**（发射器侧计算，避开与母船初始重叠）；初速 = 母船 `groupVelocity` + 朝目标 × `missileSpeed`。
  - 创建弹群 group + **1 个领弹实体**（`linkedMapId=-1`，`HasMap=false`，`PropulsionData` 满罐注入），N 为逻辑计数（§5.1）；发射成本 = 扣 `WeaponInstance.ammo`（§0.2，燃料链后置）。
  - 默认携带 Mission = `Attack(定位机当前索敌目标)`（fire-and-forget 基线）或 Standby（玩家选择）→ 注册 AutonomousVehicleManager。

**Missile 分支与 Projectile 分支的两条硬性分叉**（2026-09-06 对账新增）：
1. **不得切 Combat 档**：Projectile 出膛即 [SetCombatModeImmediate](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Combat/CombatManager.cs#L1438-L1440) 进子弹时间——那是炮射近距对射的节奏。导弹是慢兵器，发射绝不进 Combat 档，分支内不得调用。
2. **不做弹道提前量**：Projectile 用 `ComputeLeadAimPoint`（按 `projectileSpeed` 解二次方程）。导弹出膛速度量级远低于炮弹（`missileSpeed` 相对母船轨道速度 ~7.8km/s 可忽略）且靠制导收敛——出膛方向 = 指向**目标当前/外推位置**即可，提前量由 AutonomousVehicleManager 制导循环接管（§7），不在此处解算。

**发射入口（指令驱动模型，2026-09-06 用户定稿）**：

```
发射（继承母船 pos/vel；出生点 = 发射器出膛点沿出膛方向外侧、避开母船 AABB —— 发射器侧职责）
└── 初始 = Standby 待命（或携带 1 条已下发的 Mission）
    ├── Mission = Attack(target)：唯一"自动段"
    │   ├── 按到目标 AABB 表面距离（距离口径统一 = 表面距，§0.2）自动分派执行路径：
    │   │   ├── DirectTorch：已 ≤ DirectTorch 边界（如 100km，Def 可配）→ 不复轨，解离 → 火炬撞击
    │   │   └── Rendezvous：更远 → 交会变轨 → 近点 → 解离 → 火炬撞击
    │   └── 撞击一经开始自动完成（撞上 = 转化交接，§10）
    ├── Mission = Loiter(ΔL)：玩家/AI 部署 → 变轨入待机轨道 → 熄火静默
    │        （首版 = 与目标共圆、同向、落后相位 ΔL，见 §0.2）
    ├── Mission = Standby：保持当前轨道待命
    └── Mission = SelfDestruct
撞击发起之前的一切机动均由玩家（或日后 AI）指挥下发；只有"已下发的撞击段"自主执行。
新 Mission 直接覆盖旧 Mission。
```

**发射约束（无）**：任意状态平台均可发射（自由飞 / 圆轨 / 战斗），继承母船瞬时状态向量。圆轨不是发射前提。发射成本 = 扣 `WeaponInstance.ammo` 抽象计数（N 枚；燃料链后置，§0.2）。

## 7. 制导与状态机（卫星巡航 + 火炬终末）

```
Standby / Loiter（受指挥的引力主导轨道运动：圆轨解析 / N 体自由飞行；熄火静默）
   │  玩家/AI 下发 Mission
   ├── Attack(target)（自动段入口）
   │   ├── Maneuvering ── 按表面距分派：DirectTorch（≤边界，不复轨）/ Rendezvous（交会变轨）
   │   │       （复用 RendezvousPlanner/OrbitTransferPlanner；Rendezvous 近点前仍可被新 Mission 覆盖）
   │   └── Terminal ── 自主段（不可被覆盖的只有这一瞬之后的执行）── 解离弹群 → ExitCircularOrbit → 火炬冲刺
   │           ├── 命中（撞上即爆）→ part HP 大额 + F3 Map 落点 + 弹头 AoE
   │           ├── 目标甩锁 / 目标失活 → 中止撞击 → 回 Standby 等新 Mission（§8）
   │           └── 工质尽 → 惯性弹（不主动判 miss，§0.2）
   └── SelfDestruct
```

**制导降频（每物理步 ≈ 每 2 tick，距离分档）**：

| 段 | 距离 | 制导频率 | 说明 |
|---|---|---|---|
| 巡航 | > 50km | 每 60 tick | 轨道力学主导，方向误差影响小 |
| 中距 | 5-50km | 每 12 tick | 正常积分管线，一阶外推重算 dv |
| 终末 | < 5km | 每 2 tick | 全速冲刺 + 点-盒/扫掠命中检测每步 |

- **一阶外推**：`aim = targetPos + targetVel × t_go`，几个向量运算，不迭代求解。
- **主推方向型 burn（导弹已升格，2026-09-06）**：导弹**不再是全矢量免对准**——主网（主引擎）只沿 body 局部主推轴（默认 -Z，`mainAxisLocal` 可配）**锥角内**出力（锥角 Def 可配，默认 10°）；每物理步未对准 → **只转不推、不耗工质**（魔法动量轮直设角速度、限 `MaxAngularRate`，导弹可配更高转向率），对准后才出力。→ **制导 = 转向 + 点火两相，转向时间计入收敛**（不是"每拍 dv 即时烧出"）。导弹同时带**弱 RCS 副网**（`PropulsionData.isVectoredRcs=true`，全矢量小推力）：主推未对准的转向期 RCS 仍能出力修正、主网尽时兜底（选网规则见 [操舵与推进朝向设计 D15](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/DesignNotes/操舵与推进朝向设计-20260829.md)）。
- **实现口径（2026-09-08）**：制导**每物理步**执行（上表降频档未实施——每步只有几个向量运算，成本可忽略；降频反而引入相位滞后，终末段致命）。控制律 = 横向相对速度归零 + 接近率补量双门控（阈值 + 横差修正时间约束）+ 几何丢失判定，参数全部 Def 可配、本体抽为纯核心 `MissileGuidanceCore`（纯测试迭代，见 §0 八轮注记）。
- **dV 消耗**：torch 模型下每步 ΔV = a·dt，消耗挂在群级 `StartBurn(dV)` 的 `remainingBurnDV` 缓释 + [ComputeGroupPhysics](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Base/Game/SpaceGameComp.cs#L709-L813) `HasActiveBurn` 分支按工质网络流率扣料（无 Map 按 D15 分类：导弹主推型走"锥内轴向"子分支、未对准只转不推不耗料；全向类走现全矢量分支）；巡航段只扣领弹这份油（§5.1 单等效体）。燃尽（`BurnExhausted`）→ burn 终止 → 惯性弹（制导降级纯弹道）——"燃料尽后变得可预测、可被规避"是天然拦截窗口。

**性能结论**：巡航/埋伏段圆轨解析 O(1) 懒缓存（**低于任何积分方案**），变轨低频，制导降频，弹群合并 Group——100 枚稳态成本 ≈ 每步 1 份扫掠 + ~2 次制导重算 + 极少量终端积分，现有管线零感知，无需并行结构。

## 8. 甩锁语义

**判定 = "解还活着吗"——连续劣化量，非布尔。但决策源 = 玩家/AI，不是导弹**（2026-09-06 指挥模型定稿）：

- 解健康度检查（群级，约每 120 tick，仅 Attack 撞击段内有意义）：按当前机动序列外推，预测近点 vs 目标外推位置；近点 > 阈值（如 2× 解离距离）→ 解死亡。
- 解死亡时导弹**只做一件事：中止当前撞击 → 回 Standby，向玩家/AI 上报甩锁事件**（面板状态 + 可选 Message）。后续处置全由玩家/AI 以新 Mission 决定：
  - Replan（重新下 Attack）：需 dV 预算允许（新解 dV ≤ 剩余 × 0.8，留终末余量）；不足则只能 Torch 硬冲或放弃；
  - Return Loiter（改下 Loiter 部署）：省 dV，威胁仍在；
  - SelfDestruct / 换目标。
- **防抖（滞后闸门）**：目标 |Δv| < 5m/s 且位置偏差 < 1km 不判解死、不上报（防噪声刷屏）。dV 预算 = 玩家/AI 决策时可用的重攻次数上限。

**由指挥模型自然长出的博弈**：
1. **静默即安全 / 机动换生存**：目标圆轨熄火 → 位置可预测 → 解永不失效；目标一机动就破坏解 → 玩家被迫重下令 → 消耗导弹剩余 dV → 真实 dV 竞速。
2. **终末竞速**：解离火炬后目标变轨 → 导弹只剩终末修正能力，甩锁即中止回 Standby（此距离上基本只能看它跑掉或自毁）→ 双方 dV 正面比拼。

**探测模型首版全知**（导弹群 tick 直读目标 group 状态），不做"必须看到才更新"。探测链路（中继/导引头）留到星座组网一起做。

## 10. 命中与爆炸（撞击式命中语义，2026-09-06 定稿）

**导弹攻击 = 物理撞向目标，不是近炸引信**：终末子弹直接撞目标；与目标 AABB 接触的瞬间，导弹销毁并就地转化为"弹头射弹"，由后者在 1 物理步内 slab 精确命中目标完成结算（机制见下）。爆炸中心 = 弹头射弹的精确命中点（可被弹着偏置拉偏，见下）。

**命中判定（红线）**：
- 唯一命中判据 = **撞上碰撞体**（目标/第三方实体 AABB，走射弹同款连续 slab 判定防 tunneling）。
- ❌ **禁止"到达 / 落回目标地图地面（或任何平面/地板）= 命中"的分支**。
- ✅ **已验证**：现有射弹（`ProjectileInstance`）只有两种结局——[CheckSegmentGroupHit](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Combat/CombatManager.cs#L416) slab 撞上碰撞体 → 结算；或寿命超时 → "超时脱靶"清理（[UpdateProjectiles](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Combat/CombatManager.cs#L293-L358)）。代码中**不存在任何"地板/平面即命中"路径**，射弹飞到任意深度都不会命中地板。Map 内 [PFProjectile3D](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Combat/PFProjectile3D.cs) 是命中**之后**才生成的落点视觉弹（落点 y=0 / 出膛 y 夹取属表现层设计，非命中判定）。**此保证必须原样带进导弹实现，不允许回退**。

**实现机制（2026-09-06 用户定稿）：AABB 接触 = 就地放置弹头射弹 + 销毁导弹（先生成、后销毁）**：

```
导弹（碰撞池里的 group）被扫掠盒检测到与某碰撞体 AABB 相交
└── 不走通用船-船碰撞（动量/弹开/动能爆炸全错）
    └── 转化交接（顺序：先生成 → 后销毁，用户定）：
        1. 先生成「弹头射弹」ProjectileInstance：位置/方向/速度**直接继承导弹**（从尚存的导弹对象拷贝状态，无空窗）
           └─ damage=missileDamage（大额）/ lifetime / 弹头爆炸参数（Def 配）
        2. 再销毁导弹（移除该 group/实体，弹群侧注销）——紧随其后、同一物理步内完成
        3. 之后一切交给射弹命中链：下一物理步连续 slab 精确命中 part → 结算（下）
```

- **顺序 = 先生成弹头射弹、后销毁导弹**（2026-09-06 用户补充）：方向/速度/位置直接从尚存导弹实体拷贝（含 3D y 高度），不留"导弹已消失、射弹未就位"的空窗；射弹生成瞬间其 `sourceGroupId` 指向的导弹 group 仍在，自伤过滤（跳过同源）即时生效，销毁后亦无残留引用问题。
- **命中判定仍只有射弹那一条**（撞上碰撞体，连续 slab 防 tunneling）——**不新增任何"平面/地板即命中"分支**，也不写自定义引爆逻辑。
- 交接点 = 导弹扫掠段与目标 AABB 的**首次接触点**（RayAabb 停点，非本步终点）：弹头射弹自该点**向内复扫整个进入段** → 命中点精确不偏深（本步终点已探入盒内，直接放会命中过深，只能靠"起点在盒内"兜底）。
- 交接点已在 AABB 面上且速度向内 → 弹头射弹**必然 1 物理步内 slab 命中**（"起点在盒内"已有防御，[CheckSegmentGroupHit](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Combat/CombatManager.cs#L520-L524) 已处理）。
- 若目标在被接触瞬间变轨甩开（接触点已失效）→ 弹头射弹照常飞、超时脱靶自然销毁（等效 miss，无泄漏）。

**高度语义（求证，2026-09-06）**：RW 原版 `Projectile.ExactPosition` = `origin.Yto0() + xz 进度 + Vector3.up·def.Altitude`——两端 y 都被拍平，原版射弹**恒在固定 `def.Altitude` 高度水平飞行，不在严格 y=0**；命中只发生在"到达目标格 / 途中撞到目标物"时（落到地面格 ≠ 伤害命中，非爆弹打空无伤害）。对照我们：
- 3D 弹（`ProjectileInstance`，含弹头射弹）全程保留真实 3D 位置（含 y），**无 y=0 概念、无拍平**——命中几何与高度无关；
- 唯一的 y=0 是 Map 落点视觉弹（`PFProjectile3D`）的「爆炸层落点 / y≥0 防御夹取」——表现层，不会反向产生 3D"地板命中"判定；
- 若将来 Map 内视觉弹有"贴地/潜地"观感问题，参照原版给它补恒定飞行高度（`def.Altitude` 或入口高度），仅终点落到爆炸层——这是表现问题，不是命中判定问题。

**命中结算 = 射弹命中链 + 导弹弹头爆炸（由弹头射弹执行，复用 + 放大）**：
1. **part HP 大额直扣**：复用射弹命中后的 `part.ApplyDamage` 结算点，单发伤害 = 射弹 damage 的数十倍（Def 配 `missileDamage`）。
2. **F3 Map 落点视觉**：命中目标带 Map（空间站/带图载具）→ 走 [SpawnPenetrationMote](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Combat/CombatManager.cs#L1505-L1577) 同款落点瞬爆/贯穿弹（落点建筑伤害 + Fleck 爆闪）。
3. **额外一次弹头 AoE（力度远大于射弹）**：
   - 3D 侧：以命中点为心 `ExplosionInstance` + `ApplyExplosionDamage/Impulse`（半径/中心伤害 Def 可配，量级 = "重弹头"而非射弹）；
   - Map 侧：目标带 Map → 以命中点映射格为心做**地图范围爆炸**。⚠️ 太空 Pocket Map 上 `GenExplosion` 会 NRE（既有注释）→ 需自实现：半径内格遍历 + 建筑/pawn 伤害 + Fleck 视觉（实现节点，见 §14）。

**有 Map 目标的弹着偏置（= 定位机"精确炮击"同源）**：
- 复用 [CompMapDesignator](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Base/Buildings/CompMapDesignator.cs) 的 `preciseStrikeCell` 流程：格 → `MapCoordMapper` → 目标船体局部（y=0）→ 世界瞄准点（随目标旋转/运动，即现有 `GetAimTargetPosition`）。
- 发射/改派时把该"目标局部偏置点"写入导弹（`aimOffsetLocal`，目标局部系）；制导与终末撞点据此偏置，命中/爆炸中心落在指定格（≈ 炮击选择弹着部位）。无偏置 → 默认瞄目标质心。

**转化判据 / 拦截语义（实现节点）**：
- 触发点 = 通用船-船碰撞对枚举处：任一方是导弹 group → 走转化交接分支，**跳过**动量交换/弹开/动能爆炸/分离量逻辑（[CombatManager.CheckShipCollisions](file:///d:/PioneerFrameworkLite/Source/PioneerFramework/Combat/CombatManager.cs#L617) 需加导弹识别）。转化对**任何**碰撞体生效（含友军，误伤是玩法）；不设 `CollisionExplosionSpeedThreshold` 低速下限（低速接触也转化）。
- **排除同齐射弹群互碰**：同一 volley 的兄弟子弹彼此 AABB 相邻 → 不转化不自爆（按 volleyId 归属判断），防止链式自毁。
- **被射弹先击中**（导弹作为目标被拦截/误击）：走普通射弹命中判定——导弹被击毁 = 在该位置就地引爆弹头 AoE（与接触同效；近炸引信本体后置）。
- 转化交接本身不再新增任何伤害/爆炸——爆炸全部来自弹头射弹命中后的结算，避免双算。

**非命中结局**：
- miss（弹头射弹超时脱靶 / 未撞上）→ 惯性飞完自毁（无爆炸或小爆，Def 可配）。
- 工质尽 → 惯性弹，被规避后成太空垃圾（可后续清理）。
