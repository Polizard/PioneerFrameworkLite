## 被验证的算法

要以 O(1) 判断"断没断"，靠三件事：

1. **绕数 = 连通块数 − 孔洞数**（平面图欧拉公式在方格上的离散形式）：`χ = w/4 = c − h`
   ⇒ 维护 `w` 与 `h` 就能 O(1) 得到 `c`。
2. **`w` 局部可算**：每个格点看周围 4 格，恰好 1 格 = 凸角 `+1`、恰好 3 格 = 凹角 `−1`、
   2 格对角 = `±2`（符号由连通性配对决定）。拿掉一格只改动它的 4 个角点。
3. **前景与背景必须互补配对**：`(4 邻域前景, 8 邻域背景)` 或反过来，混用会破坏 Jordan 定理。

由此得到的不对称解法（与文献一致）：

| 操作 | 便宜的一侧 | O(1) 得到的量 | 需要修复的一侧 |
|---|---|---|---|
| 拿掉一格 | 背景只会**合并**（并查集 O(α) 精确给 Δh） | `Δc = Δw/4 + Δh` | 前景（只在 `Δc > 0` 时） |
| 放上一格 | 前景只会**合并**（并查集 O(α) 精确给 Δc） | `Δh = Δc − Δw/4` | 背景（可推迟/合并到批末） |

## 四种做法（同一负载对比）

| 变体 | 说明 |
|---|---|
| 全量重算 | 暴力基准，也是**正确性权威** |
| 脏标记 + 局部 BFS | 同样工作，但**关掉 O(1) 检测**（`AlwaysRepair = true`）⇒ 每次都要 flood |
| 增量（带检测） | 上面的算法，只有计数真变了才修复 |
| 批量 | 一批多格只做**一轮**修复（而不是每格一轮） |

## 判据（每步都对拍，不是抽样）

- 计数：`c`、`h` 与暴力全量一致
- 恒等式：`w % 4 == 0` 且 `w/4 == c − h`
- **分区**：同根 ⇔ 同暴力分量（前景与背景各查一遍）
- 批量 ≡ 逐格：终态完全一致
- 边界用例：空/满/1×1/对角相碰（两种配对给不同答案）/空心方框/破角补角/一字长条断开接回/细环断口/洞中有岛
- 内部对账：`CompactAll` 重建后孔洞数必须等于维护值（不符即抛）

## 踩过的坑（留着当教材）

1. **坐标两套混用**：内部坐标 `(x,y)` 与 padded 索引 `i=(y+1)*Size+(x+1)`。
   在 `Add` 里用内部坐标算背景邻居、却当成 padded 索引用 ⇒ 修复播种到错位的格子、
   覆盖不全 ⇒ 分区错。**归零靠的是一次"事后暴力对照"的诊断输出，不是推理。**
2. **把 `List<int>` 当定长数组用**（`list[k++] = v`）：Count 为 0 时抛异常；更坏的是
   上一步残留的 Count 让它"有时候不抛"，于是错得静悄悄。
3. **并查集不支持删除节点**：格子会被反复拿走/放回。曾让"被拿走的格子"继续当根，
   放回时把它的旧孩子一并并进别人的分量 ⇒ 错合并。
   **正解：每次"放上一格"给一个全新节点，永不复用**，节点池靠 `CompactAll` 回收。
4. **批量删除的修复闸门不能看净值**：一批里可能既有"拿掉孤块"（`Δc = −1`）又有
   "切断链条"（`Δc = +1`），净值为 0，但断裂确实发生了 ⇒ 必须按**正的部分之和**决定是否修复。
5. **我自己的断言写错了**：曾断言"拿掉一格不可能减少块数"——错的，被拿掉的格子本身
   就是孤块时 `c` 会减少 1（合法范围 `[−1, +3]`）。
6. **`Find` 成环会死循环**，比报错难查得多 ⇒ 加了 `GuardFind` 环检测。

## 结论（跑出来的数字见运行输出）

- 单格增删：增量版与"关掉检测"版是**同一份工作负载**，差距就是 O(1) 检测省下的 flood；
  最坏情况（细环断口，两端都是大块）单独统计。
- 批量：一批 N 格只做一轮修复，对比"逐格 N 轮"。
- 恒等式与分区在全部随机对拍里成立 ⇒ **"绕数 + 双图并查集"这条路是可行的**；
  按 §15 的文献，删除方向的 O(1) 摊还是可达的（Łącki–Sankowski STACS 2015），
  完全动态的 O(1) 不可能（Pătraşcu–Demaine 2004，平面图同样成立）。
