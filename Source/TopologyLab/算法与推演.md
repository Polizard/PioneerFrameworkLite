# 方格连通性增量算法：判定"断没断、断成几块"

> 算法、推演与实测。配套代码 `Source/TopologyLab/`（独立工程，可复现，退出码即判据）。
> 目标读者：需要"在方格图上频繁增删格子、并立刻知道图形是否分裂"的工程师。

---

## 0. 摘要

**问题**：一张 M×N 的方格图，每格"有砖/无砖"。反复执行"拿掉一格/放上一格"（允许一次多格），
每次都要立刻回答：**现在有几块连通块（c）、几个孔洞（h）**，以及**每格属于哪一块**。

**做法**：不重扫全图，而是维护三个量——**绕数 w**（局部可算，O(1)）、**孔洞数 h**、
以及前景/背景两套并查集；靠平面图欧拉公式

```
χ = w/4 = c − h        ⇒   Δc = Δw/4 + Δh
```

在 O(1) 内判断"这次改动到底有没有改变连通块数"，**只有真的断裂时才去做一次泛洪修复**。

**结果（250×250 = 62,500 格，Release，单线程）**：

| 项 | 前景 4 邻域 + 背景 8 邻域 | 前景 8 邻域 + 背景 4 邻域 |
|---|---|---|
| 全量重算（暴力 BFS 基准） | 1.88 ms | 1.44 ms |
| **单格增删（本算法）** | **4.8 µs** | **25.0 µs** |
| └ 每次改动平均扫描格数 | 522 / 62,500 | 2,452 / 62,500 |
| 单格增删（每次重排背景，不作优化） | 805 µs（×168 慢） | 465 µs（×19 慢） |
| 批量 9 格 | 1.07 ms/批（118 µs/格） | 0.73 ms/批 |
| 批量 100 格 | 1.28 ms/批（12.8 µs/格） | 0.80 ms/批 |
| **批量 1000 格** | **1.82 ms/批（1.8 µs/格）** | 1.29 ms/批 |
| 最坏情况：砍断"哑铃"的桥（断成两个大块） | 扫 31,125 格（= 整个连通区域） | 同 |
| 最坏情况：把桥接回 | **扫 0 格** | 同 |

**正确性**：与暴力全量**逐步对拍**约 130 万次操作（计数、恒等式、每格分区、批量≡逐格），无一次不符。

## 1. 问题定义

- 地图：M×N 方格，外圈补一圈恒为空的 **padding**，用来表示"外部"（区分孔洞与外部）。
- 输入：布尔存在性数组 `A`（1 = 有砖）。
- 操作：`Add(cell)` / `Remove(cell)`，以及一次多格 `AddBatch(cells)` / `RemoveBatch(cells)`。
- 输出：
  1. `c`：前景连通块数；
  2. `h`：孔洞数 = 不连外部背景的背景连通分量数；
  3. **分区**：每格属于哪一块（同一块共享一个标记）。
- 目标：单次改动尽量 O(1)；**允许用内存换时间**（这是本题的题设）。

**连通性语义必须先定**，且前景与背景必须**互补配对**：

| 配对 | 含义 |
|---|---|
| 前景 4 邻域 + 背景 8 邻域 | "必须共边才算连"（对角相碰不算） |
| 前景 8 邻域 + 背景 4 邻域 | "对角相碰也算连" |

**这不是实现细节，而是物理语义**：同一张图在两种配对下答案不同（见 §6.3 的边界用例），
而且"共点算不算连"在真实系统里往往由别的子系统（寻路、房间、气密）决定，必须与它们对齐。

## 2. 三块基石（推演）

### 2.1 基石一：绕数 = 连通块数 − 孔洞数

平面区域有 `χ = c − h`（欧拉公式；`χ` 是欧拉示性数）。把它离散化到方格上：

- 对每个**格点** v（格子的角，不是格子本身），看它周围 4 格里有几格有砖，记 `n(v)`；
- 给每个格点一个整数贡献：

| 该格点周围有砖的格数 | 贡献 |
|---|---|
| 恰好 1 | `+1`（凸角） |
| 恰好 3 | `−1`（凹角） |
| 2 格，且**对角** | `+2` 或 `−2`（见 §2.3，这是配对开关） |
| 2 格共边 / 0 格 / 4 格 | `0` |

令 `w = Σ_v 贡献`，则

```
w / 4  =  c − h
```

这正是图像分析里的**欧拉数**（Euler number）局部计数法：等价于经典的 2×2 bit-quad
（凸凹模式计数），出处见 Gray 1971 / Pratt。

### 2.2 基石二：`w` 是局部可算的 ⇒ 单格改动 O(1)

`w` 只依赖每个格点周围 4 格。**拿掉或放上一格，只改动它的 4 个角点**：

```
Δw = Σ_{该格 4 个角点} (改动后的贡献 − 改动前的贡献)
```

⇒ 4 次局部查询，O(1)，不需要任何搜索。实测这一步的常数就是几十纳秒的量级。

### 2.3 基石三：前景与背景必须互补配对（对角项 `±2` 的来历）

**对角项的符号就是"共点算不算连"这个开关**：

- 若前景取 **4 邻域**（对角相碰**不算连**），两格对角各自是一个独立区域的凸角 ⇒ 两个 `+1` 都保留 ⇒ 该格点贡献 `+2`。
- 若前景取 **8 邻域**（对角相碰**算连**），两格连成一体、不再是凸角 ⇒ 两个 `+1` 相互抵消 ⇒ 贡献 `−2`。

配对的**互补性**不是审美要求，而是 Jordan 定理的要求。反例（(4,4) 混用）：

```
. X .
X . X        中间那格是空的；四个"X"在 4 邻域下互不相连（对角），
. X .        但中间那格在 4 邻域下也无法到达外部 ⇒ 一块"没有曲线的洞"
```

在 (4,4) 下：前景 = 4 个互不相连的块；背景 = 中间格自成一块（不连外部）。
于是"一条并不连通的曲线把平面分成了内外"——Jordan 定理失效，`c − h` 与局部计数不再一致。
**取互补配对（4 配 8）则自洽**：8 邻域下曲线连通且确实分隔内外；或者反过来取 (8,4)，曲线不连通也就不分隔。

## 3. 增量维护设计

### 3.1 不对称：每条方向都有"只合并"的一侧

关键观察（也是全部效率的来源）：

| 操作 | 前景侧 | 背景侧 |
|---|---|---|
| **拿掉**一格（该格变成背景） | 可能**分裂** | 只会**合并** |
| **放上**一格（该格变成前景） | 只会**合并** | 可能**分裂** |

而**并查集擅长合并**（O(α)），不擅长分裂。于是：

- **拿掉一格**：背景侧只会合并 ⇒ 并查集**精确**给出 `Δh`；再由恒等式
  `Δc = Δw/4 + Δh` 得到 `Δc`。**O(1) 就能知道"到底断没断"**，不必去搜索。
- **放上**一格：前景侧只会合并 ⇒ 并查集**精确**给出 `Δc`；再由恒等式
  `Δh = Δc − Δw/4` 得到 `Δh`。同样 O(1)。

也就是说：**每个方向都用一个便宜的并查集拿到一个量，另一个量由恒等式推导。**
"断裂"只发生在不便宜的那一侧，而我们**已经知道它有没有发生**——只在真发生时才修。

### 3.2 断裂修复：只动受影响的一侧

`Δc ≠ 0` 时，从被改动格的邻居出发泛洪，每一块换一个新标记（根）。
本实现的代价是 **O(连通区域大小)**；文献的版本用"从两端并行 DFS、先耗尽的一侧先停"，
可做到 **O(较小的一块)**，并在平面图删除方向上达到 O(1) 摊还（见 §5）。

注意方向不对称带来的好处：**合并方向（把桥接回）是 0 格扫描**（实测），
真正的开销只在"砍断"那一刻，而砍断是罕见事件。

### 3.3 批量：一批只做一轮修复

一次放/拿 N 格时，若按逐格处理就要做 N 轮修复。改为：

- 逐格做并查集记账（O(α) 每格）与绕数更新（O(1) 每格）；
- **整批只做一次**背景重排 / 一次前景断裂修复。

实测 1000 格：1.8 µs/格，比逐格路径快 **26～54 倍**。

> **批量修复的闸门不能看净值**：一批里可能既有"拿掉孤块"（`Δc = −1`）又有"切断链条"（`Δc = +1`），
> 净值为 0 但断裂确实发生了 ⇒ 必须按**正的部分之和**决定是否修复。

### 3.4 一条可证明无害的跳过（把单格从 805 µs 打到 4.8 µs）

背景结构**只在"放上一格"时需要重排**（它会分裂），而它被用到的唯一地方是
**将来"拿掉一格"时数"有几个不同的邻居分量、其中几个是有限的（孔洞）"**。

设原背景分量为 `C`（`touch = C 是否连外部`）。分裂成若干块后：

```
Δh = (有限块的个数) − (C 有限 ? 1 : 0)
```

于是：

> **若 `C` 连外部 且 `Δh == 0`，则一块有限块都没产生**（否则 `Δh` 会大于 0），
> 即所有块都不连外部。把这几块**当成一块**时：
> - 任何将来查询里的 `有限分量数` 不变（都不有限）；
> - 合并后的 `touch` 不变（都不连外部）。
> ⇒ **任何将来的 `Δh` 都完全一致** ⇒ 可以整块保留，不做泛洪。

配套把**判据**收窄（这是"仪器"的判据，不是算法）：背景结构只承诺两件事——
①每格"是否连外部"与暴力一致；②**有限（= 孔洞）分量**必须精确分区。
连外部的若干块允许被合并成一块。理由与上面的证明一一对应。

**一个副产物**：这也说明"背景分区"根本不是必需产物，我们真正要的是
**前景分区 + 两个计数**。文献里"双图并查集"的角色也正是只负责检测（"删边两侧是否同面"），
不负责产出标记。

### 3.5 并查集的节点生命周期（不可删节点的绕法）

并查集**不支持删除节点**，而格子会被反复拿走/放回。若让"被拿走的格子"继续当根，
它可能还挂着孩子，**放回时会把那些孩子一并并进别人的分量** ⇒ 错合并。

做法：

- **每次"放上一格"给一个全新节点**，永不复用；
- 被拿走的格子的旧节点**留在树里当"穿线"**——它恰好是"未修复的分裂"得以存在的原因，由计数器检测；
- 节点池只增不减 ⇒ 超过阈值（4×格数）时做一次**整图重建（Compact）**回收；
- Compact 同时充当**兜底**：局部修复的对账对不上时直接整图重建（正确性优先），并顺带对账孔洞数（不符即报错）。

## 4. 伪代码

```
状态：
  A[]                     存在性（含 padding）
  w                       绕数（四分之一转为单位）
  c, h                    连通块数、孔洞数
  UF_fg, UF_bg            前景/背景并查集（节点只增不减）
  node_fg[], node_bg[]    每格 → 节点号

Add(x, y):
  if A[x,y]: return
  dw ← Δw(把该格置为有砖)          # 只看它 4 个角点
  w += dw;  A[x,y] ← 1
  me ← UF_fg.新节点()
  roots ← 该格前景邻居所在分量的根（去重）
  dc ← (roots 为空 ? +1 : −(|roots|−1))
  c += dc
  Δh ← dc − dw/4                    # 恒等式
  h += Δh
  # 背景侧：该格离开背景 ⇒ 可能分裂
  if UF_bg.该分量还有别的格子 or 强制修复:
      if not (原分量连外部 and Δh == 0):    # ← 可证明无害的跳过（§3.4）
          从该格的背景邻居泛洪，每块换新节点
  按需 Compact

Remove(x, y):
  if not A[x,y]: return
  dw ← −Δw(把该格置为无砖)
  w += dw;  A[x,y] ← 0
  Δh ← UF_bg.并入该格()             # 只会合并 ⇒ O(α) 精确
  h += Δh
  dc ← dw/4 + Δh                    # 恒等式（合法范围 [−1, +3]）
  c += dc
  if dc > 0: 从该格前景邻居泛洪，每块换新节点（修复断裂）
  按需 Compact

AddBatch(cells) / RemoveBatch(cells):
  逐格做上面的记账，但把"泛洪修复"与"背景重排"推迟到批末各做一次；
  批量删除是否要修复，按 Σ max(0, dc_每格) 判断（不是净值）
  若局部修复的块数与 Σ max(0, dc) 不符 ⇒ 整图 Compact 兜底
```

## 5. 复杂度与理论边界

- **单次改动**：绕数 O(1)、并查集 O(α)、断裂修复 O(连通区域)（罕见）。
  实测单格 4.8 µs、平均扫 522 格（其中绝大多数操作根本不触发修复）。
- **批量**：一批一次修复 ⇒ 1000 格 1.8 µs/格。
- **最坏情况**：一次断裂可能扫整个连通区域（实测哑铃砍桥 31,125 格）。
  文献的"两端并行 DFS 取小者"可以改善到 O(较小块)；本实现未做这一步。
- **理论边界**（这决定了"能不能做到严格 O(1)"）：
  - **完全动态（插入+删除）的连通性有 Ω(log n) 下界**（cell-probe），且**硬实例是"不相交路径"**，
    因此**平面图同样成立**；平面嵌入图上的 O(log n) 上界与之匹配 ⇒ 即最优约为 Θ(log n)。
    **所以"完全动态 + O(1)"是被证明不可能的**，除非放宽模型（摊还、离线、只删）。
  - **只删**（平面图）：可以达到 **O(n) 总更新 + O(1) 查询** ⇒ 每次删除 O(1) 摊还。
  - **只插**：并查集 O(α)。
  - **离线**（变更序列已知）：时间分治 + 可回滚并查集，O(log) 摊还、查询 O(1)。
  本算法属于"用恒等式把动态性拆成一个便宜方向 + 一个由恒等式推导的方向"，
  于是**主路径（拿掉一格）落在"只删"这一类里**，其余靠局部修复兜住。

## 6. 验证

### 6.1 方法：不是抽样，是**每一步都与暴力全量对拍**

暴力基准是每次从头 BFS，四个判据：

1. **计数**：`c`、`h` 与暴力一致；
2. **恒等式**：`w % 4 == 0` 且 `w/4 == c − h`；
3. **分区**：同标记 ⇔ 同暴力分量（前景精确查；背景按 §3.4 收窄后的承诺查）；
4. **批量 ≡ 逐格**：同一批操作两条路径的终态完全一致。

另外还有内部对账：整图 Compact 重建后，孔洞数必须等于维护值（不符即抛）。

### 6.2 覆盖与结果

| 项 | 规模 | 结果 |
|---|---|---|
| 随机对拍 | 864 例（尺寸 3～34 正方，两种配对，每例最多 1500 步） | 全过（≈130 万次操作逐步验证） |
| 批量等价 | 200 例（地图最大约 50×50，批量 1～30 格，每例 60 步） | 全过 |
| 边界用例 | 14 个手写（空/满/单格/对角相碰/空心方框/破角补角/长条断开接回/细环断口/洞中有岛…） | 全过 |
| 最坏情况 | 哑铃砍桥/接回，50×50 与 250×250 | 全过，结果与暴力一致 |

边界用例里有一条专门验证 §2.3 的开关：**同样的"两格对角相碰"，4 邻域语义给 2 块，8 邻域语义给 1 块**——
两种配对都自洽，但答案不同。

### 6.3 实测数字

见 §0 摘要表。补充说明：
- 全量重算是把 62,500 格从头 BFS 一遍的代价（1.4～1.9 ms），**这就是"不增量"的基线**；
- 单格 4.8 µs 的关键是 §3.4 的跳过；关掉它立刻退化到 805 µs（**×168**），
  这说明"O(1) 检测"本身不够，**还必须避免无谓的结构重排**；
- 本机偏慢，绝对值应视为上界；不同配对（4/8 与 8/4）差 5 倍，
  原因是 8 邻域背景（配 4 邻域前景）下背景分量更碎，更容易触发重排。

## 7. 这个验证过程抓出的问题（证明验证是有效的）

实现这套算法的过程中被逐步对拍抓出的问题，都是"看起来对"的那一类：

| # | 现象 | 真因 |
|---|---|---|
| 1 | 特定图（方框补角）分区错 | **两套坐标系混用**：用"内部坐标"算邻居、却按"含 padding 的索引"取值 ⇒ 修复播种错位、覆盖不全 |
| 2 | 随机序列跑到上千步后**错合并** | 并查集不支持删节点；被拿走的格子继续当根，放回时把它的旧孩子并进别人的分量（⇒ §3.5） |
| 3 | 批量删除偶发**漏掉断裂** | 修复闸门看了**净值**，而"拿掉孤块(−1)"与"切断链条(+1)"会抵消（⇒ §3.3 的注） |
| 4 | 修复时泛洪结果错乱 | 泛洪**一边改父指针**，破坏了泛洪自己用的"是否同分量"判据 ⇒ 必须分两阶段（先标记、后换根） |
| 5 | 偶发异常、偶发正常 | 把 `List<int>` 当定长数组用（`list[k++] = v`）：Count 为 0 时抛异常，更坏的是上一步残留的 Count 让它**有时候不炸** |
| 6 | 无输出、进程挂住 | 并查集父指针**成环** ⇒ 死循环（比抛异常难查得多）⇒ 加环检测 |
| 7 | 报出"不可能"的错误 | **我自己的断言写错了**：曾断言"拿掉一格不可能减少块数"——被拿掉的格子本身就是孤块时 `c` 会减少 1（合法范围 `[−1, +3]`） |

第 7 条值得单独说：**判据本身出错时，报的是被测物的错**。
上面每一条都是靠"每步与暴力对拍"抓到的，而不是靠阅读代码。

## 8. 适用边界与未决

**适用**：
- 平面方格图（结论依赖平面图的 `χ = c − h`；一般图没有"孔洞"，判断裂要另找割点算法）。
- 变更局部、频率高（这正是增量算法的主场）；若变更很稀，`dirty + 全量 BFS`（1.9 ms）就够，不必上这套。
- 需要的是**"数量 + 分区"**：断没断（O(1)）、断成几块（O(1)）、每格属于哪块（查表 O(1)）。

**不适用 / 不给**：
- 不给**割点集合 / 最小割**（"是哪一格把它分成两半的"需要另一套结构）。
- 不给"具体是哪几块"以外的几何信息。
- 最坏情况仍是 O(连通区域) 而非 O(1)：这是**本质的**（见 §5 的下界），
  只能靠"断裂罕见 + 只扫较小侧"压常数。
- "一格有没有砖"的语义由调用方决定（专用地板地形 / 任意建筑格 / 可通行地板 / 房间…）。
  **这是唯一还没定的输入**，它直接决定"孔洞"有没有物理意义：
  若"砖"是墙，所有房间都是洞；若"砖"是地板，房间算前景。

**已知可继续优化的点**：
- 批量路径目前**每批仍做一次全背景泛洪**，所以小批摊不薄：9 格批量是 118 µs/格，
  而 1000 格批量只要 1.8 µs/格。把 §3.4 的跳过按格用到 `AddBatch` 即可消掉这个常数；
- 断裂修复可改为"两端并行 DFS、取较小侧"，把 O(连通区域) 降到 O(较小块)。

## 9. 参考文献

- **Pătraşcu & Demaine**, *Lower Bounds for Dynamic Connectivity*, STOC 2004 / SICOMP 35(4):932–963, 2006
  —— 完全动态连通性的 Ω(log n) 下界（硬实例为不相交路径，平面图同样成立）。
  <https://people.csail.mit.edu/mip/docs/enc-algs/connect.pdf>
- **Łącki & Sankowski**, *Optimal Decremental Connectivity in Planar Graphs*, STACS 2015, LIPIcs 30:608–621
  （期刊版 ToC 61(4):1037–1053, 2017；arXiv:1409.7240）
  —— 只删方向 O(n) 总更新 + O(1) 查询；核心判据"删边两侧是否同面"由**双图（对偶图）并查集**验证；
  断裂时从两端并行 DFS 取较小侧。
  <https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.STACS.2015.608> · <https://arxiv.org/abs/1409.7240>
- **Holm & Rotenberg**, *Good r-divisions Imply Optimal Amortized Decremental Biconnectivity*,
  STACS 2021, LIPIcs 187:42:1–42:18（期刊版 ToC 68:1014–1048, 2024；arXiv:1808.02568）
  —— 推广到 2-边连通/双连通与有界亏格、minor-free 图；技术核心是 **r-division**（每块 O(√r) 个边界顶点）。
  <http://arxiv.org/abs/1808.02568> · <https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.STACS.2021.42>
- **Eppstein, Italiano, Tamassia, Tarjan, Westbrook, Yung**, *Maintenance of a Minimum Spanning Forest
  in a Dynamic Plane Graph*, J. Algorithms 13(1):33–54, 1992 —— 平面嵌入图 O(log n)/操作（分离器 sparsification）。
- **Gray**, *Local Properties of Binary Images in Two Dimensions*, IEEE Trans. Computers C-20(5):551–561, 1971
  —— 欧拉数的局部（2×2）可算性；工程表述见 Pratt《Digital Image Processing》的 bit-quad。
- **Gustedt**, *Efficient union-find for planar graphs and other sparse graph classes*, TCS 203(1):123–141, 1998
  —— 平面图上的并查集可线性时间。
